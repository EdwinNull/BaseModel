## 0 结论先行

1. **现有 CDM `aligned_20260927` 在结构、编码、单位层面已经对齐**；v1.0 实验只用了其中 15 个变量的首值。
   "彻底对齐"还缺的主要不是表结构，而是四类**语义不对称**：结局标签来源、时间语义、"未知 ≠ 阴性"、队列构成。
2. **影响最大的是结局标签不对称。**
   - GAM 的 E1 组成（有创、ICU、死亡）全部来自病历文本规则，没有经过人工核查；
   - GD 的 E1 组成来自 CRF 人工填写；
   - 训练集只有 10 个事件，错 1 个就是 10%。
3. 本计划分两段：
   - 先做 CDM v2（新版本目录，v1 产物不动），并对 GAM 结局做人工裁定；
   - 再按预先锁定的 v2.0 方案，在 GAM 上训练、在 GD 上测试。
4. **GD 已经不是"未使用过"的外部集。** v1.0、A1 七项、A3、A5 都已在 GD 上评价过。因此：
   - v2.0 只能作为新登记的版本，与 v1.0 并列报告，不替代 v1.0；
   - 所有选择在运行前锁定，不依据任何 GD 上的模型结果。
5. **对齐解决不了的问题：**
   - GD 没有入院时间，事件只有日期，38 个事件中有 26 个落在索引当天；
   - GD 每个变量只有 1 个值，没有时间序列。

   这两点只能靠数据方补充数据（A6）解决。v2.0 继续用 GD_prospective（9 个事件）检验泄漏，结论强度不会因为对齐而本质提高。

### P2 CDM v2 实现

原则：
- 写入新版本目录 `derived/aligned_<日期>/`，v1 产物不动；
- 改动以新增列、新增表为主，v1 各列的取值不变（去重导致的行删除除外）。

| 项 | 改动 |
|---|---|
| 去重 | `events` 删除完全重复的行（住院 × 变量 × 时间 × 数值），新增 `dup_n` 记录原重复次数 |
| 时间语义 | `events`、`treatments` 新增 `time_kind`，取值为 measured / resulted / note_written / date_only / anchor_imputed。GAM 检验时间是采样时间还是报告时间，按原表字段核实后再标注 |
| 三态编码 | 症状、基础病、治疗新增 `assertion`（present / absent / not_mentioned）和 `value_tri`（未提及记缺失）；原 `value` 列保留 |
| 结局组成表 | 新表 `outcome_components`：住院 × 组成（IMV/NIV/ICU/ECMO/DEATH/RF）× 状态 × 最早时间 × `time_kind` × 来源（CRF/rule/ward/adjudicated）× 证据引用（化名文书 ID + 位置，不含正文） |
| 锚点 | `encounters` 新增 `anchor_kind`、`earliest_record_time`、`anchor_late_flag` |
| 窗口 | 保留旧列 `in_window`，新增 `in_clean_window` 并在字典中写明：这是清洗窗，不得用于特征构造 |
| 其他 | 生成 v2 QC JSON；写盘后做隐私审计；同一输入连续跑两次，产物 sha256 一致 |

新增单元测试（全部用虚构数据）：去重、`time_kind`、三态编码、结局组成表、锚点标记。

**验收**：
