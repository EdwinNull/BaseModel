## 1. 相对 B1 修复了什么

| B1 的问题（week02 规划 §1.3） | B1v2 的处理 |
|---|---|
| 有创通气只用 `procedureevents` 的单个 itemid 225792 | 改用 mimic-code `ventilation` 派生表：状态为 InvasiveVent 或 Tracheostomy 的疗程开始时间 |
| 升压药 itemid 是手工列出的 | 改用 mimic-code 的 norepinephrine、epinephrine、phenylephrine、vasopressin、dopamine 五张表；按 09-25 方案不含多巴酚丁胺、米力农 |
| 没有排除 DNI 与仅舒适治疗 | 用 mimic-code `code_status`（chartevents 223758 + POE Code status）判断 t0 时的状态；主分析排除，敏感性分析纳入（只打标记，不删行） |
| 部分 landmark 无法证明 t0 时仍在 ICU（旧数据门控测试 `test_b1_existing_dataset_invariants` 报 24 例） | 风险集要求 t0 < ICU 出科时间，且 t0 < 死亡时间；检查结果为 0 |
| 只有 ICD 入组 | 增加住院期间呼吸道病毒检测阳性入组（§4 第 1 条，待复核） |
| 没有入 ICU 时已气管切开的排除 | 已增加（§4 第 2 条，待复核） |
| 没有盲区与"可部署"流感标记 | 增加 `blind1h`、`flu_known_at_t0` |
| 事件只看同一次 ICU 入住 | 按住院汇总：同一住院内后续 ICU 入住发生的事件也计入窗口 |

mimic-code 的 SQL 原样取自 commit `303d26c`（`vendor/mimic_code_303d26c/`，MIT 许可，`SOURCE.txt` 记录了各文件的 sha256），代码中没有改写其逻辑。

## 4. 需研究者复核的操作化（A 档相关，已按方案原文实现，未自行改口径）

1. **呼吸道病毒检测条目与阳性规则**。09-25 方案要求"检测条目名在审计时人工核对后冻结"。本次按聚合词表检索冻结了一版候选，影响 38 次仅凭检测入组的住院（主分析中 182 个 landmark），以及流感子组。
   - **labevents，流感 A/B PCR 与快速抗原**：itemid 51864、51865、51872、51873、51869、51870、51874、51875。阳性判定：value 以 POS 开头，或 value 为空且 flag = abnormal。
   - **labevents，RSV 快速检测**：itemid 53113，阳性判定同上。
   - **microbiologyevents**：下列检测 org_name 非空即判为检出：DIRECT INFLUENZA A/B ANTIGEN TEST、Respiratory Viral Culture、Respiratory Virus Identification。Respiratory Viral Antigen Screen 没有 org_name，以 comments 以 "POSITIVE FOR RESPIRATORY VIRAL ANTIGENS" 开头为阳性。
   - **未纳入**：FLUA1/FLUA2/FLUB1/FLUB2/RSV1/RSV2（53107–53110、53114、53115），这些条目只有数值，无法判定阴阳性。
   - **备选**：若研究者不认可以上规则，可用 `in_main_icd_only` 列直接得到"仅 ICD"版本，不需要重建。
2. **"入 ICU 时已气管切开"**：判定为 ventilation 表中 Tracheostomy 状态在入科后 6h 内开始，即首个 landmark 之前，共 96 例。入科后更晚出现的 Tracheostomy 计为终点事件（按 week02 规划 V1 的定义）。
3. **DNI/CMO**：用 t0 时最近一条有效 code status 记录判断；同一时刻有多条记录时，只要有一条为 DNI/CMO 就算。另提供 `dni_cmo_ever` 列（t0 前出现过即算），供敏感性分析使用。
4. **切分**（AD2 与 09-25 方案 §2.5 的冲突）：
   - AD2 要求沿用 B1 的患者级随机切分。B1 的切分没有按事件、年龄、流感分层，与 §2.5 不一致。
   - B1 中没有的 635 名患者，用 sha256 哈希确定性分配 70/10/20。
   - 主分析的患者数：训练 3,877、验证 549、测试 1,105。
   - 时间外推集：2020–2022 年组有 580 名患者、3,785 个 landmark。按 AD2，它与 eICU 一起作为首次评价集。这些患者目前也分布在 B1 的训练/验证/测试中，正式使用前需决定做时间外推分析时是否把他们从训练集中剔除。
5. **§2.8 继续/调整规则**：测试集中 ≥65 岁且发生 Y24 的患者有 164 人，不少于 100 人，因此 ≥65 岁仍是主评估人群（AD11）。这一点只计数，没有看任何模型在测试集上的表现。

## 5. 泄漏检查

| 编号 | 检查 | 结果 |
|---|---|---|
| L1 | 输入最大时间戳 ≤ t0 | 特征表中每个小时格的最后观测都落在本格内（bad_bin = 0）；`views._window` 对每个样本断言窗口内最后观测时刻 ≤ t0：全部 37,252 个样本通过 |
| L2 | 化验按结果可用时间（storetime）进入 | 是。7,490,696 条化验中 storetime 缺失 5 条（不使用），storetime 早于 charttime 61 条 |
| L3 | 当次住院 ICD、出院信息不进入输入 | landmark 表已删去入院、出院时间等字段；表格视图列名黑名单扫描：222 列中 0 列命中 |
| L4 | t0 前已有有创通气或升压药的样本不在风险集 | 0 |
| L5 | 同一患者不跨切分 | 0 |
| 补充 | t0 ≥ 出科时间 / t0 ≥ 死亡时间 / Y24 ⊆ Y48 ⊆ Y72 / 组分与总标签一致 / 阳性事件在 t0 之后 | 全部为 0 |
| L6、L7、L8 | 老师模型、证据参考集、LLM 提示 | 相应步骤生成时检查 |

泄漏嗅探：训练集拟合，只在验证集上看结果，测试集不读标签。LR 的验证集 AUROC 为 0.718，LightGBM 为 0.754（≥65 岁为 0.764），都远低于泄漏警戒线 0.95。按增益排序，LightGBM 的前几位特征是：距最近一次血气 pH 的小时数、距最近一次 FiO2 的小时数、呼吸均值、年龄、氧流量。这些都是 t0 前就能获得的观测过程与生理信息，没有出现可疑的未来信息。这不是正式结果，正式基线在 F2/F5 中报告。

## 6. 特征（V1 原始层）

- 网格：小时 h 覆盖 (入科 + (h−1)h, 入科 + h·h]，h 从 −23 到 72。负的小时只含入科前的化验。
- 共 26 个通道，覆盖 12,855 次入住：
  - 体征 7 个（vitalsign）；
  - GCS；
  - FiO2（ventilator_setting）；
  - 氧流量；
  - 呼吸支持等级（取 ventilation.sql 的逐条分类，不含用后续记录推断疗程的部分）；
  - 化验 15 个。
- 前向填充上限：体征类 4h、化验 24h（09-25 方案 §2.6）。
