## 1 先读：本机处理真实数据的规矩（D34、D35）

1. **本机可以放原始数据（D35，取代 D34 的"只拷化名后的 CDM"）。**两家医院的原始 Excel、化名对照表 `registry.csv`、对齐好的 CDM 都可以放在本机，由 flucase 处理。原始 Excel 里有姓名、病案号、病历全文，本机数据因此可以直接对应到真人，下面几条都要守住。
2. **放在 BaseModel 的 `data/` 里**（§3.1）：BaseModel 的 `.gitignore` 已排除 `data/`；目录只给本人账户（`chmod 700`）；整盘加密（macOS FileVault、Windows BitLocker）；BaseModel 不放在 OneDrive、iCloud、Dropbox、坚果云等同步目录里（10-13 查过：本机桌面没有开 iCloud 同步）。
3. **不进任何仓库**：真实数据和从真实数据导出的逐例文件只放 `data/` 下；不放进 `flucase/`（它是另一个仓库，`.gitignore` 不排除这些文件），也不放进 BaseModel 的其他目录。提交前看一眼 `git status`，不应出现 `data/` 下的文件。
4. **化名对照表只有一份口径（D35）**：从服务器拷 `registry.csv`，flucase 对齐时沿用其中的化名，只为新患者追加，化名因此与服务器的 CDM 和实验一致。新数据只在一处对齐（本机或服务器），追加后把 `registry.csv` 同步到另一处；两处不能各自追加，否则同一个号会指向不同的人。
5. **不传任何在线服务**：不上传网盘，不发邮件，不粘贴进任何在线大模型（包括 Claude）。
6. **Claude 不读真实病例内容**：本机用 Claude Code 时，先按 §3.4 设好读取限制。涉及真实数据的命令由你自己执行；需要 Claude 帮忙时，只告诉它计数、列名、报错类型，报错信息里的病例取值先删掉（§7）。
7. **文档只放聚合量**：报告里 1–9 写作 <10，不写任何病例编号以外的逐例信息。

服务器上 `data/real_world/README.md` 和 `aligned_cdm/README.md` 原来写着"不得复制到 W 之外"，10-13 先补了 D34 例外，同日又按 D35 改为：原始文件、化名对照表和 CDM 都可以拷到研究者本人设备处理，条件见本节（备份与日志：D34 在 `W/logs/2026-10-13/`，D35 在 `W/logs/2026-10-14/`，按服务器日期）。

开发内容与验收（每项都要有测试）：

**1. 虚构 CDM 样例**（`flucase/synth/cdm_v31.py`）

- 按两份字典生成 9 张表的 Parquet，列名、类型和真实 CDM 一致，取值全部虚构；另生成 `run_meta.json` 和 `SHA256SUMS`，格式同真实目录。

- 化名用一看就是虚构的格式，例如 `DEMO-GDE0001`、`DEMO-GAME0001`、`DEMO-GAMV0001`。
- 文书（`notes`）用现有虚构文书生成器的写法，不复制任何真实文本。

**2. CDM 适配器**（`pipeline/adapters/cdm_v31.py`）

- 输入是一个 CDM 目录（9 张 Parquet + 字典 + `run_meta.json`）；识别靠文件组合与 `run_meta.json` 的版本号。
- 校验：每张表的必有列都在；按来源报计数（就诊、各类记录）；时间、精度字段能解析；只出计数，不出逐行内容。
- 一个 CDM 目录建三个批次与三条运行（GD_CRF、GAM_IP、GAM_OP 各一），沿用"每个来源一条当前运行"的现有逻辑。
- **不再化名**：就诊编号、患者编号直接用 CDM 里的；flucase 自带的化名（会编成 `DEMO-` 开头）对 CDM 输入关闭。
- 映射：
  - `encounters` → 就诊：预测时点取 `anchor_time`（取法 `anchor_rule`、精度 `anchor_precision`），年龄、性别、BMI、死亡及时间、离院时间、基础病 `COM001–COM010`、疫苗 `vaccine_code`、流感检测（`flu_test_pos` 等）→ 相应抽取记录。
  - `events` → 体征、检验、症状记录（数值、`unit_cdm`、时间、`time_precision`、`time_kind`；`implausible`、`censor` 记为标记）。
  - `treatments` → 治疗记录（状态、起止、时间来源）；`complications` → 并发症记录；`imaging` 的报告结论能用的就用。
  - `notes` → 文书，交给规则抽取（S5）。若 `notes` 没有书写时间，文书抽取的时间记"未知"，并在校验结果里报出来（计划 §6）。
  - `outcome_components`、`crf_view` 不参与分级，只用于核对。
- GAM_OP 按门急诊来源处理（场景 `ed`）；`linked_ip_encounter_id` 与关联住院的时间 → "随访：住院"记录，供 O3 使用（D32：只是候选结局）。

## 7 出问题怎么办

- **请 Claude 帮忙时只给聚合信息**：报错的类型和行号、出错的表名和列名、计数；把报错信息里的病例取值（姓名、编号、日期、数值、文书片段）删掉或换成"<值>"再贴。
- **常见问题**：

| 现象 | 先查 |
|---|---|
| 正式模式登录后又跳回登录页 | 是否设了 `FLUCASE_COOKIE_SECURE=0`；是否用 `http://localhost` 访问 |
| 启动时报端口被占用 | 换端口，例如 `--port 8001` |
| 识别与校验报"缺少列" | 对照 §3.5 的列字典看缺的是哪一列；可能是 CDM 版本不同，看 `run_meta.json` 的 `version` |
| 计数与 `run_meta.json` 对不上 | 看校验结果里每类记录被跳过的条数和原因 |
| 导出被隐私正则拦下 | 看命中的是哪一类规则、哪张表哪一列，只把这三样告诉 Claude |
| 对齐报"需要 pandas 2.x" | 按 §2 重新安装：`.venv/bin/python -m pip install -e ".[dev]" -c constraints.txt` |
| 对齐报"三类各正好一个文件" | 把三个原始 Excel 单独放一个目录，或命令行用 `--gd`、`--gam-ip`、`--gam-op` 分别指定 |
| 对齐报"表头与预期不符""缺少列" | 原始导出的版式变了：把这句报错原样告诉 Claude（只含表头文字，不含病例取值） |
| 对齐报"对齐失败：XxxError @ 文件:行号" | 只把这一行告诉 Claude；报错内容可能含病例取值，系统已经不显示 |
| 对齐报"隐私审计不通过" | 产物已整个删除、化名对照表没动；把各规则的命中计数告诉 Claude |
