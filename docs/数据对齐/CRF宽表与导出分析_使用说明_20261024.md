# CRF 式宽表与导出分析：使用说明（2026-10-24）

把 flucase "数据导出"页导出的标准格式（std_v3，也认 std_v2；第一次是 GD 原始导出 + GAM 住院 / 门诊的两院对齐）转成**一个 Excel 文件、多个 sheet 的 CRF 式宽表**（每次就诊一行），同时生成一份**只含聚合量的分析报告**。以后同格式的导出（新快照、新中心、新编码、新口径、新增的列）直接放进来跑，不用改脚本（见第 4 节）。

脚本：`scripts/crf_wide/build_crf_workbook.py`；测试：`scripts/crf_wide/test_build_crf_workbook.py`（只用虚构数据）。

## 1 为什么是研究者在本机跑

项目规则（CLAUDE.md、D41）：Claude 不读 `data/` 下的真实病例，医院数据不发给任何在线 LLM / API。所以分工是：

1. Claude 按 flucase std_v3 的表结构（`flucase/backend/flucase/export/std_v3.py`）写脚本，只用虚构数据测试；
2. 研究者在本机对真实导出运行；
3. 研究者只把**分析报告**（或其中几节）回报给 Claude。报告里计数 1–9 写作 "<10"，不含就诊编号、具体日期和病历文字，写出前脚本会自检。

## 2 运行

导出放在 `data/export/`：zip 或解开后的目录都可以，子目录里的也会找到；同一份导出既有 zip 又有解开的目录，只算一次。系统 Python 没有 pyarrow，用 flucase 的 venv（在仓库根目录）：

```bash
flucase/backend/.venv/Scripts/python.exe scripts/crf_wide/build_crf_workbook.py --input data/export
```

只处理某一份新导出：

```bash
flucase/backend/.venv/Scripts/python.exe scripts/crf_wide/build_crf_workbook.py --input data/export/std_v3_20261101.zip
```

输出在 `data/crf_wide/`（`data/` 已 gitignore），文件名带导出版本，新导出不会覆盖旧的：

| 文件 | 内容 | 能不能外传 |
|---|---|---|
| `CRF宽表_<导出版本>.xlsx` | 逐就诊的 CRF 宽表 + 分析表（照实计数）+ 字段字典 | 不能：含病例ID与真实日期，只留本机 |
| `分析报告_<导出版本>.md` | 同一套分析，只含聚合量（小格抑制） | 可以回报给 Claude |
| `生成记录_<导出版本>.json` | 用了哪几份导出（版本、快照、encounters 的 sha256）、选项、脚本 sha256、行数、报告自检结果 | 只有计数和编号的哈希，可以回报 |

**一个目录里有几份导出时**（`--mode`）：

| 取值 | 做法 | 什么时候用 |
|---|---|---|
| `auto`（默认） | 几份导出的就诊互不重叠（如 GD、GAM 分开导出）就合成一份宽表；有重叠（同一批病例的新旧版本）就每份各出一份，不混用版本 | 一般情况 |
| `merge` | 全部合成一份，同一就诊出现在几份里时用较新的那份（按 manifest 的生成时间），A1 记重复了多少 | 确定要拼起来时 |
| `each` | 每份各出一份 | 想分别看每一版 |
| `latest` | 只用最新的一份 | 目录里攒了旧版本、只要最新的 |

其他参数：

| 参数 | 作用 |
|---|---|
| `--sites GD,GAM` | 只要这些中心（文件名后面加中心代码） |
| `--window LO HI` | 基线窗，相对 t0 的小时，默认 `-24 24`（D18）；改了"说明"里会写明不是默认 |
| `--age-main 60` / `--age-sub 65` | 主分析人群与亚组的年龄下限，默认按 D70 |
| `--keep-implausible` | 越界值也进基线与极值 |
| `--include-unmapped` | 未映射检验（`LABX:<原名称>`）有数值的也按项目列进 06_检验 |
| `--skip-existing` | 同名宽表已经存在就跳过（目录里攒了很多份导出时用） |
| `--no-names` | 报告里不列未映射项目名称、诊断编码和带医院原名的编码 |
| `--no-suppress` | 报告也照实计数（这时报告不能外传，也不做自检） |
| `--out-dir` | 改输出目录 |

报告自检没通过时（发现就诊编号、患者编号或具体日期），脚本不写报告，退出码 2，屏幕上只打印"含……几处"。把这一行回报即可。

## 3 宽表的 sheet

每个 CRF sheet 一行一次就诊，前四列都是 `site`（中心）、`setting`（场景）、`patient_id`、`encounter_id`，各 sheet 用 `encounter_id` 连接。第 1 行是中文名，第 2 行是字段名，用 pandas 读：`pd.read_excel(文件, sheet_name="05_生命体征", header=1)`。

| sheet | 内容 |
|---|---|
| 说明 | 输入的导出与组合方式、口径、读法、数据纪律、自动生成的要点 |
| 01_就诊与人口学 | 年龄、性别、BMI、身高体重、t0 与取法、流感季、索引状态（D73）、主分析人群标记 `pop_main`（确诊且 ≥60 岁，D16、D70）、亚组 `pop_sub`（≥65 岁）、起病日期与起病到 t0 天数、院内发病、发热三态、疫苗、高危类别、中医证候；**encounters 里本脚本没有专门处理的列原样带在末尾**，中文名取自导出的 data_dictionary.csv |
| 02_流感检测 | 病原学确诊、阳性 / 阴性检测条数、首次阳性时间与相对 t0 小时、检测方法（核酸 / 抗原，按名称文字归类）、型别、诊断中有流感 |
| 03_基础病 | encounters 里所有 COM 列的三态（有 / 无 / 未记录），只在 events 里出现的 COM 编码也列出；高危类别数 |
| 04_症状 | 所有 SYM 编码的三态、首次"有"相对 t0 小时 |
| 05_生命体征 | 所有 VS 编码：基线值（基线窗内最早的一个）与时间、基线窗最低 / 最高、全程最低 / 最高、条数、有记录的天数；SpO2 另有基线值的吸氧状态、吸空气最低；未映射体征（如意识）的首次记录 |
| 06_检验 | 所有 LAB、EXT_ 编码：基线值与时间、全程最低 / 最高、条数；未映射检验条数（`--include-unmapped` 时按项目列出） |
| 07_影像 | 所有 IMG 编码：三态、首次时间、条数 |
| 08_治疗 | 所有 TRT 编码：有没有、非确定语境（假设 / 计划 / 拒绝 / 围术期）、首次开始与相对 t0 小时、最晚结束、条数、医嘱或药品名称 |
| 09_并发症与诊断 | 所有 CLP 编码：三态、首次时间、标记（只认到编码 / 只认到名称）；原始诊断（编码 名称）与个数 |
| 10_结局与去向 | 离院时间与去向、住院天数（离院 − t0）、院内死亡与时间、ICU 与首次进入时间、围术期 ICU、随访完整性、门急诊当次收住院、之后住院（随访）、原表结局字段 OUT*（只作对照，D24） |
| 11_分级时间线 | 有效层：最高级别（有时间的证据 / 含时间未知的证据）；首次达到中型 / 重型 / 危重型及以上的时间、相对 t0 小时、首个判据与依据；各判据类首次重型及以上；命中过的判据；时间未知的阳性证据；只进敏感性口径的判据 |
| 12_候选结局 | 有效层：数据里有的全部结局 × 口径（现在是 D0 / O1 / O2 / O3 / O3_7d × primary、physiologic、guideline、primary_img、all、treatment、diagnosis）；主口径的事件时间与理由；自动层与有效层不同的个数 |
| 13_记录质量 | 记录条数、来源方法、时间精度、时间未知、越界值、自动修正、删失值、吸氧状态推断、复核、最早 / 最晚记录相对 t0、t0 前 30 天以前的记录、有体征 / 检验记录的天数 |
| 14_其他数据项 | **导出里有、上面没有专门处理的编码**（现在是起病时长、发热起始；以后新加的数据项会自动出现在这里）：三态、第一个数值、文字、首次时间、条数 |
| A1–A10 | 分析表（照实计数），与报告同一套，见第 6 节 |
| 字段字典 | 每个 sheet 每一列的中文名与说明；附导出自带的 data_dictionary.csv |

## 4 以后的导出：哪些自动适配，哪些要改脚本

自动适配（不用改脚本）：

- **新编码**：编码前缀已知的（VS、LAB、EXT_、SYM、COM、TRT、CLP、IMG、OUT）直接进对应的 sheet；前缀不认识的进 14_其他数据项。中文名先用脚本的编码表，其次用导出自带的 codes.csv，再次用 events 里最常见的 label；单位同理（编码表 → events 里最常见的 unit）。A1 和"要点"会列出进了 14_其他数据项的编码。
- **新中心、新场景**：分组按"中心 × 场景"从数据里取；中心间差异（A5）对同一场景里的中心两两比较，例如以后有了 GD 门急诊，就会多一张 A5（门急诊）。
- **新结局、新口径、新的判据类、新标记、新的复核条目类型**：都从数据里取。候选结局是否缺行，按"同一场景别的就诊有、它没有"来判断，不写死哪个场景该有哪些结局。
- **encounters 新增的列**：原样带进 01_就诊与人口学。
- **少了列**：照样跑，A1 列出缺了哪些列。
- **几份导出**：按 `--mode` 处理（第 2 节）。

要改脚本的：已有列的含义或取值变了（例如 `state` 不再用 pos / neg、`t_rel_h` 改了零点）；分级级别不再是中型 / 重型 / 危重型（A1 会列出"不认识的级别"）；不是 flucase 标准格式的 parquet（至少要有 encounters 的 `encounter_id`、`setting`，events 的 `encounter_id`、`var`、`state`、`value`、`t_rel_h`）。

## 5 口径（都写在"说明"sheet）

- **基线窗** = t0 前后 24 小时（D18），基线值 = 窗内时间最早的一个有效值；只有日期的记录按当天 00:00 算（与 std_v3 的 `t_rel_h` 一致）。
- **"全程"最低 / 最高含 t0 之后的信息**，只作描述，不能直接当预测特征。
- 分级、候选结局取**有效层**（effective）；**候选结局不是标签**，用哪一列由研究者定（A 档）。
- 主分析人群、亚组只是标记，**不筛**；同一患者多次就诊看 `season_index`（D73），也不筛。
- 标了 `implausible`（越界）的数值不进基线与极值，条数记在 13_记录质量（B 档的数据清洗选择，`--keep-implausible` 可改回）。
- `unrecorded` / 空 = 没有记录，**不等于"无"**；治疗只有"有"的记录，没有"无"。

## 6 分析报告的内容

| 节 | 内容 |
|---|---|
| 要点 | 各组就诊数、主分析人群、中心间差异最大的基线字段（\|SMD\|）、覆盖率组间相差 ≥50 个百分点的数据项、非零的待核问题、单位不一致、进了 14_其他数据项的编码 |
| A1 | 导出与结构检查：格式与版本、快照、规则集、各中心读取格式、manifest 行数核对、重复就诊、孤立记录、缺少的列、候选结局缺行、没有候选结局的场景、不认识的分级级别、复核改动、14_其他数据项里的编码 |
| A2 | 人群与基本特征（按中心 × 场景）：年龄、性别、BMI、起病到 t0、发热、确诊、主分析人群与索引就诊、去向、随访、ICU、流感季、高危类别 |
| A3 / A4 | 体征与检验的覆盖（有记录、基线窗有值、条数 / 就诊、实际单位、越界、分钟精度）与数值分布（中位 [P25, P75]） |
| A5 | 中心间差异（每个有两个及以上中心的场景一张）：基线值有值比例、均值 ± SD、两两 SMD |
| A6 / A6b | 症状、基础病、并发症、影像、治疗、其他数据项的有记录比例；治疗首次开始时间相对 t0 的分布、记了结束时间的比例 |
| A7 / A7b / A7c | 最高级别分布、首次重型 / 危重型的时间分布、各判据命中的就诊数（判据类、依据）、候选结局各口径的取值分布 |
| A8 / A8b–A8f | 记录层：状态、方法、精度、时间未知、相对 t0 的时间分布、标记、SpO2 吸氧状态、未进统一编码的项目名称、原始诊断编码（只列名称与次数，D56） |
| A9 | 待核问题的就诊数（t0 / 年龄 / 性别缺失、起病晚于 t0、离院早于 t0、死亡或 ICU 没有时间、住院没有检验、越界值、t0 前 30 天以前的记录、时间未知的证据、确诊未记录、门急诊随访未知、主分析人群里的非索引就诊）、单位与统一单位不同的数据项、编码表里没有且单位不止一种的数据项 |
| A10 / A10b / A10c | 问题单计数（给 `docs/汇报/临床负责人问题单_20261024.md`，题号跟问题单走，按中心 × 场景）：入院前后不发热、COPD 与吸空气低氧、诊断与检测不一致、弱阳性、14 天内再就诊、中医证候写法、新开始吸氧及给氧前后 24 小时内是否同时有低氧（吸空气 SpO2 ≤93%、PaO2/FiO2 ≤300、呼吸 ≥30，分开列）、ICU 与其他器官衰竭、术后转入、无创 / 有创 / 高流量、确诊且 ≥60 / ≥65 岁、SpO2 按医嘱推断为吸空气的记录比例；ICU 科室名称导出里没有，表里注明。A10b 是流感检测名称、A10c 是中医证候写法（问题单附件 1、3；`--no-names` 不列） |

小格抑制只按单元格做（1–9 写 "<10"），不防"总数减已知格"这类差分推算；报告只回报给 Claude、不对外发布时这样够用。

## 7 测试情况（只用虚构数据）

入库的测试（`scripts/crf_wide/test_build_crf_workbook.py`，现场生成 std_v3 形状的虚构导出，8 项，约 25 秒）：

```bash
flucase/backend/.venv/Scripts/python.exe -m pytest scripts/crf_wide -q -p no:cacheprovider
```

- 基线值取窗内最早、窗外的不算；越界值不进极值；吸空气 SpO2；治疗开始时间；首次重型时间；候选结局；主分析人群标记；
- 导出里没见过的编码进 14_其他数据项，中文名取自 codes.csv；encounters 新增的列带进 01，中文名取自 data_dictionary.csv；
- 选项：`--keep-implausible`、`--include-unmapped`、`--age-main`、`--window`、`--sites`；
- 报告只含聚合量、自检能拦下就诊编号 / 患者编号 / 日期，`--no-names` 不列医院原名；
- 同一批病例的新旧两版：auto 各出一份、latest 只出新的、merge 合并时用新版的值；互不重叠的两份自动合并；
- zip 与解开的目录只算一次；`--skip-existing`；std_v2 形状的输入；
- A10 问题单计数：新开始吸氧、给氧前后 24 小时内同时有低氧（3 次给氧里 2 次给氧后 2 小时呼吸 ≥30）、弱阳性与只靠弱阳性确诊、COPD、中医证候写法与已对应、主分析人群，以及没有 ICU 时"其中"行写"—"、科室名称注明算不了。

另外用 flucase 自带的虚构数据生成器（`synth.gd_raw`、`synth.raw_export`）走一遍 flucase 导入 → 自动分级 → 冻结 → std_v3 导出（生成脚本不入库）：

- 67 次就诊、23,433 条 events：抽 25 次就诊手算核对体温、呼吸、CRP、氧合指数的基线值、全程最高与条数，奥司他韦首次开始时间，首次重型及以上时间，0 处不一致；
- 10-24 改成通用版后，与改之前的宽表逐格对照：13 张 CRF sheet 除了 `pop_65` 改名 `pop_sub`，其余完全一致（67 次就诊和 645 次就诊两份都比过）；
- A10 第 8 题在 645 次就诊那份上另写代码直接从 parquet 算：新开始吸氧 618、24 小时内 618、同时有低氧 0、没有 618，与 A10 一致（这份虚构数据给氧都在入院后 1–2 小时，低氧记录最早在给氧后 28 小时，所以是 0）。

## 8 规模与耗时

按真实 GD 的规模生成虚构导出（GD 618 次住院 + GAM 住院 10、门诊 17，共 645 次就诊、382,410 条 events），在本机（Windows，flucase venv：Python 3.12、pandas 3.0.6、pyarrow 26）上：约 20 秒，峰值内存约 1 GB，宽表 xlsx 约 1.2 MB。真实导出的记录数如果是它的两倍多，耗时和内存大致按比例增加（估计 1 分钟、2 GB 左右，没有在真实数据上量过）。几份导出各出一份宽表时按份依次处理，内存不叠加；`--mode merge` 时是合起来的总量。

## 9 回报给 Claude 什么

- 优先：整份 `分析报告_<版本>.md`（自检通过才会写出）。
- 只想先看结论：报告的"要点"、A1、A9 三节。
- 填问题单：抄报告的 A10（附件 1、3 是 A10b、A10c），见问题单末尾的对照表。
- 脚本报错：把屏幕上的错误信息回报（错误信息只有表名、列名和计数）。
- 不要贴 xlsx 里的任何内容。
