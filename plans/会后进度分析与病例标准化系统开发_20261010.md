## 2 flucase 本轮开发：做了什么

### 2.1 从原型到可运行系统

| 模块 | 之前（10/09 骨架 + 静态原型） | 现在 |
|---|---|---|
| 数据源 | 只有 CRF 宽表的识别与表头校验；虚构数据只有 CRF | 三个适配器（CRF 宽表、EHR 导出 + 病历文本、门急诊导出模板）都实现了识别、校验、映射预览、构建；三个虚构数据生成器，埋入设计文档 §11.1 的全部问题 |
| 流水线 | 33 个接口返回 501 | S1–S11 真实运行：导入哈希 → 续行分组 → 化名与清洗（隐私审计必须 0 命中，否则停止）→ 映射（删失值、越界值、单位待确认）→ 规则抽取 + 本地 LLM 第二抽取（演示为预置结果）→ 时间精度与年份修正 → 分级 → R1–R7 标记 → 复核回流 → 质控 → 冻结 |
| 分级 | 只能读 YAML | 规则集解释器：判据（事件阈值、吸氧状态要求、治疗区间、组件、并发症、组合判据）、基线窗口、日精度事件、病程类型、候选结局 O1/O2/O3/D0、分级色带 |
| 复核 | 静态原型，状态存浏览器 | 后端分派（A 类两人、B 类一人 + 15% 抽样第二人）、盲法视图（后端只发问题、背景、证据片段）、判定与共识写入复核层、有效层分级实时重算；按抽取记录编号回流，换规则集重算时复核结果直接沿用 |
| 规则集 | v0 只读 | v0 与 v0.1 两个版本；后端校验区分"错误"和"提醒"；版本对比（在当前有效层上各算一遍）；"用此版本重算"只从 S7 开始 |
| 前瞻录入 | 前端校验，存浏览器 | 表单 v0.2；后端按同一份定义重新校验（绕过前端也提交不了）；提交后生成第 7/14/28 天随访；由定义生成带下拉选项的 .xlsx 模板 |
| 质控 | 虚构数字 | 后端在有效层上计算覆盖率、时间精度、冲突、一致性（κ 只在配对 ≥10 时报告）、可行性计数、候选结局计数；全部在后端做小格抑制 |
| 测试 | 14 个 | 35 个（抽取陷阱、分级判据、复核回流、规则集重算、前瞻录入后端校验、小格抑制、快照） |

### 2.2 规则集 v0.1 相对 v0 的修改（候选，供讨论）

1. 中型停用"发热>3天"（不删）：早期预测"轻→中"时属循环定义（会后计划 §2.2 第 2 条）。
2. 中型三条判据补 kind，report_split 才能分类（v0 的这个缺口现在由校验器报出）。
3. 肺炎判据同时认 CRF 合并症表的"病毒性肺炎"（GD 没有影像结论）。
4. 新参数 `chronic_hypoxemia_policy`：COPD 者不用"吸空气 SpO2≤93"判重型（A 档）。
5. 两院都无法评估的判据（24–48 小时影像进展>50%、急性坏死性脑病）显式列为 not_evaluable。

### 2.3 前瞻录入表单 v0.2 相对 v0.1 的修改（候选，需临床确认）

1. 新增"本次是否发热"三态字段：v0.1 首次发热时间留空时分不清"不发热"和"没评估"。
2. 测量模块新增体温部位（D-H3）。
3. 新增退热药与开始时间；随访新增最后一次退热药日期（退热时间作为次要结局时必须有）。
4. 新增关键检验：白细胞、淋巴细胞、CRP、血糖。
5. 新增中医证候（自由文本，选项待临床给定）。
6. 随访新增实际随访日期（区分"确定阴性"和"随访不足"）。

## 3 演示结果（虚构数据，只说明系统按设计工作）

规模：CRF 80 次住院、EHR 40 次住院（230 份文书）、门急诊 120 次就诊；共 7,419 条抽取记录；隐私审计 0 命中。

### 3.1 复核候选（S8，v0.1）

| 来源 | A 类 | B 类 | 主要类型 |
|---|---|---|---|
| CRF | 9 | 31 | R5（SpO2≤93 但吸氧状态未知）28 条：CRF 没有吸氧列 |
| EHR | 50 | 22 | R3 语境 22、R1 时间 16、R2 规则与 LLM 不一致 12 |
| 门急诊 | 0 | 2 | — |

演示批次按类型限量后共 42 条；预置了一条两人日期不一致的 A 类条目（演示共识）和一条两人一致的条目（自动回流）。

### 3.2 候选结局（v0.1，计数 1–9 显示 <10）

| 候选结局 | CRF | EHR | 门急诊 |
|---|---|---|---|
| D0 住院期间重型及以上 | 40 / 80 | 25 / 40 | — |
| O1 住院中→重（干净事件） | <10（不干净 18，起点已达到 13） | <10（起点已达到 20） | — |
| O2 进展到危重或死亡（干净事件） | <10 | 0（不干净 <10） | — |
| O3 门急诊 14 天内住院或达到重型 | — | — | 13；未知 12；排除 30（当次收住院或起点已重） |

和真实计数同一个方向：住院数据撑不起"进展"研究，只能描述 D0；门急诊才有像样的进展事件，但"随访未知"必须单列。

### 3.3 规则集 v0 → v0.1 的影响（版本对比页）

- 门急诊：基线"中型"从 28 例降到 0。v0 下门急诊的中型几乎全由"发热>3天"判出——正是会后计划指出的循环定义。
- CRF：认合并症表的"病毒性肺炎"后，基线中型从 <10 升到 16。
- EHR：13 次住院有 COPD，按 v0.1 不再用"吸空气 SpO2≤93"判重型；这些人的重型改由治疗、诊断类判据决定。

### 3.4 抽取评测（会后计划 §5.5 的口径；标准答案是生成器真值）

| 字段 | 召回率 | 准确率 | 时间误差中位 |
|---|---|---|---|
| 起病日期 | 100% | 100% | 0 |
| 发热起始日期 | 91% | 100% | 0 |
| 氧疗开始 | 100% | 88%（3 例把入院时 SpO2 括号里的"鼻导管吸氧"当成开始氧疗） | 0 |
| 有创通气开始 | 100% | 100% | 0.9 小时（病历书写时间晚于实际插管） |
| 进入 ICU | 100% | 100% | 0.6 小时 |
| 抢救时 SpO2 低值（"降至"写法） | 自动层 0% → 两位复核员确认演示批次里的 5 条后，有效层 5/9 | — | — |

两点值得汇报：①模板文本上规则的召回率接近 100% 不说明任何问题，真实病历要用医生标注重测；②"规则漏抽 → LLM 补抽 → 复核确认"这条链路在有效层上是可度量的，没进复核批次的值不会自动生效。

## 附录：演示步骤

启动（本机，只含虚构数据）：在 `flucase/` 下运行 `bash scripts/run_demo.sh`，打开 http://127.0.0.1:8000 。第一次启动时后端用三个虚构样例真实跑一遍流水线（约 5 秒）；要从头再演示，停掉服务、删除 `var/` 后重启。演示密码 demo。

1. 研究者登录 → 总览：运行记录（v0 与 v0.1 两组）、演示脚本；
2. 导入与映射：选一个虚构样例 → 识别与校验 → 映射预览 → 运行，S1–S11 逐步显示计数；
3. 病例（EHR）：发病时钟取自主诉；"必要时气管插管"记假设不计入；"SpO2降至"由 LLM 补抽进入复核；切换自动层 / 有效值；
4. 病例（CRF）：单元格证据；ICU 勾选无时间、"呼吸机"结局与通气列冲突；
5. 换 reviewer1 / reviewer2：盲法判定同一条 A 类条目；
6. 研究者 → 共识：定稿后回病例看有效值与分级更新；
7. 规则集：v0.1 改了什么、两版对比、"用此版本重算"；
8. 质控：覆盖率、时间精度、一致性、可行性计数、候选结局、抽取评测；冻结快照；
9. 录入员 entry1：填入虚构示例，漏选吸氧状态被拦下；提交后生成随访；下载 Excel 模板。
