# flucase 病例复核：请医生帮忙做的事

> **给研究者（发给医生前删掉这一框）**
>
> - 本文按 11-03 研究者定的方式写：本中心医生直接看到待复核项、自己领，**每条至少两位医生**（A、B 类一样）。flucase 已在分支 `feat/review-pool-20261103` 上实现（本机虚构数据测过），**还没有部署到京东云**；部署之前医生的账号里还没有“待复核”。
> - 研究者的操作：在“复核”页点“建复核批次”，选病例库某个中心的运行，分派方式选“本中心医生自领”（默认），点“开放给本中心医生”。每个中心至少要有两位医生账号，否则条目会一直停在“还差人”。
> - 文中还有两处【待定】：医生记得的情况和病历不一致时怎么判；每人大致要做多少。两人不一致时，系统现在是研究者在“共识”页定稿（第五节）；如果想改成交给本中心第三位医生，要另外改系统。
> - 第六节“本地模型”一段，只有决定采用模型预审后才保留。

---

## 一、这是在做什么

flucase 会从您导入的病历和表格里自动读出一些关键信息，比如“有没有用有创呼吸机、什么时候开始用的”“有没有进 ICU”“哪一天起病”。研究里一位老年流感患者算不算“转重”，就是按这些信息定的。

自动读取有时会读错，有时拿不准，比如“必要时气管插管”算不算已经插了管。遇到拿不准的地方，系统会把它整理成一个个小问题，请您对照原文片段作答。

**您的回答是研究里的最终标准。** 它会改正系统读到的值，也用来检验自动读取到底有多准。

---

## 二、您要做的事（每次几分钟，随时可停）

1. 用您**导入数据的同一个账号**登录。左侧“待复核”旁边的数字，是本中心还在等您判的条数；“我的中心”页上也有一张“待复核”卡片。
2. 点“待复核”。左边是本中心的条目，系统已经排好顺序（要紧的、已经有一位医生判过的排在前面），从第一条开始做就行。每条旁边写着“**已判 n / 至少 2 位**”。
3. 看右边：最上面是问题和“本条至少 2 位医生各自判定”“已有 n 位医生判过”，下面是背景（年龄段、数据来源、时点）和原文片段，相关的词已经高亮。
4. 选“是 / 否 / 不确定”，也可以按键盘 1 / 2 / 3。
5. 问题问到时间、您又选了“是”的，填首次时间，并选精度：到分钟 / 只有日期 / 无法确定。
6. 写一句理由，说明依据的是哪一段原文。
7. 点“提交并下一条”（Ctrl 或 ⌘ + Enter）。每次做几条都行，下次登录接着做。

问题前面会标一个类别，帮您知道要看什么：

| 类别 | 一般在问什么 |
|---|---|
| 时间核对 | 某项治疗或事件（有创通气、无创通气、ICU、休克、ECMO）是否发生，首次是什么时候 |
| 记录核对 | 两处记录对不上，比如表格里“呼吸机”一栏和“无创 / 有创”两栏 |
| 语境判断 | 一句话是否表示当时**已经**发生，比如“必要时”“拟”“家属拒绝” |
| 起病时间 | 哪一天开始发病 |
| 吸氧状态 | 测血氧饱和度时，病人是吸着氧还是吸空气 |
| 数值与单位 | 数值是否合理、单位对不对 |
| 随机核对 | 系统已经自动接受的内容，随机抽出来请您再看一次 |

## 三、判定时请遵守的几条

| 情况 | 怎么做 |
|---|---|
| 证据不够、看不明白 | 选“不确定”，不要猜。“不确定”本身就是有用的答案 |
| “必要时……”“拟……”“建议……”“家属拒绝……”“术中……” | 问题问的是“当时是否已经发生”。预案、计划、被拒绝的，都不算已经发生 |
| 时间 | 原文写到几点几分，就填到分钟；只写了日期，选“只有日期”；看不出来，选“无法确定”。不要按查房或书写时间去估 |
| 和同事讨论 | 提交之前，请不要和同事讨论这一条。每条都要两位医生各判一次，您能看到已有几位判过，但两人互相看不到对方的答案 |
| 发现自己判错了 | 可以改，写明原因再提交。原来的答案会保留在记录里 |
| 不熟悉这类问题 | 可以点“跳过…”写一句原因，留给本中心其他医生。跳过的在“已跳过”里，想判随时可以回来判 |
| 列表里写着“有医生正在判” | 已经有两位医生在判这一条（打开一条，会为这位医生保留 30 分钟），换别的条目即可 |
| 条目看起来很简单 | 有一部分是随机抽查，用来估计系统的准确率，请照常判 |
| 您记得的情况和病历写的不一样 | 【待定】建议按病历判，并在理由里写明 |

## 四、为什么看不到系统的结论

复核页上只有问题和原文，看不到系统怎么判的，也看不到另一位医生的答案，也不显示病例编号。

这样安排，是为了让您的判断不受系统影响，研究才能拿您的答案去检验系统；两位医生的答案互相独立，也才能算出医生之间的一致程度。如果先让您看到系统的答案，大家很容易顺着它走，检验就不准了。

您导入数据的页面同样不显示系统的分级结论，道理相同。

---

## 五、提交之后会怎样

- **每条都要两位医生**：只有一位判过时，这一条还不生效；第二位判完，两人答案一致就定稿。
- **两人不一致**：由研究者把两人的答案和原文并排比较，必要时约两位医生一起看，定稿并写明理由。
- 两位都判完的条目，不会再出现在其他医生的列表里。
- 定稿的答案会改写系统里的这一项，病例的分级随之自动重算。您导入的原始数据不会被改动，所有修改都留有记录。
- 复核结果只用于本研究。

## 六、常见问题

**要做多少？**
【待定】

**我能看到别的医院的病例吗？**
不能。您只看得到本中心的条目，别的中心的医生也看不到您中心的。

**我管过的病人，我能判吗？**
能。请按问题和原文作答。

**有时候会让我把整份病历逐项填一遍？**
会有少量这样的条目（“全字段标注”）：左边是整份文书，右边逐项填写，用来全面检查系统漏读了什么。页面上有单独的填写说明。

**以后会用 AI 吗？**
【只有决定采用时才保留这一段】研究者可能在课题组自己的服务器上运行本地模型，先把有把握的条目过一遍；病例内容不会发给任何外部网站或在线服务。采用以后，您看到的条目会少一些，主要是模型拿不准的、模型和规则判得不一样的，以及随机抽查。模型的结论同样不会显示给您；您的答案正是用来检验模型准不准的标准。
