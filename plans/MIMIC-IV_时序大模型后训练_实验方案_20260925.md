## 1. 研究问题与假设

### 1.1 为什么这样设计

调研中的四条结论直接决定了本方案的结构：

1. 医学时序基础模型的后训练，主流仍是监督、时间到事件似然和参数高效适配。强化学习后训练在 2025–2026 年于 ECG、EHR 上成型，配方是 SFT 热身 + GRPO/DAPO + 可核对的结局奖励 + 格式奖励；在本组检索范围内，流感或老年转重的 LLM-RL 后训练为 0 篇。（C001、C011、C012）
2. 预测侧奖励必须有界、相对强基线，并防止组内零方差。PostTime 报告绝对误差奖励下 27.97% 的组近零方差，改为相对改进后降到 4.66%。（S005、S006、S007）
3. LLM 在医学时序上并未稳定胜过专门模型；A 线论文很少与 LightGBM、GRU-D 正面比较。（S042、S045）因此本方案把强监督基线列为主对照，而不是只比未微调的 LLM。
4. 给阳性样本加权的适当评分规则，会让最优输出偏离真实概率：p* = w·q / (w·q + 1 − q)。q = 0.10、w = 3 时 p* = 0.25，系统性高估 2.5 倍。（C020，本组推导）因此奖励里只放适当评分规则。

### 1.2 预注册假设

下表的比较均在 MIMIC-IV 测试集、≥65 岁、全部 landmark、24h 主终点上进行。"E2 最佳"只按验证集 AUPRC 选出。

| 编号 | 比较 | 主指标 | 判定规则 | 家族 |
|---|---|---|---|---|
| H1 | E2 最佳时序基础模型后训练 vs LightGBM | ΔAUPRC | 95% CI 下界 > 0 → 优于；TOST 落在 ±0.02 内 → 等价；其余 → 未判定 | 主（Holm） |
| H2 | Qwen3-4B：SFT→GRPO(Brier) vs 同底座仅 SFT | ΔBrier（越低越好） | 95% CI 上界 < 0，且 ΔAUPRC 的 CI 下界 > −0.02 → RL 改善概率质量 | 主（Holm） |
| H3 | Qwen3-4B GRPO(Brier) vs LightGBM | ΔAUPRC | CI 下界 > −0.02 → 非劣；CI 下界 > 0 → 优于 | 主（Holm） |
| H4 | GRPO 加权 Brier（w = 3）vs GRPO Brier（Qwen3-1.7B） | 校准截距；平均预测 − 阳性率 | 偏移方向与 p* 推导一致且 CI 不含 0 → 推导得到经验支持 | 次要 |
| H5 | 最佳模型与 LightGBM 在 eICU 上的判别与校准 | ΔAUPRC；校准斜率 | 描述 + 95% CI | 次要 |
| H6 | 证据奖励 λ > 0 vs λ = 0 | 证据精确率、幻觉证据率、Brier | 描述 + 95% CI | 次要 |

注意：H3 中 LLM 的 SFT 目标概率来自 LightGBM 的袋外预测（§6.3），所以 H3 实际检验的是"强化学习能否让学生超过老师"。不依赖老师的 SFT-cls 结果同时报告。

### 1.3 本轮不做

- **治疗或资源决策的强化学习。** 没有定义动作日志与状态转移；离线策略评估对终点和 MDP 定义敏感（S013、S027）。
- **报警停时策略的训练。** E6 只计算效用分，不训练策略。
- **闭源在线 API 模型的对照。** 见 §12 合规。
- **因果解释。** 所有"增量"均指给定同样信息后的额外预测收益。

## 2. 数据、队列与标签

### 2.1 数据源

| 数据 | 角色 | 版本 | 访问 | 说明 |
|---|---|---|---|---|
| MIMIC-IV | 开发（训练、验证、内部测试） | 撰写时参照 v3.1；执行时以 PhysioNet 当前版本为准并写入 `data_manifest.json` | PhysioNet 凭证 + CITI 培训 + DUA | hosp 与 icu 模块；使用 mimic-code 派生概念（ventilation、vasoactive_agent、sofa 等） |
| eICU-CRD | 外部验证（多中心） | v2.0 | 同上 | 208 家医院 ICU；只用于测试，不参与训练和调参 |
| HiRID | 可选外部验证 | v1.1.1 | 同上 | 高频监测；无 ICD 诊断，呼吸道感染需按入科诊断分组近似 |
| AmsterdamUMCdb | 可选外部验证 | 以获批版本为准 | 单独申请 | 欧洲人群 |

多库变量统一优先复用 YAIB / ricu 的概念字典，不自行重写跨库映射（S046）。概念名称与单位以所用 ricu 版本为准，审计阶段逐项核对。

### 2.2 队列

**纳入：**

1. 每次住院的首次 ICU 入住，入 ICU 时年龄 ≥18 岁（MIMIC-IV 年龄 = anchor_age + 入院年份 − anchor_year）。
2. 当次住院为急性呼吸道感染（ARI）：
   - MIMIC-IV：ICD-10 J09–J18、J20–J22，或 ICD-9 480–488、466；或住院期间流感/呼吸道病毒检测阳性（microbiologyevents 与 labevents，检测条目名在审计时人工核对后冻结）。
   - eICU：`diagnosis.diagnosisstring` 或 `admissiondx` 含肺炎、流感、病毒性呼吸道感染；关键词表在审计时冻结，且只取 `diagnosisoffset ≤ t0` 的诊断。
3. 至少有一个 landmark 满足下述风险集条件。

**排除：**

- COVID-19（U07.1）在主分析中排除，另作敏感性队列。
- 入 ICU 时已气管切开。

**每个 landmark 的风险集条件：** `t0` 时仍在 ICU，未出院、未死亡；本次住院内 `t0` 前从未开始有创通气或升压药；`t0` 时没有"不插管（DNI）"或"仅舒适治疗"医嘱。老年患者常有 DNI 医嘱，此时"未插管"不等于"未转重"，会造成标签偏倚。纳入这些患者的版本作敏感性分析。

**子组：**

- 流感子组：ICD J09–J11 / 487–488，或流感检测阳性。敏感性分析用"可部署"定义：流感阳性结果在 `t0` 前已回报。
- 年龄层：18–64、65–74、75–84、≥85。

当次住院的 ICD 诊断在出院时编码，只能用于入组，不能作为模型输入。

### 2.3 预测时点与观察窗

- **预测时点：** `t0` ∈ {6, 12, 18, …, 72} 小时（相对入 ICU 时刻），每 6 小时一个 landmark，满足风险集条件才生成样本。
- **观察窗：** [t0 − 24h, t0]。入 ICU 前的部分通常只有化验（MIMIC-IV hosp.labevents；eICU 中 offset 为负的化验）。
- **主评估：** 全部 landmark 合并，按患者聚类估计不确定性。**次要：** 只取 `t0 = 6h`（最早预警），以及按 `t0` 分层。

### 2.4 终点

| 终点 | 定义 | 用途 |
|---|---|---|
| 主终点 Y24 | (t0, t0 + 24h] 内首次发生：有创机械通气开始；升压药开始（去甲肾上腺素、肾上腺素、去氧肾上腺素、血管加压素、多巴胺，不含多巴酚丁胺、米力农）；院内死亡 | H1–H6 |
| Y48、Y72 | 同上，窗口为 48h、72h | 次要 |
| 组分终点 | 通气、升压药、死亡分别报告 | 次要 |
| 扩展终点（可选） | 主终点，或 `t0` 时未用无创通气/高流量者新开始 NIV/HFNC | 探索 |

- **事件时间来源：** MIMIC-IV 用 mimic-code 的 ventilation 派生表（有创通气类别）与 vasoactive_agent；eICU 用 respiratorycare / treatment / infusiondrug，经 ricu 概念统一。某库若无法区分有创与无创通气，该库终点改为"任意机械通气"并在结果中标注。
- **竞争事件：** 院内随访到出院是完整的，出院存活视为竞争事件而非删失。因此窗口二分类标签就是累计发生率（CIF）的估计目标；另用离散时间竞争风险模型（DeepHit）做一致性检查。
- **敏感性：** 设 1 小时盲区，剔除事件落在 (t0, t0 + 1h] 的样本，检查模型是否只是在识别已经开始的事件。

### 2.5 数据切分

- MIMIC-IV：按 `subject_id` 分层随机 70/10/20。分层变量为是否发生主终点、是否 ≥65 岁、是否流感。种子固定，患者 ID 列表存档。
- 所有调参、早停和模型选择只用验证集；测试集锁定，解盲流程见 §9.4。
- 时间外推敏感性：按 anchor_year_group，2008–2016 训练、2017–2019 测试；2020–2022（若版本包含）单独报告。
- eICU：全部合格住院均为外部测试。"仅重校准"分析按医院切分：20% 医院作校准集，80% 医院评估。

### 2.6 特征与三种输入视图

同一张逐小时特征表派生出所有模型的输入，保证各模型看到的信息相同。

| 模型 | 输入视图 | 实现 | 调参 |

### 5.2 后训练方案

| 代号 | 做法 | 可训练参数 | 学习率 |
|---|---|---|---|

| R1 | LoRA（r = 8，注意力 q、v）+ 风险头 | 约 0.5–2% | 1e-4 |
| R2 | 全参微调（只对 ≤50M 的模型） | 100% | 2e-5 |
| R3 | 域内继续预训练（MIMIC-IV 训练集序列；MOMENT 用掩码重建，Chronos 用预测损失，5 个 epoch）后接 R1 | — | 1e-4 |

- **风险头：** 拼接（池化后的时序嵌入、静态特征、观测过程特征）→ MLP（隐藏 256）→ 三个输出（24/48/72h）各接 sigmoid，损失为三个 BCE 之和。
- **训练：** batch 128，bf16，最多 30 个 epoch，按验证集 24h AUPRC 早停（patience 5），5 个种子。
- **选择：** 所有 E2 组合中验证 AUPRC 最高者进入 H1。
- **可选 E2-HF：** 在 eICU 或 HiRID 上用 5 分钟高频体征（24h = 288 点）重复最佳组合，检验时序基础模型是否需要高频输入才有优势。

| 评估解码 | 主：贪心（temperature 0）；次：8 次采样取均值 | — |
| 种子 | 3 个 | — |

### 7.2 奖励定义

**解析与格式：** 输出必须完整匹配 `<think>…</think><evidence>…</evidence><answer>p</answer>`，p 为 [0, 1] 内最多两位小数。不合规时总奖励为 0（TimeSRL 的做法），不再计算其他分项。

**合规时：** R = 0.1 × 1 + 0.9 × R_out + λ × R_evid。

| 代号 | R_out | 取值范围 | 预期 |
|---|---|---|---|
| Brier（主） | 1 − (p − y)² | [0, 1] | 期望奖励在 p = q 时最大，保持校准 |
| 0/1 | 1[ 1(p ≥ 0.5) = y ] | {0, 1} | 阳性率低时"全答低风险"也能拿高分，预期灵敏度与校准塌缩 |
| 对数（EAG-RL 式） | log(y·p̃ + (1 − y)(1 − p̃)) + Δ；p̃ = clip(p, 0.01, 0.99)；Δ 按 EAG-RL 的间隔奖励，β = 0.5 | 约 [−4.61, 0.25] | 严格适当；裁剪后有界。EAG-RL 未给 β，本方案取 0.5 |
| 加权 Brier（w = 3） | w^y × [1 − (p − y)²] | [0, 3] | 按 p* = wq / (wq + 1 − q) 系统性高估（H4 压力测试，不用于正式模型） |
| 相对改进（可选，PostTime 式） | clip{ [(p_T − y)² − (p − y)²] / max[(p_T − y)², 0.01], 0, 1 }，p_T 为老师概率 | [0, 1] | 只奖励超过老师的部分，用于罕见结局下的组内区分度 |

**证据奖励：** R_evid = Jaccard（模型 evidence 中的合法代码集合，规则参考集）。两者都为空时记 1；词表外的代码不计入集合，单独统计为"幻觉证据"。λ ∈ {0, 0.1, 0.2}。参考集按附录 A 的规则，只用 `t0` 前数据生成（L7）。

参考实现见附录 C。

### 7.3 消融矩阵

| 组 | 底座 | 奖励 | 优势归一化 | 种子 | 回答的问题 |
|---|---|---|---|---|---|
| G0 | 1.7B、4B | 无强化学习（SFT-cot） | — | 3 | 基准 |
| G1 | 1.7B、4B | Brier | 除以组内 std | 3 | H2、H3 |
| G2 | 1.7B | 0/1 | 除以组内 std | 3 | 0/1 奖励是否塌缩 |
| G3 | 1.7B | 对数（裁剪） | 除以组内 std | 3 | 两种适当评分规则的差别 |
| G4 | 1.7B | 加权 Brier，w = 3 | 除以组内 std | 3 | H4 |
| G5 | 1.7B；最佳 λ 进 4B | Brier + 证据，λ = 0.1 | 除以组内 std | 3 | H6 |
| G6 | 1.7B | Brier + 证据，λ = 0.2 | 除以组内 std | 3 | H6 |
| G7 | 1.7B | Brier | 只减均值 | 3 | 除以 std 是否放大组内噪声 |
| G8（可选） | 1.7B | 相对改进 | 除以组内 std | 3 | 罕见结局下的组内区分度 |
| G9（可选） | 1.7B | Brier + 阳性 2 倍过采样 + 先验校正 | 除以组内 std | 3 | 过采样的校准代价 |

核心运行数：1.7B 上 G1–G7 共 7 × 3 = 21 次；4B 上 G1 与 G5（取 1.7B 上验证最佳的 λ）共 2 × 3 = 6 次。过采样 k 倍后的先验校正：几率除以 k，即 p_corr = (p/k) / (p/k + 1 − p)。

### 7.4 训练监控

每步记录：

- 奖励均值与标准差；**近零方差组比例**（组内奖励 std < 1e-3 的组所占比例；PostTime 报告的基线为 27.97%）。
- 格式错误率、平均回答长度。
- 批内平均预测概率与批内阳性率之差（校准漂移的早期信号）。
- KL、熵、被裁剪 token 比例。

**中止条件：** 格式错误率连续 50 步超过 20%；或验证 Brier 连续 4 次评估变差。

### 7.5 双 L40 部署

L40 之间没有 NVLink，只经 PCIe 通信，因此按角色分卡，而不做跨卡张量并行：

```
GPU0（L40 48GB）：策略模型 + LoRA 训练；参考模型 = 同一底座关闭 LoRA，不额外占显存
GPU1（L40 48GB）：vLLM 生成服务，每步为 16 个提示各生成 8 条回答
CPU：奖励函数（解析、Brier、Jaccard），无需 GPU
每步流程：GPU1 生成 → CPU 计算奖励与组内优势 → GPU0 更新 → 合并后的权重同步到 GPU1
```

启动示意（命令与参数名以 E-1 阶段锁定的 TRL 版本文档为准）：

```bash
# GPU1：启动 vLLM 生成服务，加载 SFT-cot 合并后的权重
CUDA_VISIBLE_DEVICES=1 trl vllm-serve \
  --model ckpt/sft_cot_qwen3-4b_seed1_merged \
  --gpu-memory-utilization 0.85 --max-model-len 2048

# GPU0：启动 GRPO 训练，配置文件中 use_vllm=true、vllm_mode=server
CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  src/llm/train_grpo.py --config configs/grpo/qwen3-4b_brier_seed1.yaml
```

配置文件的关键项（YAML，注释说明含义）：

```yaml
# configs/grpo/qwen3-4b_brier_seed1.yaml
model_name_or_path: ckpt/sft_cot_qwen3-4b_seed1_merged   # SFT-cot 合并权重
reward: {kind: brier, lam: 0.0, w_fmt: 0.1, w_out: 0.9}   # 见附录 C
peft: {r: 32, lora_alpha: 64, lora_dropout: 0.05, target_modules: all-linear}
grpo:
  num_generations: 8            # 组大小 G
  prompts_per_step: 16          # 每次参数更新看 16 个提示 = 128 条回答
  micro_batch_completions: 4    # 每次前向/反向的回答条数，按显存调整
  max_prompt_length: 1536
  max_completion_length: 384
  temperature: 1.0
  beta: 0.001                   # KL 系数
  epsilon: 0.2                  # PPO 式裁剪
  scale_rewards: true           # G7 组设为 false：优势只减组均值
  learning_rate: 1.0e-5
  warmup_ratio: 0.03
  num_train_epochs: 1
  bf16: true
  gradient_checkpointing: true
  use_vllm: true
  vllm_mode: server
  eval_every_steps: 25
  seed: 1
# 说明：prompts_per_step 与 micro_batch_completions 需换算成所用 TRL 版本的
# per_device_train_batch_size / gradient_accumulation_steps / generation 相关字段，
# 并满足该版本对 num_generations 的整除要求。
```

**单卡退路：** 1.7B 可在一张 L40 上用 vLLM colocate 模式（生成与训练共卡，vLLM 显存占比约 0.3）；4B 单卡时把每步提示数降到 8、回答上限降到 256。若 TRL 双卡吞吐不足，备选 verl（FSDP + vLLM）。

### 7.6 显存与耗时估算（E-1 实测后替换）

以 Qwen3-4B（36 层、隐藏维 2560、8 个 KV 头 × 128 维、词表约 15.2 万）为例：

| 项 | 估算 | 说明 |
|---|---|---|
| bf16 权重 | 约 8GB | GPU0、GPU1 各一份 |
| LoRA（r = 32）参数与 Adam 状态 | < 1GB | 约 6–7 千万参数 |
| 激活（梯度检查点，每微批 4 条 × 约 1.9k tokens） | 约 2–4GB | — |
| 回答部分的 logits（fp32） | 约 1GB | 4 条 × 384 tokens × 15.2 万 × 4 字节；只保留回答位置 |
| GPU0 合计 | 约 15–25GB | 余量充足 |
| GPU1 KV cache | 每 token 约 144KB | 0.85 利用率时约可容纳 22 万 tokens；128 条 × 1.9k tokens 略超，vLLM 会分批调度 |

## 附录 C 奖励函数参考实现

只依赖 Python 标准库，可直接注册到 TRL 的 `GRPOTrainer(reward_funcs=[...])`。TRL 会把数据集中与参数同名的列通过关键字参数传入，因此数据集需要提供 `label`（0/1）、`evidence_ref`（参考证据代码列表），相对改进奖励另需 `teacher_p`。

```python
"""GRPO 奖励函数（实验方案附录 C）。

用法示意：
    reward_fn = make_reward_fn(kind="brier", lam=0.0)
    trainer = GRPOTrainer(model=..., reward_funcs=[reward_fn], args=..., train_dataset=ds)
"""
import math
import re

# 回答必须完整匹配这个格式：<think>…</think><evidence>…</evidence><answer>p</answer>
# p 允许写成 0、0.3、0.35、1、1.0、1.00；re.S 让 "." 可以匹配换行
ANSWER_PATTERN = re.compile(
    r"^\s*<think>(?P<think>.*?)</think>\s*"
    r"<evidence>(?P<evidence>.*?)</evidence>\s*"
    r"<answer>\s*(?P<p>0(?:\.\d{1,2})?|1(?:\.0{1,2})?)\s*</answer>\s*$",
    re.S,
)

# 附录 A 的证据代码词表；模型写出的代码必须在表内才计入 Jaccard
EVIDENCE_VOCAB = {
    "SPO2_LOW", "SF_RATIO_LOW", "PF_RATIO_LOW", "FIO2_HIGH", "O2_ESCALATION",
    "NIV_OR_HFNC", "RR_HIGH", "HR_HIGH", "SBP_LOW", "MAP_LOW", "GCS_LOW",
    "TEMP_ABNORMAL", "LACTATE_HIGH", "PH_LOW", "PACO2_HIGH", "CREAT_HIGH",
    "BUN_HIGH", "WBC_ABNORMAL", "PLT_LOW", "BILI_HIGH",
}


def completion_to_text(completion):
    """TRL 对话格式下 completion 是 [{"role": "assistant", "content": "..."}]，
    普通格式下是字符串。这里统一转成字符串。"""
    if isinstance(completion, list):
        return completion[0]["content"]
    return completion


def parse_answer(text):
    """解析一条回答，返回 (概率 p, 合法证据代码集合, 词表外代码集合)。
    格式不合规时返回 None，调用方据此把总奖励记为 0。"""
    match = ANSWER_PATTERN.match(text)
    if match is None:
        return None
    p = float(match.group("p"))
    codes = {c.strip().upper() for c in match.group("evidence").split(";") if c.strip()}
    valid = codes & EVIDENCE_VOCAB      # 计入 Jaccard 的代码
    invalid = codes - EVIDENCE_VOCAB    # 词表外代码：不计分，单独统计为"幻觉证据"
    return p, valid, invalid


def brier_reward(p, y):
    """有界 Brier 型适当评分：1 - (p - y)^2，取值 [0, 1]。
    真实风险为 q 时，期望奖励 q*(1-(1-p)^2) + (1-q)*(1-p^2) 在 p = q 处最大，
    所以模型因"说真话"得分最高，概率保持校准。"""
    return 1.0 - (p - y) ** 2


def indicator_reward(p, y):
    """0/1 奖励（对照组）：把 p 按 0.5 切成类别，与标签相同得 1 分。
    阳性率很低时，"一律给低概率"也能拿到很高的期望奖励。"""
    return 1.0 if int(p >= 0.5) == y else 0.0


def log_score_reward(p, y, beta=0.5):
    """EAG-RL 式对数得分加间隔奖励（EAG-RL 未给 beta，这里取 0.5）。
    先把 p 裁剪到 [0.01, 0.99]：否则 p 为 0 或 1 且答错时 log 为负无穷，
    会在组内归一化时主导整组的优势。"""
    q = min(max(p, 0.01), 0.99)
    reward = math.log(y * q + (1 - y) * (1 - q))
    if y == 1 and q > 0.5:
        reward += beta * (q - 0.5)      # 正例答对，且越有把握加分越多
    elif y == 0 and q < 0.5:
        reward += beta * (0.5 - q)      # 负例答对，同理
    return reward


def weighted_brier_reward(p, y, w=3.0):
    """给阳性样本乘权重 w 的 Brier 奖励，只用于 H4 压力测试。
    推导：最优输出变为 p* = w*q / (w*q + 1 - q)，会系统性高估风险。"""
    return (w if y == 1 else 1.0) * brier_reward(p, y)


def relative_improvement_reward(p, y, teacher_p, floor=0.01):
    """PostTime 式相对改进：模型的平方误差比老师（LightGBM 袋外概率）少了多少比例，
    裁剪到 [0, 1]。floor 防止老师几乎全对时分母接近 0、奖励剧烈波动。"""
    teacher_loss = (teacher_p - y) ** 2
    model_loss = (p - y) ** 2
    ratio = (teacher_loss - model_loss) / max(teacher_loss, floor)
    return min(max(ratio, 0.0), 1.0)


def jaccard(a, b):
    """两个集合的 Jaccard 相似度；两者都为空时视为完全一致，返回 1。"""
    if not a and not b:
        return 1.0
    return len(a & b) / len(a | b)


OUTCOME_REWARDS = {
    "brier": brier_reward,
    "indicator": indicator_reward,
    "log": log_score_reward,
    "wbrier": weighted_brier_reward,
}


def make_reward_fn(kind="brier", lam=0.0, w_fmt=0.1, w_out=0.9):
    """生成可注册到 GRPOTrainer 的奖励函数。
    kind：结局奖励类型（brier / indicator / log / wbrier / relative）；
    lam：证据奖励系数 λ，从 0 开始消融。"""

    def reward_fn(prompts, completions, label, evidence_ref, teacher_p=None, **kwargs):
        rewards = []
        for i, completion in enumerate(completions):
            parsed = parse_answer(completion_to_text(completion))
            if parsed is None:
                rewards.append(0.0)     # 格式不合规：总奖励记 0，不再计算其他分项
                continue
            p, valid_codes, _ = parsed
            y = int(label[i])
            if kind == "relative":
                r_out = relative_improvement_reward(p, y, float(teacher_p[i]))
            else:
                r_out = OUTCOME_REWARDS[kind](p, y)
            reward = w_fmt * 1.0 + w_out * r_out
            if lam > 0:
                reward += lam * jaccard(valid_codes, set(evidence_ref[i]))
            rewards.append(reward)
        return rewards

    reward_fn.__name__ = f"reward_{kind}_lam{lam}"   # TRL 用函数名区分日志里的奖励项
    return reward_fn


def prior_shift_correct(p, k):
    """阳性过采样 k 倍训练后（G9 组），把输出概率校正回自然阳性率。
    过采样等价于把阳性几率（odds）乘以 k，所以这里把几率除以 k。"""
    odds = p / max(1.0 - p, 1e-6)
    odds /= k
    return odds / (1.0 + odds)


def near_zero_std_fraction(rewards, group_size, tol=1e-3):
    """近零方差组比例：同一提示的 group_size 条回答奖励几乎相同的组所占比例。
    GRPO 的优势 = (r - 组均值) / 组标准差，组内没有差异时，这一组对梯度几乎没有贡献。"""
    groups = [rewards[i:i + group_size] for i in range(0, len(rewards), group_size)]
    flat = 0
    for g in groups:
        mean = sum(g) / len(g)
        std = (sum((r - mean) ** 2 for r in g) / len(g)) ** 0.5
        flat += std < tol
    return flat / max(len(groups), 1)
```
