## 〇 先抓住这六个词

整份 PPT 都围绕下面六个词。先把它们弄懂，其余的术语都是在补充细节。

| 词 | 一句话 |
|---|---|
| **O3** | 我们的主结局：老人第一次到门急诊看流感、当时不重也没住院，之后 14 天内会不会住院或变成重型。 |
| **t0 / 窗口** | t0 是"做预测的那一刻"（首次门急诊就诊）；窗口是围绕 t0 划出的时间段：前后 24 小时定基线，之后 14 天看结局。 |
| **口径** | 一个概念具体怎么算的规定。比如"什么算进 ICU"、"什么算确诊"，口径不同，算出来的人数和结局就不同。 |
| **判据（原文 / 代理）** | 判断病情级别的依据。原文判据是诊疗方案上写的（如呼吸 ≥30 次/分）；代理判据是用治疗行为间接代表病情（如"开始吸氧"代表重型）。 |
| **规则集** | 把所有口径和判据写成程序能执行的规则文件，有版本号（现在 v0.3，下一版 v0.4）。 |
| **std_v3** | 我们的统一导出格式：两家医院的数据导出成同样的表、同样的列、同样的编码。 |

## 一　项目、医院与数据来源

**GD**
广东省中医院。本项目的"新数据"中心。PPT 里的"GD 住院原始导出 618"指从它的病历系统导出的 618 次住院。（第 2 页，附录 A1–A4）

**GAM**
中国中医科学院广安门医院。本项目的"旧数据"中心，现有住院 173 次、门急诊 1,166 次。（第 2 页，附录）

**中心 / 多中心 / 两院**
一家参与研究的医院就是一个"中心"。多中心研究就是几家医院的数据合在一起做，好处是样本多、能检验模型换一家医院还准不准。我们现在只有两个中心（GD、GAM），所以 PPT 反复说"要多收中心"。（第 6–8 页）

**住院 / 门急诊 / 发热门诊**
住院是收进病房；门急诊是门诊加急诊，看完就回家（或留观）；发热门诊是专门接诊发热病人的门诊，流感季很多流感病人第一站就在这里。O3 是从门急诊出发的预测，所以门急诊和发热门诊的数据是关键。（第 2、8 页，附录 A4）

**原始导出**
医院病历系统直接导出的 Excel，没有经过整理。GD 的原始导出是一整套 20 个 xlsx 文件。（第 2 页）

**信息科**
医院里管信息系统、负责数据导出的部门。申请门急诊、发热门诊的数据要经过它。（第 8 页，附录 A4）

**前瞻收集 / 前瞻表单 / 回顾性数据**
回顾性数据是用已经存在的病历；前瞻收集是从现在开始，按事先设计好的表单、在固定的时间点给新入组的病人记录数据。前瞻的好处是变量和时间点统一、缺失少；代价是要等病人、要人力。"前瞻表单待上线"指这套表单还没开始用。（第 2、8 页）

**病例报告表（CRF）**
Case Report Form，临床研究里给每个病人填的标准化表格。ISARIC 4C 用的就是公开的标准化病例报告表，所以各家医院记的东西一样。（第 6 页）

**聚合量 / 只报聚合量**
只报告计数、比例、均值这类汇总数字，不出现任何单个病人的记录。项目规定文档里只放聚合量，1–9 这样的小数字写成"<10"，防止有人从很小的数字反推出具体的人。（第 2 页）

## 二　数据系统与数据集工程

**flucase / 病例库**
本项目自己开发的网页版病例数据收集系统。医生把本院 Excel 导进去，系统读成"病例库"（按就诊整理好的病例记录），部署在专用服务器上。（第 2 页）

**入库 / "读到了什么"再确认**
导入分四步：选文件 → 认格式 → 看系统读到了什么 → 确认导入。医生先核对系统读出来的内容对不对，确认后才算"入库"，避免读错的数据混进来。（第 2 页）

**格式族 / 格式配置**
不同医院导出的 Excel 长得不一样。"格式族"是一类导出的共同结构，比如"病历系统多文件导出"这一族，一整套文件按表头认出十几类表；"格式配置"是某家医院在这个格式族下的具体设定，比如列名叫什么、诊断编码范围、吸氧医嘱叫什么名字。新医院接入时，多数情况只需要写一份新的格式配置，不用改程序。（第 2 页）

**可追溯 / 溯源**
数据集里的每个值都记着它来自哪个文件、哪张表、哪一行、哪一列。出问题时能一路查回病历原文。（第 2、7 页）

**文字规则词表**
一套共用的关键词和短语规则，用来从病历文字里认出需要的信息，并排除不该算的语境。比如医嘱写"必要时吸氧""拒绝插管"，就不能算作已经吸氧、已经插管。两院共用同一套，保证同一句话在两家医院被同样处理。具体收了哪些词，以规则集文件为准。（第 2 页）

**规则集（v0.3 / v0.4）**
把分级判据、结局定义这些口径写成程序可以执行的规则文件。每次改口径就换版本号重算，旧版本保留，可以前后对比。v0.3 是现在在用的版本；v0.4 是按 GD 答复修改后的下一版。（第 2、5、7、8 页，附录）

**std_v3 统一导出**
std 是 standard（标准）的缩写，v3 是第三版。指 flucase 导出数据的统一格式：两院同表、同列、同编码、同取值。（第 2、3、7 页）

**同表 / 同列 / 同编码 / 同取值**
- 同表：两家医院导出的是同样几张表；
- 同列：每张表的列名一样；
- 同编码：同一个概念用同一个代码，比如两院叫"血氧""SPO2""经皮血氧饱和度"的，都统一成 SpO2；
- 同取值：取值的单位、类别写法一致，比如都用"是 / 否"，不混用"有 / 无 / Y / N"。

做到这四"同"，同一段分析代码才能直接在两家医院的数据上跑。（第 2 页）

**导出不定 t0、人群和标签**
导出时不预先替分析者决定"预测时点是哪一刻、哪些人纳入、结局是 0 还是 1"，而是把这些都作为列给出来，分析时再按列筛选。这样同一份导出可以服务不同的研究问题。（第 2 页）

**encounters（就诊根表）**
一次就诊一行，包括人口学信息、流感证据（检测结果）、属于哪个流感季。其他表都用"就诊编号"挂在它下面，所以叫"根表"。（第 2 页）

**events（事件表） / 长表与宽表**
事件表是一条观测一行：哪个变量、什么值、什么时间、从哪里来的。这种格式叫"长表"。"宽表"是一个病人一行、每个变量一列，像 CRF Excel 那样。宽表看起来直观；长表适合存时间不规则、次数不固定的数据，比如一个人可能测了 3 次体温，另一个人测了 30 次。（第 2 页）

**分域视图**
从事件表按领域切出来的子表：体征、检验、诊断、流感检测等。数据本身还是同一份，只是按用途分开展示，查起来方便。（第 2 页）

**原值 / 来源 / 时间精度**
原值是病历里原本写的值，没有换算、没有规整；来源是这个值出自哪份文件哪个位置；时间精度说明时间是精确到分钟，还是只知道日期。只有日期的事件会打上 `same_day` 标记，因为这时分不清它发生在 t0 之前还是之后。（第 2、7 页）

**treatments（治疗区间表）**
治疗不是一个时间点，而是一段"从几点开始到几点结束"的区间，比如吸氧从 10 月 3 日 14:00 到 10 月 5 日 9:00。区间表专门存氧疗、通气、ICU 的起止时间。（第 2 页）

**severity_timeline（分级时间线）**
按时间记录病人在每个时刻处于哪一级（中型 / 重型 / 危重型）。每条判据都标注是"原文"还是"代理"。（第 2 页）

**outcomes（结局表）**
按每种口径分别算出来的候选结局，同一个病人在主口径、各敏感性口径下各有一个结果。（第 2 页）

**派生**
不是病历里直接记的，而是由原始记录按规则算出来的量。分级、结局都是派生量。（第 2 页）

**元数据：数据字典 / 映射表 / manifest / SHA256**
元数据是"描述数据的数据"。
- 数据字典：每张表、每一列的含义、单位、可能的取值；
- 映射表：医院原名到统一编码的对照，例如"指脉氧"对应 SpO2；
- manifest：导出包的"装箱单"，列出包含哪些文件、各有多少行、用的是哪一版规则集等；
- SHA256：一种"文件指纹"。文件哪怕只改一个字节，指纹就完全不同，用来证明拿到的文件和导出时的一样、没有被改动。

（第 2、3、7 页）

**版本化发布 / 版本说明**
每次发布数据都给一个版本号，并写明这一版改了什么；旧版本保留。这样任何一个分析结果都能说清楚"用的是哪一版数据"。（第 3、7 页）

**验收测试 / 单元测试 / 完整性 / 一致性 / 阈值 / 与上一版比对**
这是 MIMIC-IV 的做法，我们打算学。数据每次构建完，先让程序自动做一遍检查：
- 完整性：该有的都有，比如每个诊断码都能在字典里找到；
- 一致性：数据之间对得上，比如 MIMIC-IV 要求 ≥99% 的 ICU 住段有诊断、有心率；
- 阈值：给每项检查定一个合格线，低于合格线就不发布；
- 与上一版比对：人数、记录数和上一版相比变化太大就报警。

"单元测试"是程序员的说法，指一项项小的自动检查；"验收测试"强调这些检查是发布前的关卡。（第 3、7、8 页）

**时间来源列**
记录每个时间是怎么来的：测量时刻（护士测体温的时间）、医嘱时刻（开吸氧医嘱的时间）、书写时刻（写病程记录的时间）、还是推断的。同一件事，这几种时间可能差几个小时，对"t0 之前还是之后"影响很大。这个想法来自 MIMIC-IV 把 charttime 和 storetime 分开存。（第 3、7、8 页）

**查找表（ICU 查找表）**
单独维护的一张对照表，列出哪些科室算 ICU、哪些科室要结合医嘱判断。不把这些名单写死在程序里，以后改名单只改表、不改代码。（第 3、7、8 页）

**允许取值清单（受控词表）**
给每个统一编码规定可以取哪些值，比如"呼吸支持设备类别"只能是"鼻导管 / 面罩 / 高流量 / 无创 / 有创"等几种。出现清单以外的值，系统就报警。（第 4、7 页）

**呼吸支持长表**
仿照 CLIF 的呼吸支持表：每次呼吸支持记一行，写明设备类别、开始和结束时间、医院原文。有了它，就能分清"吸氧""高流量""无创""有创"，而不是笼统地记一个"吸氧"。（第 4、7、8 页）

**预测实例 / 预测实例表**
"预测实例"是一次预测机会：某个病人在某个 t0 做一次预测。预测实例表是每个实例一行，写明是谁、t0 是什么时候、窗口从哪到哪、标签是 0 / 1 / 未知、如果被排除则写明排除原因。这张表是"任务定义可复现"的直接证据。（第 5、7、8 页）

**任务文件 / 拆两层**
仿照 ACES，把规则集拆成两层：
- 中心专用的判据映射：每家医院的"吸氧""ICU"在本院数据里怎么认；
- 中心无关的 O3 任务文件：触发、窗口、排除规则，对所有医院都一样。

新医院接入时只写第一层，第二层不动。（第 5、7、8 页）

**Healthsheet**
给健康数据集写的"说明书"模板（Rostamzadeh 等，FAccT 2022）。用一组问题把数据集说清楚：谁建的、为什么建、纳入了谁（谁被代表、谁没有）、标签怎么来的、有几个版本、各站点有什么差异。（第 8 页备注）

## 三　临床概念

**《流行性感冒诊疗方案（2025 年版）》**
国家发布的流感诊疗方案，本项目的分级判据和中医证型都依据它，PPT 里简称"方案"。（第 2 页，附录 A3）

**起病 / 流感样症状**
起病是第一次出现流感样症状（发热、咳嗽、咽痛、全身酸痛等）的时间，是"发病时钟"的起点。GD 的意见是：不发热的病人从首个感冒样症状起算。（第 2 页，附录 A2、A4）

**病原学确诊：抗原 / 核酸 / NGS / 弱阳性**
病原学确诊是有实验室证据证明感染的是流感病毒，不只凭症状诊断。
- 抗原检测：快速检测病毒蛋白，几十分钟出结果；
- 核酸检测（PCR）：检测病毒基因，更准确；
- NGS：二代测序，一次能查出多种病原体；
- 弱阳性：结果在阳性边缘。GD 的意见是弱阳性算阳性。

（第 2 页，附录 A2、A4）

**院内发病**
病人是住院期间才感染或才发病的（院内感染）。这种情况下 t0 取首次流感阳性的时间。（第 2、5 页）

**分级：中型 / 重型 / 危重型**
按 2025 年版方案给病情定级：
- 中型：有肺炎（影像或诊断），或者呼吸困难；
- 重型：呼吸 ≥30 次/分，或吸空气时 SpO2 ≤93%，或氧合指数 ≤300；代理判据是新开始吸氧、高流量；
- 危重型：需要机械通气（含无创），或者休克，或者进 ICU 同时有器官衰竭；代理判据是进 ICU、上 ECMO。

（第 2 页）

**转重**
病情从较轻的级别进展到重型及以上。项目里，现有住院数据只做描述，不叫"转重"；"转重"指 O3 这样带时间方向的定义。（标题，第 6 页）

**基线**
预测时刻（起点窗内）病人的病情级别。O3 要求基线不超过中型，已经是重型的病人就谈不上"会不会变重"，所以排除。（第 2、5 页）

**RR（呼吸频率）**
每分钟呼吸次数。成人正常为每分钟十几次，≥30 次/分是重型判据之一。（第 2 页，附录 A1）

**SpO2（血氧饱和度） / 吸空气 / 吸氧状态 / 推断**
SpO2 是用指夹测的血液含氧程度，正常在 95% 以上。同一个人吸氧时 SpO2 会被抬高，所以方案要求"吸空气时 SpO2 ≤93%"才算重型。病历里常常不写测量时是否在吸氧，项目按吸氧医嘱来推断，并标上"推断"。GD 只有不到 1% 的 SpO2 被推断为吸空气，所以这条判据在 GD 几乎用不上。（第 2 页，附录 A1）

**PaO2/FiO2（PF，氧合指数） / 血气分析**
PaO2 是动脉血里的氧分压，要抽动脉血做"血气分析"才能测到；FiO2 是吸入气体中的氧浓度，吸空气时是 21%。两者相除得到氧合指数，≤300 mmHg 说明肺的换气功能明显受损。血气分析也是判断呼吸衰竭的主要依据。（第 2 页，附录 A1、A2、A4）

**低氧 / 低氧证据**
项目里的定义：吸空气 SpO2 ≤93%、PaO2/FiO2 ≤300，或者呼吸 ≥30 次/分，满足任一条就算有低氧证据。（附录 A1）

**慢性低氧：COPD / 间质性肺病 / 哮喘 / 心衰**
这些慢性病人平时血氧就偏低，不能拿"SpO2 ≤93%"判断他这次变重了。GD 建议把慢性低氧的病种从 COPD 扩大到这三类，并改用血气判断呼吸衰竭。（附录 A2、A4）

**氧疗 / 新开始吸氧 / 长期家庭氧疗**
氧疗就是吸氧。"新开始吸氧"指这次生病后才开始吸，是重型的代理判据；本来在家就长期吸氧的人不算"新开始"。（第 2 页，附录 A1、A4）

**高流量氧疗**
经鼻高流量氧疗：通过鼻塞给加温、加湿的高流量氧气，比普通鼻导管支持力度大。（第 2 页，附录 A1）

**无创通气 / 有创通气（机械通气） / ECMO**
- 无创通气：戴面罩接呼吸机，不插管；
- 有创通气：气管插管或气管切开后接呼吸机，也就是通常说的"上呼吸机"；
- ECMO：体外膜肺氧合，用机器在体外给血液加氧，是最高级别的呼吸支持。

（第 2、6 页，附录 A1）

**休克 / 升压药 / 器官衰竭**
休克是血压低到器官供血不足，通常要用升压药维持血压；器官衰竭指肺、肾、肝等器官功能严重受损。（第 2、3 页，附录 A1）

**ICU / HDU / EICU / 科内监护室**
- ICU：重症监护病房；
- HDU：英国的高依赖病房，介于普通病房和 ICU 之间；
- EICU：急诊重症监护室；
- 科内监护室：普通科室里自设的几张监护床位。

GD 的意见是：科内有监护室的，要看有没有"重症监护"医嘱，不能只看科室名。（第 2、6 页，附录 A1、A2、A4）

**升级治疗 / 不升级**
病情加重时，医生和家属决定要不要给更强的治疗，比如进 ICU、插管。老年人有时因为预后差或本人意愿而不升级，病情虽然重，记录里却没有"进 ICU / 插管"。这样一来，只看治疗类判据，会漏掉这部分"重但没升级"的老人。ISARIC 4C 观察到了这种现象。（第 6 页）

**腋温 / 退热**
腋温是腋下测的体温。GD 的意见是体温都按腋温，不做换算；"昨日到今晨无发热"就算退热。（附录 A2、A4）

**再住院**
出院后又住院。GD 的意见是：14 天内再住院期间发生的转重，算进第一次住院。（附录 A2、A4）

**术后转入 ICU / 围术期**
手术后常规转入 ICU 观察，不一定是流感加重导致的。GD 意见是不排除，但项目会打标记、单独计数。（附录 A2）

**尿素 / CRP / LDH / D-二聚体**
常见检验：尿素反映肾功能和容量状态；CRP（C 反应蛋白）反映炎症程度；LDH（乳酸脱氢酶）在组织损伤时升高；D-二聚体反映凝血和血栓。ISARIC 4C 用了尿素、CRP；LDH、D-二聚体因为能测到的人不到 60%，没有进模型。（第 6 页）

**证型 / 证候 / 辨证**
中医按病人的整体表现，把同一种病分成不同"证型"，作为治疗依据。方案把流感分为三期七型：轻症四型（风热犯卫、风寒束表、表寒里热、热毒袭肺）、重症两型（毒热壅盛、毒热内陷内闭外脱）、恢复期一型（气阴两虚、正气未复）。病历里医生写下的具体说法叫"证候写法"，同一个证型可能有很多种写法，所以要做对应表。项目里证型只作研究变量，不参与分级。各证型的辨证要点以方案原文为准。（附录 A3）

## 四　研究设计与任务定义

**口径**
一个概念在研究里具体怎么算的规定。比如"进 ICU"是只看科室名，还是还要看医嘱，这就是 ICU 的口径。改口径会改变人数和结局，属于研究者要拍板的 A 档决策。（第 2、7、8 页，附录）

**判据：原文判据 / 代理判据**
判据是判断病情级别的依据。原文判据是方案上写明的，比如 RR ≥30 次/分；代理判据是方案没写、但用治疗行为间接反映病情的，比如"新开始吸氧"代表重型、"进 ICU"代表危重型。代理判据好处是病历里容易找到，缺点是受医院习惯影响。分级时间线里每条判据都标明"原文 / 代理"。（第 2 页）

**生理类 / 治疗类 / 诊断类判据**
- 生理类：体征和检验，如 RR、SpO2、PF；
- 治疗类：给了什么治疗，如氧疗、通气、ICU、ECMO；
- 诊断类：医生下的诊断，如肺炎、呼吸困难、呼吸衰竭、休克。

三类分开派生、分开报告。（第 2、6 页）

**主口径（primary） / 敏感性口径 / 敏感性分析**
主口径是主要结果用的算法，项目里是"治疗类 + 诊断类"，因为生理类受测量频率影响最大：GD 有分钟级的监护数据，GAM 只有病历里写的数。敏感性口径是换一种算法再算一遍，比如只用生理类、只用方案原文判据。敏感性分析就是看换了算法以后结论变不变；不变，说明结论稳。（第 2、6 页，附录 A1、A4）

**结局 / 复合结局 / 候选结局**
结局是要预测的事件。复合结局是几种事件任一发生都算，比如 ISARIC 的"开始通气支持、进 HDU/ICU 或死亡"。候选结局是还没最终拍板、先都算出来备选的几种结局定义。（第 2、6 页）

**O3（以及 D0 / O1 / O2）**
O3 是主结局"门急诊早期进展"：首次门急诊就诊、当次没收住院、基线不超过中型的病人，之后 14 天内住院或达到重型及以上记为 1。没能关联到全院记录或转院的记"未知"，不记阴性。
D0、O1、O2 是住院场景的结局：D0 是住院期间达到重型及以上，只做描述；O1 是住院中由中型以下变成重型；O2 是住院中进展到危重型或死亡。O1、O2 是次要结局，现有数据的事件太少，要等新数据。（第 2、5–8 页）

**t0 / 触发 / 预测时点**
t0 是做预测的那一刻。O3 的 t0 是首次门急诊就诊（院内发病的取首次流感阳性）。ACES 把"决定在哪一刻做预测的事件"叫触发（trigger）。（第 2、5 页）

**起点窗 / 标签窗（目标窗） / 间隔窗 / 输入窗**
都是围绕 t0 划出的时间段：
- 起点窗：t0 前后 24 小时，用来确定基线；
- 标签窗（ACES 叫目标窗）：t0 之后 14 天，看这段时间里结局有没有发生；7 天窗作敏感性分析；
- 间隔窗（ACES 的 gap）：触发之后的一段时间，要求这段时间里不能出院或死亡，否则排除。我们的 O3 没有间隔窗；
- 输入窗（ACES 的 input）：模型可以看的数据范围。

（第 2、5 页）

**发病时钟**
从起病到就诊经过了多少天。同样是首次就诊，发病第 1 天来和第 7 天来，风险可能很不一样，所以它既作预测变量，也作分层变量。（第 2 页）

**风险集**
所有符合条件、"有可能发生结局"的预测实例的集合。当次已收住院、基线已是重型的不进风险集。"O3 风险集太小"就是说能拿来做 O3 预测的就诊太少，现在只有 17 次。（第 2 页）

**排除 / 未知 ≠ 阴性**
排除是不进入分析。"未知"是在分析里但结局不确定：比如病人转去别的医院，我们查不到后续，就不能当作"没变重"（阴性），否则会低估转重率。（第 2、5 页）

**人群 / 主分析人群 / 亚组**
人群是纳入研究的病人范围。主分析人群是病原学确诊且 ≥60 岁；亚组是从中再挑出的一部分，比如 ≥65 岁，方案把这部分人列为高危。（第 2 页）

**索引就诊 / 流感季**
同一个病人一个流感季里可能看好几次病。规则是每人每个流感季取第一次符合条件的就诊作为"索引就诊"，之后 14 天内的就诊算同一病程。流感季暂按 ISO 第 40 周到次年第 39 周划分，这样一年全部覆盖，不会漏掉华南的夏季高峰。（第 2 页）

**谓词 / 窗口（ACES）**
谓词（predicate）是"某个事件在本库里怎么认"，比如"入院"对应本库的哪个编码，每个数据库各不相同；窗口是触发、输入、间隔、目标之间的时间关系，跟用哪个数据库无关。ACES 把任务写成"谓词 + 窗口"，换库时只改谓词。（第 5、7 页）

**队列 / 队列抽取 / 复现**
队列是按纳入条件挑出来的一组研究对象。队列抽取是按规则从数据库里把这组人挑出来。复现是别人按同样的描述重做一遍，得到同样的结果。ACES 指出，复现 MIMIC-III 上的研究时，一半以上的队列重建不出来，人数差可达 25%。（第 5 页）

**事件流 / MEDS / ESGPT**
事件流是把病人的所有记录都排成"时间 + 事件 + 值"的一条条记录，和我们的 events 长表很像。MEDS（Medical Event Data Standard）是一种事件流的标准格式；ESGPT 是另一个事件流工具。ACES 要求数据先转成这类格式。（第 5、7 页）

**WHO 临床进展量表**
WHO 为新发呼吸道传染病研究定的一把"尺子"，从 0（未感染）到 10（死亡）：门诊病人 1–3 分；住院不吸氧 4 分，住院面罩或鼻导管吸氧 5 分；无创通气或高流量 6 分；插管上呼吸机及更重 7–9 分；死亡 10 分。它的一个关键设计是"看给了什么支持，不看在哪个病房"。ISARIC 的复合结局约等于 ≥6 分；O3 把"住院"也算结局，约等于 ≥4 分。（第 6 页，附录 A2）

**社区获得 / 院内感染（ISARIC 的定义）**
ISARIC 规定：起病或首次阳性在入院 7 天以内的算社区获得，超过 7 天算院内感染。（第 6 页）

**前瞻队列**
从某个时间开始，按统一方案连续纳入病人并随访记录。ISARIC 4C 是前瞻队列，数据质量和一致性比回顾性病历好。（第 6 页）

**预设变量 / 可得率 ≥60%**
预设变量是在看数据之前就定好的候选预测因子，避免"看了结果再挑变量"。ISARIC 只纳入 ≥60% 病人能测到的变量，好处是模型能在大多数医院用，代价是 LDH、D-二聚体这类不常测的指标进不了模型。（第 6 页）

**决策编号（D68 等） / A 档决策**
D 开头的编号是研究者决策记录的编号，比如 D68 是"std_v3 两院同表同编码同取值、导出不定 t0"这条决定。A 档决策是必须由研究者拍板的事项，比如结局定义、纳排标准、口径。讲的时候不用念编号。（第 2 页）

**新旧版本重算对比**
口径改了以后，用 v0.3 和 v0.4 两套规则在两院数据上各算一遍，把人数、结局率的变化列出来，让大家看到改口径到底影响多大。（第 7、8 页，附录 A4）

## 五　模型与评价指标

**预测模型**
输入病人在 t0 时已知的信息，输出"之后发生结局的概率"。（第 4–6 页）

**AUROC / AUC / C 统计量**
三个名字在二分类问题里是同一个指标。含义：随机挑一个会发生结局的人和一个不会发生的人，模型给前者打分更高的概率。0.5 等于瞎猜，1 是完美；临床预测模型在 0.7–0.8 就算不错。（第 4–6 页）

**ROC 曲线**
横轴是假阳性率（没病被判成有病的比例），纵轴是真阳性率（有病被判出来的比例）。把判定阈值从高到低调，就画出一条曲线。曲线越往左上角鼓，模型越好；对角虚线代表瞎猜。曲线下面积就是 AUC。（第 4 页图 2A）

**95% 置信区间（95% CI）**
对估计值不确定程度的范围。比如 AUC 0.81 [0.79, 0.83]，意思是真实值大致落在 0.79 到 0.83 之间。区间越窄，估计越准，通常样本越大区间越窄。（第 4、6 页）

**正负比 / 类别不平衡**
阳性样本和阴性样本的数量比。Lauritsen 图里 1:15 是每 1 个阳性配 15 个阴性，1:750 则是阳性极少。正负比越悬殊，模型越难把阳性挑出来，而 AUROC 对这一点不敏感，所以要同时报正负比，或者看 AUPRC（精确率-召回率曲线下面积，它会随阳性比例变化）。（第 5 页）

**校准 / 整体校准（calibration-in-the-large） / 校准斜率**
AUC 只看排序对不对，校准看概率准不准：模型说 30% 风险的一群人，实际是否约有 30% 发生。
- 整体校准：平均预测风险和实际发生率差多少，0 最好。按常用定义，负值表示整体预测偏高，正值表示偏低；
- 校准斜率：1 最好。小于 1 说明预测太极端（高的说得太高、低的说得太低，常见于过拟合）；大于 1 说明预测太保守。

（第 4、6 页）

**外部验证 / 内部验证**
内部验证是在开发模型用的同一批数据里检验（比如交叉验证、bootstrap）；外部验证是拿到另一家医院、另一个时期的数据上检验，更能说明模型能不能推广。（第 4、6 页）

**内-外交叉验证（IECV） / 留一**
有多个中心或地区时，轮流把其中一个留出来做验证，其余的合起来开发模型，一圈下来每个中心都当过一次"外部"。ISARIC 是 8 个地区轮流留一，伦敦整区另外留到最后单独验证。我们计划按医院做同样的事，但两个中心只能轮两次，太少。（第 2、6、7 页）

**随机效应合并（meta 分析） / 森林图 / 异质性**
把各个地区的结果合成一个总的估计，同时承认各地本身就有差异，这种合并方法叫随机效应合并。森林图是展示方式：每行一个地区，方块是点估计（方块越大，样本越多），横线是 95% 置信区间，最下面的菱形是合并结果。各地区结果差别的大小叫异质性。（第 6 页）

**LightGBM**
一种常用的树模型（梯度提升决策树），处理表格数据效果好、速度快。CLIF 的死亡预测模型用的是它。（第 4 页备注）

**样本量估算 / pmsampsize**
开发预测模型前，先估算"至少要多少人、多少个结局事件"才不会严重过拟合。Riley 等 2020 年在 BMJ 提出的方法需要预先给出结局比例、候选预测参数的个数和预期的模型表现，pmsampsize 是实现这个方法的 R / Stata 软件包。论文里的例子：结局比例 5%、30 个候选参数，至少要 5,249 人、263 个事件。（第 7、8 页）

**过拟合**
模型把训练数据里的偶然噪声也学进去了，在训练数据上很准、换一批数据就不准。样本少、变量多时最容易发生，这也是第 8 页要先做样本量估算的原因。

**选择偏倚 / 左删失 / 右删失**
- 选择偏倚：纳入方式让研究对象不能代表目标人群。比如 CLIF 按"在 ICU"定义重症人群，而谁能进 ICU 还取决于床位和医生判断；
- 左删失：事情在观察开始之前就已经发生，没有被记录到。比如病人在急诊就已经很重了，进 ICU 才开始记录；
- 右删失：观察在结局发生前就结束了。比如病人转院或随访中断。我们记"未知"就是在处理这种情况。

（第 4 页）

## 六　论文、数据库与标准

**MIMIC-IV / BIDMC**
美国波士顿 Beth Israel Deaconess Medical Center（BIDMC）的公开重症数据库，约十年的数据，431,231 次住院、73,181 次 ICU 住段。研究者签协议后可以下载，是医学 AI 研究用得最多的数据库之一。前一代是 MIMIC-III。（第 3 页）

**MetaVision**
BIDMC ICU 用的床旁临床信息系统，MIMIC-IV 的 ICU 数据从这里来。原图里标为 metavision。（第 3 页）

**hosp / icu / note 模块**
MIMIC-IV 按来源把表分成模块：hosp 是全院的数据（入出院、检验、处方、诊断编码等），icu 是 ICU 床旁记录的数据（体征、出入量、操作等），note 是去标识后的出院小结和影像报告文本。（第 3 页）

**subject_id / hadm_id**
MIMIC-IV 的编号：subject_id 是患者号，hadm_id 是住院号。表与表之间靠这些编号和时间连起来。（第 3 页）

**去标识 / 日期平移**
去标识是把能认出个人的信息去掉。MIMIC-IV 把每个病人的日期整体平移到未来某个年份（同一个人内部的时间间隔不变），真实年份只给 3 年一档的范围，也不发布季节，所以用它做不了流感季分析。（第 3、7 页）

**charttime / storetime**
MIMIC-IV 的两种时间：charttime 是测量的时间，storetime 是床旁人员在系统里核实录入的时间。两者分开存，时间含义就很清楚。（第 3 页）

**schema / 格式转换**
schema 是数据库的表结构设计。格式转换是把各个来源系统的数据转成同一套表结构。（第 3 页）

**MIMIC Code Repository / 派生概念**
MIMIC 官方的共享代码库，"是否在通气""是否用升压药"这类要从多张表推出来的派生概念，用这里的共享代码算，大家结果一致。（第 3 页）

**CLIF / mCIDE / _category 与 _name**
CLIF（Common Longitudinal ICU data Format）是美国多家医院合作制定的 ICU 数据通用格式：8 个医疗系统、33 家医院、94,356 次 ICU 入住，23 张纵向表。mCIDE（minimum Common ICU Data Elements）是每张表里一组必须统一的最小公共元素，字段以 _category 结尾，取值限定在受控清单里；旁边配一个 _name 字段，保留医院原名。例如原名"UCM_LAB HEMOGLOBIN - AUTOMATED"统一成 Hemoglobin。（第 4、7 页）

**ER 图（实体关系图）**
画数据库表结构的图：每个框是一张表，框里每行是一个字段（字段名 + 数据类型），框之间的连线表示表和表怎么关联。连线末端的"鸡爪"表示"一对多"，比如一次住院对应多条体征记录。（第 4 页）

**数据类型：VARCHAR / DATETIME / INT / DOUBLE**
ER 图里字段的类型：VARCHAR 是文字，DATETIME 是日期时间，INT 是整数，DOUBLE 是带小数的数。（第 4 页图）

**ADT**
Admission-Discharge-Transfer（入院、出院、转科）记录，记录病人什么时候在哪个科室、哪个病房。CLIF 用 ADT 判断病人是否在 ICU。（第 4、7 页）

**FHIR**
HL7 组织制定的医疗数据交换国际标准，很多新的医院系统支持它。CLIF 没有接入 FHIR。（第 4 页）

**联邦分析 / 行级数据**
联邦分析是数据不出医院：把分析脚本和模型发到各家医院本地运行，只把汇总结果传回来。行级数据就是逐个病人、逐条记录的原始数据。CLIF 的行级数据不公开。（第 4、7 页）

**预印本 / medRxiv**
论文正式发表前先公开的版本，还没经过同行评审。medRxiv 是医学预印本平台。CLIF 先发预印本，2025 年发表在 Intensive Care Medicine。（第 4 页）

**ACES / ICLR**
ACES（Automatic Cohort Extraction System）是一个按配置文件自动抽取队列和任务标签的工具，2025 年发表于 ICLR（International Conference on Learning Representations，机器学习顶级会议）。（第 5、7 页）

**OMOP / OMOP-learn / DPM360**
OMOP 是国际上广泛使用的医疗数据通用数据模型；OMOP-learn 和 DPM360 是基于 OMOP 的建模工具，ACES 跟它们做过初步对比。（第 5 页备注）

**Lauritsen 2021 / EWS / SOFA / 脓毒症**
Lauritsen 等 2021 年发表在 npj Digital Medicine 的论文，用同一批普通病房住院数据比较不同的"预测实例取法"对脓毒症预测结果的影响。脓毒症是感染引起的危及生命的器官功能障碍；EWS 是早期预警评分（护士按体征打分）；SOFA 是序贯器官衰竭评分；原图里的 OR 指手术室。（第 5 页）

**ISARIC / 4C / CCP / NHS 地区**
ISARIC 是国际严重急性呼吸道和新发感染联盟；4C 是英国新冠临床特征联盟；CCP 是他们的临床特征研究方案（英国版叫 CCP-UK），规定了标准病例报告表和随访时点。ISARIC 4C Deterioration 是他们开发的新冠住院成人恶化预测模型。NHS 地区是英国国民医疗服务体系的行政区，验证就是按这些地区轮流留出的。（第 6 页，附录 A2）

**4CE / N3C（附录 A2"文献呼应"列）**
- 4CE：国际多中心新冠电子病历联盟，各站点在本地跑脚本、只上交聚合表，报告了检验单位、ICU 认定在各院间最容易出错；
- N3C：美国国家新冠队列，把检测阴性的人也纳入，并把检测证据分成确诊阳性、确诊阴性、疑似等几层。

附录表里"06 N3C""07 4CE""15 WHO 量表""18 ACES""23 ISARIC CCP"前面的数字，是数据集构建论文库里的论文编号（见 `paper/数据集构建调研_20261025/00_论文身份核对.md`）。其中 23 是 ISARIC CCP-UK 的队列论文（Docherty 等，BMJ 2020），和第 6 页的 4C 恶化模型（Gupta 等，2021）不是同一篇。（附录 A2）
