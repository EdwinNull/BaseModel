## 医院数据对齐

显然患者层次的对齐是不现实的，因此目前考虑的将数据集间**相同的临床变量**放入共同编码、单位和时间表示，最后对齐的表结构如下：

| 表                      | 粒度与功能                                 | 关键信息                                                     |
| :---------------------- | :----------------------------------------- | :----------------------------------------------------------- |
| encounters              | 每次就诊一行；人口学、锚点、来源、流感证据 | source、患者/就诊化名、anchor_rule                           |
| events                  | 每条体征、检验或症状观测一行               | raw_name / raw_value、unit / unit_cdm、time_raw、time_precision、origin |
| treatments              | 就诊 × 治疗；使用状态与起止时间            | time_source、围术期插管、否定与首次提及依据                  |
| complications           | 就诊 × 并发症；人工/诊断依据               | POA、判定依据、时间来源                                      |
| complications_lab_rules | 检验规则候选标签                           | 候选阈值、可评估性；与临床判定分开                           |
| imaging / notes         | 影像报告、清洗后的文书                     | 检查类型、时间、来源；直接标识符去除                         |
| crf_view + 字典         | 每次住院一行的同构宽表；变量和列定义       | adm、idx、lab_、SEV_、cmp_ 区分派生口径                      |

## 公开数据集对齐

现在MIMIC-III正在下载（速度很慢），先考虑对MIMIC-IV+MIMIC-IV-ED、eICU、MC-MED进行对齐，同时试图使公开数据集与目前的私有数据集也进行对齐。

### MIMIC-IV+ED

对于此数据集，适配的程度比较高，目前已有**425087 encounters、2472841 体征事件（events）、无treatments、36887 complications**，但是MIMIC-IV-CXR中的**影像报告还没有抽取**

### eICU和MC-MED

这几个数据集问题比较类似，变量上可以部分对齐，但是流感相关症状不如MIMIC-IV多，属于ICU型数据集，而MIMIC-IV有脓毒症等与流感相关症状，我认为如果要进行公开数据集和私有数据集的对齐，可能更多地需要MIMIC。

### 公开与私有的分析

就目前的分析而言，能够比较好的建立映射的主要是**心率、血红蛋白、血小板**等有统一单位或容易换算的指标，而对于有些指标，公开数据集与医院**记录方式、记录标准、采用指标**存在不一致，例如对于血压，医院普遍采用文本记录的收缩/舒张压，但MIMIC则还要分有创无创记录；以及还有些指标医院有而MIMIC没有，MIMIC有医院没有。

综上，医院和公开数据集如果要对齐，大表结构可以保持不变，缺失就保留为null；变量与单位能换算就换算，而**时间尺度**也是一个比较麻烦的地方，医院基本上没有看到一名患者同一天的多次结果，化验主要是隔几天化验一次，因此时间尺度为天级，而公开数据集在这方面会更细，往往都是小时级的。

因此，**现在还需要更近一步的对数据集分析，对于难以对齐的变量，可能要先考虑不使用或者作为泛化验证的一部分？**，时间尺度上，day级应该比较好，采用hour级的话医院数据集只能当作稀疏的时序验证集。

## 目前的实验设置

目前实验做的是对**事件进行预测**，包括**IMV（有创机械通气，即插管）、ICU（进入ICU治疗）、ECMO（体外设备辅助交换气体，即人工肺）、死亡**。

对于输入，目前对医院数据集和公开数据集进行分开实验，因为暂时还没有对二者进行对齐。医院组主要输入年龄、性别加上15项临床测量；而公开数据组的输入借鉴先前的实验，输入t-18，t-12、t-6，t四个时间点的序列，每个序列包括七项生命体征和体征的5项统计特征（last/max/min/mean/count）

而对于基础模型选择，目前先使用的如下：

| 模型      | 当前实现                                                     | 训练的部分                                       |
| :-------- | :----------------------------------------------------------- | :----------------------------------------------- |
| URB-65    | 尿素>7、呼吸≥30、低血压、年龄≥65各1分；缺失不加分            | 只在GAM拟合分数→概率的一维LR                     |
| LR        | 中位数插补→标准化→L2逻辑回归；C∈0.01/0.03/0.1/0.3/1          | 训练源内部交叉验证按log loss选C                  |
| LightGBM  | 浅树：max_depth=2、num_leaves=4、learning_rate=.05；树数25/50/100/200 | 训练源内部交叉验证选树数                         |
| TabPFN v2 | 本地预训练表格模型；n_estimators=8                           | 使用训练表格和标签作为上下文；没有本任务梯度微调 |
| MIRA R0b  | 每变量序列→冻结MIRA→末观测768维；15通道拼11,520维→标准化→PCA16→LR | 编码器冻结；训练PCA与LR，C在训练内选             |
| Qwen3-8B  | 结构化数值→固定中文提示→首词元logit(是)−logit(否)→一维LR概率 | Qwen权重冻结，只训练概率映射                     |
