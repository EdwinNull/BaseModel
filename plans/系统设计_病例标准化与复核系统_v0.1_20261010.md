## 1 目标与范围

### 1.1 要解决的问题

1. **格式不一样。** 两院的数据来源和格式完全不同：GAM 是多张表的 EHR 导出加自由文本病历；GD 是一人占多行的 CRF 宽表。新导出的门急诊数据、前瞻录入又是两种新格式。现在的对齐代码是为两家医院一次性写的，接新来源要改代码。
2. **时间和证据最关键，但最难拿到。** 转重研究需要"首次转重时间"和"转重前的观测"。现有数据中，时间精度参差（分钟、日期、病历书写时间），文本里还有否定、假设、计划、拒绝等语境。
3. **自动抽取需要人工兜底。** 规则会漏抽（例如"SpO2 降至75%"），也会遇到语义不清（例如 GD 的"呼吸机"与无创、有创三列不一致）。需要一个让医生高效复核、并保留判定痕迹的地方。
4. **口径还在变。** 发热阈值、分级判据、窗口都属于 A 档，要等研究者和临床拍板。系统要能在不改代码的情况下更换口径并重算，同时保留每个版本。
5. **前瞻数据要一开始就记对。** 这个流感季如果前瞻收集，录入时就要采集到发病日期、带时间的体征和吸氧状态，不再事后从病历里抽。

### 1.2 范围

| v0（本次演示） | v1 及以后 |
|---|---|
| GD CRF、GAM EHR 两个源适配器，以及一个"门急诊导出"模板适配器 | 医院在线上传；更多中心的适配器 |
| 流水线 S1–S11（§5），在虚构数据上真实运行 | 服务器真实数据运行与医生试用 |
| 规则抽取，加本地 LLM 第二抽取（演示时用预置结果） | 服务器上接入 Qwen3 在线推理；用医生复核结果改进抽取 |
| 指南分级时间线（规则集 YAML） | 规则集在网页上编辑并比较差异 |
| 复核：按条目分级（双盲 + 共识，或单人 + 抽样） | 复核任务分派、提醒、工作量统计 |
| 前瞻录入：入组、多次测量、第 7/14/28 天随访（演示） | 正式部署（院内 / VPN / Excel 模板，待定）、数据锁定与稽查 |
| 最小认证与审计（演示账号、关键操作留痕） | 正式用户管理、单点登录 |

### 1.4 设计原则

1. **原值不覆盖。** 数据分三层（§4.1）：原始层只读；自动层是每次运行的产物；复核层是叠加在自动层之上的覆盖值。任何"有效值"都能回溯到原始单元格或文书片段。
2. **口径参数化。** 凡是 A 档的东西（分级判据、阈值、窗口、病程分类）都写进带版本号的规则集，不写死在代码里。改口径就是新建一个规则集版本，再重算。
3. **证据优先。** 每个抽取值都带证据（文书 ID 和字符区间，或原始表的行列）、方法（规则、LLM、表单、复核）、时间含义和精度。
4. **隐私优先。**
   - 只用本地模型，医院数据不发给任何在线 LLM / API；
   - 复核员只看完成判定所需的化名片段；
   - 观察者只看聚合量，1–9 显示为"<10"；
   - 查看文书、提交判定、导出都要审计留痕。
5. **用虚构数据开发。** 开发和演示全部使用生成器产生的虚构数据；真实数据只在服务器上运行。
6. **可复现。** 每次运行都记录输入哈希、代码版本、规则集版本和复核快照；冻结的数据集有自己的哈希。

## 2 用户与角色

| 角色 | 典型使用者 | 能做什么 | 看不到什么 |
|---|---|---|---|
| 管理员 / 研究者 `admin` | 你、合作开发同学 | 导入、映射、运行流水线、管理规则集、建复核批次、冻结和导出、查看审计 | — |
| 复核员 `reviewer` | 受邀临床医生 | 只做分给自己的复核条目；查看判定需要的化名证据片段 | 规则或模型的结论（盲法）；其他复核员的判定（共识前）；病例列表全貌 |

## 4 数据设计

### 4.1 三层数据

```
原始层（只读）              自动层（每次运行一个版本）            复核层（覆盖值，带来源）
raw/<batch>/文件 + sha256 → runs/<run_id>/CDM + 抽取 + 分级 → overrides（判定 / 共识）
                                     │                                  │
                                     └──────────── 有效值 = 覆盖值 ?? 自动值 ┘
```

- **改口径**：新的规则集版本，生成新的 `run_id`，旧版本保留；复核层按"条目指纹"（就诊 + 字段 + 证据）尽量迁移到新运行上，迁移不了的重新进入复核队列。
- **冻结**：快照 = 运行版本 + 规则集版本 + 复核快照时间；整体计算哈希，写进数据使用台账。

### 4.2 统一数据模型

沿用服务器 CDM v3.1 的 8 张表（encounters、events、treatments、complications、complications_lab_rules、imaging、notes、crf_view），以及 outcome_components。所有编码不变（VS/LAB/SYM/COM/TRT/OUT/CLP/EXT_）。新增或扩展的部分如下：

| 表 / 列 | 内容 | 用途 |
|---|---|---|
| `encounters` 新增 `onset_time / onset_precision / onset_source / days_onset_to_visit` | 起病时间；来源取值：主诉解析、现病史解析、前瞻录入、复核 | 发病时钟 |
| `events` 新增 `o2_status / o2_flow` | 测量时的吸氧状态与流量（文本抽取或录入） | 判断"吸空气 SpO2≤93%" |
| `extractions`（新表） | 每个抽取值一行：字段、值、三态或语境、时间、时间含义、精度、方法、规则 ID 或模型、置信度、证据区间 | 证据追溯；生成复核条目 |
| `severity_events`（新表） | 就诊、时间、精度、级别、判据、证据引用、规则集版本 | 分级时间线 |
| `severity_summary`（新表） | 基线级别、最高级别、首次达到重型 / 危重型的时间、病程类型、标记 | 病例页的分级带；O1–O3 / D0 计数 |

新增编码（录入和抽取共用）：

| 编码 | 含义 |
|---|---|
| `O2_STATUS` | 吸氧状态：空气 / 鼻导管 / 面罩 / 高流量 / 无创 / 有创 |
| `O2_FLOW` | 氧流量（L/min） |
| `TRT011` | 氧疗 |
| `TRT012` | 升压药 |
| `SYM008` | 胸痛 |
| `SYM009` | 喘息 |
| `SYM010` | 厌食 |
| `SYM011` | 精神状态改变 |
| `COM011` | 高血压 |
| `COM012` | 肝病 |
| `COM013` | 神经肌肉病 |
| `COM014` | 长期卧床 / 失能 |

这些编码是候选，最终需要研究者确认。

### 4.4 编号规则

- **回顾性**：沿用现有化名（患者、就诊随机顺序号），对照表单独加密存放，跨版本稳定。演示数据统一用 `DEMO-` 前缀。
- **前瞻性**：研究编号 = 中心码 + 流水号（例如 `S01-0012`）。系统里**不存**病案号、姓名、电话；研究编号和病案号的对照表由医院保管（入组登记表）。

## 5 流水线设计

### 5.1 步骤

| 步骤 | 输入 → 输出 | 复用代码 | 失败即停的条件 |
|---|---|---|---|
| S1 导入 | 文件 → `raw/` + `batches` | `gd_crf.load` 的"全部按文字读入"、表头校验 | 表头签名不匹配；文件无法读取 |
| S2 识别 | 原始表 → 就诊分组、再入院、门诊与住院挂接 | `gd_crf.build`（续行分组）、`gam_ehr`（挂接） | 分组数与声明总数不符时只告警 |
| S3 化名 | 标识符 → 化名；文本清洗 | `deid.py`（PseudonymRegistry、scrub_text） | 隐私审计命中不为 0 |
| S4 映射 | 原字段 → 统一编码、单位换算、删失值、合理范围 | `common.py`（apply_plausibility 等）+ `mapping_dict` | 必需字段缺映射 |
| S5 抽取 | 文书 → `extractions` | `textrules.py`（三态、否定、假设、围术期）、主诉时长解析（`guideline_feasibility.py`）、LLM 第二抽取 | — |
| S6 时间 | 时间 → time_kind、精度、锚点、年份修正、起病时钟 | `common.fix_year_typos`、`time_precision` | — |
| S7 分级 | CDM + 抽取 + 规则集 → `severity_events / summary` | 新写（§5.4） | 规则集校验失败 |
| S8 标记 | 自动层 → `review_items` | `review/gam_outcomes.py` 的候选召回思路 | — |
| S9 复核回流 | 判定、共识 → `overrides` | `review/summarize_gam_adjudication.py` 的一致性统计 | — |
| S10 质控 | 各层 → 质控指标（聚合） | `qc.py`、`guideline_feasibility.py`、`scan_code_identifiers.py` | — |
| S11 冻结导出 | 有效值 → `snapshots/` | — | 未完成的 A 类条目超过阈值时只告警 |

每一步都要求幂等：同样的输入、同样的版本，产物哈希一致（现有对齐代码已经做到"28 个产物完全一致"）。

### 5.2 源适配器接口

```python
class SourceAdapter(Protocol):
    """一种数据来源一个适配器。新增来源 = 新增适配器 + 映射字典，不改流水线。"""
    source_type: str                                         # "GD_CRF" / "GAM_EHR" / "ED_EXPORT" / "MDS"

    def detect(self, files: list[Path]) -> DetectResult: ...          # 表头签名匹配度（0–1）与依据
    def validate(self, files: list[Path]) -> list[Issue]: ...         # 表头重复、必需列、编码异常等
    def mapping_preview(self, files: list[Path], mapping: MappingDict) -> list[FieldPreview]: ...
    def build(self, files: list[Path], registry: PseudonymRegistry,
              mapping: MappingDict) -> CdmTables: ...                  # 执行 S2–S6，返回 CDM 各表
```

`FieldPreview` 包含：原字段、统一编码、单位（原 → 统一）、时间列、典型精度、非空率、映射状态（ok / 待确认），以及**虚构**示例值。真实数据的预览只给统计量，不给逐行值。

### 5.3 抽取结果与证据格式

```python
@dataclass
class EvidenceSpan:
    note_id: str            # 文书化名 ID；结构化来源用 "table:列名:行号"
    start: int              # 字符偏移（清洗后文本）
    end: int

@dataclass
class Extraction:
    encounter_id: str
    field: str              # 统一编码，如 TRT007、VS006、O2_STATUS、ONSET_DAYS
    value: float | str | None
    state: Literal["pos", "neg", "none", "hypothetical", "plan", "refused", "periop"]
    time: datetime | None
    time_kind: str          # measured / note_written / date_only / proxy / form
    precision: Literal["minute", "day", "note", "unknown"]
    method: Literal["rule", "llm", "form", "review"]
    rule_id: str | None     # 例如 "R-IMV-03"
    model: str | None       # 例如 "qwen3-14b@prompt_v1"
    confidence: float | None
    evidence: list[EvidenceSpan]
```

- 规则抽取与 LLM 抽取各占一行。两者不一致时由 S8 生成复核条目，不在流水线里"投票"决定。
- 病例页高亮证据用的就是 `evidence` 的字符区间。

### 5.4 指南分级：规则集与算法

**规则集示例**（候选，未经确认；凡标"A档"的参数都要研究者和临床拍板）：

```yaml
ruleset: guideline2025_v0          # 规则集版本；改任何参数都要换版本号
source_doc: 流行性感冒诊疗方案（2025年版）七、临床分型（p6–7）
params:
  fever_threshold_c: 37.3          # A档：指南未给阈值
  baseline_window_h: [-24, 24]     # A档：t0 前后多久算"起点状态"
  same_day_policy: ambiguous       # A档：只有日期的事件落在 t0 当天时，记为 baseline 或 ambiguous
levels:
  moderate:                        # 中型：只记"有中型证据"，没有证据 ≠ 轻型
    any_of:
      - {id: PNEU_IMG, extraction: IMG_PNEUMONIA, state: pos}
      - {id: FEVER_GT3D, derived: fever_duration_days, op: ">", value: 3}   # 依赖起病时钟
      - {id: DYSPNEA, event: SYM007, value: 1}
  severe:
    any_of:
      - {id: RR30, event: VS003, op: ">=", value: 30, kind: physiologic}
      - {id: SPO2_93_RA, event: VS006, op: "<=", value: 93, require: {o2_status: 空气}, kind: physiologic}
      - {id: PF300, event: EXT_PF, op: "<=", value: 300, kind: physiologic}
      - {id: O2_NEW, treatment: TRT011, kind: treatment}          # A档：新开始或升级氧疗是否算
      - {id: NIV, component: NIV, kind: treatment}
      - {id: RF, component: [RESPIRATORY_FAILURE_I, RESPIRATORY_FAILURE_II], kind: diagnosis}
  critical:
    any_of:
      - {id: IMV, component: IMV, exclude: IMV_PERIOP}
      - {id: ECMO, component: ECMO}
      - {id: SHOCK, any: [{complication: CLP013}, {treatment: TRT012}]}
      - {id: ICU_ORGAN, all_of: [{component: ICU}, {complication_any: [CLP005, CLP008, CLP014, CLP016, CLP018, CLP020]}]}
death: {component: DEATH}
report_split: [physiologic, treatment, diagnosis]   # 生理类与治疗/诊断类分开派生、分开报告（会议后计划 §2.2 第 4 条）
```

**算法**（S7）：

1. 对每条判据，从 CDM 和有效抽取中找阳性证据，得到 `(时间, 精度, 级别, 判据, 证据)`。没有时间的记 `time=None`。
2. 写入 `severity_events`。治疗类判据在 [开始, 结束] 区间内持续生效，生理类只在测量时刻生效。
3. 汇总 `severity_summary`：
   - 基线级别：t0 窗口内的最高级别；
   - 最高级别；
   - 首次达到重型 / 危重型的时间与精度；
   - 病程类型：起点已达到 / 观察期内首次达到 / 达到后好转出院 / 始终未达到（确定阴性或随访不足）；
   - 标记：例如"只有日期的事件落在 t0 当天""有时间未知的阳性证据"。
4. 没有任何证据时，级别记为"未见中型及以上证据"，不记为"轻型"。

### 5.5 待复核标记规则（S8）

| 代码 | 触发条件 | 层级 | 优先级 |
|---|---|---|---|
| R1 | 决定结局的事件（有创、无创、ICU、休克、ECMO）为阳性，但没有时间 | A | 高 |
| R2 | 决定结局的字段冲突：例如 GD 的"呼吸机"与无创/有创不一致；规则与 LLM 结论不一致 | A | 高 |
| R3 | 决定结局的治疗处在假设、计划、拒绝、围术期语境，或否定判断置信度低 | A | 高 |
| R4 | 起病时间缺失、互相矛盾，或晚于就诊 | B | 中 |
| R5 | SpO2≤93% 但吸氧状态未知 | B | 中 |
| R6 | 不合理值、单位存疑、年份修正后仍不在窗内 | B | 低 |
| R7 | 从自动接受的条目中随机抽样（估计自动抽取的准确率） | B | 低 |

层级 A：两人独立盲裁，不一致时开共识会。层级 B：一人复核，另按批次设定的比例（默认 15%，可设 10–20%）抽样由第二人重复。层级策略存在 `review_batches.tier_policy` 里，可以按批次改。

### 5.6 运行与重跑

- 一次运行 = 一组批次 + 一个映射字典版本 + 一个规则集版本 + 代码版本。运行记录写进 `runs`，日志写到 `logs/<日期>/`（服务器上沿用 `W/logs/YYYY-MM-DD/` 规范）。
- 只改规则集时，从 S7 开始重跑，S1–S6 的产物直接复用。

## 6 复核设计

### 6.1 批次与模式

管理员从某次运行创建复核批次，选择范围（来源、条目类型、优先级）和层级策略。系统自动分派：A 类给两位复核员；B 类给一位复核员，再按比例抽样给第二位。

### 6.2 盲法：复核员看什么

| 显示 | 不显示 |
|---|---|
| 问题（例如"该次住院是否使用有创机械通气？若是，首次时间？"） | 规则 / LLM 的结论及置信度 |
| 证据片段：化名文书片段（关键词高亮，前后各 200 字以内）、文书类型和时间、相关的结构化观测（例如血气） | 另一位复核员的判定（共识前） |
| 判定所需的最少背景：年龄段、来源、t0 | 姓名、病案号、原始 ID（这些本来就不在系统里） |

查看证据时记一条审计（谁、哪一条、什么时间），不记正文。

### 6.3 判定格式

- **结论**：是 / 否 / 不确定（证据不足时选"不确定"，不要猜）。
- **值或时间**：需要时填写值、时间和精度（分钟 / 日 / 未知）。
- **理由**：可选，文字说明。
- 提交后锁定；要修改就新建一条记录，并说明原因。

### 6.4 共识

共识页把两人的判定和证据并排显示。参会者确定最终结论、值和时间，并写明理由。仍定不下来的记"不确定"，后续敏感性分析时分别按阳性和阴性处理（沿用 10-01 计划的做法）。

### 6.5 一致性统计

按条目类型计算：两人一致率、κ；稀少条目另报 PABAK。B 类抽样重复用来估计单人复核的可靠度。这些统计进入质控看板。

### 6.6 回流

- 判定和共识写入 `overrides`，有效值随之更新；自动值保留不动。
- 定期汇总"规则 / LLM 与复核结论不一致"的条目，用来改进规则。规则改版后重跑 S5 起的步骤，并登记新版本。

## 7 前瞻录入（最小数据集，MDS）

### 7.1 原则

- 只存研究编号；对照表留在医院。
- 每个时间字段都带精度（具体时间 / 日 / 半日 / 不详）。
- SpO2 必须同时录入吸氧状态，否则不能提交。
- 症状一律三态：有 / 无 / 未评估。
- 字段编码尽量复用 CDM 编码，录入的数据直接进入 CDM，`time_kind=form`。

### 7.2 MDS v0 字段草案（候选，需临床确认，属 A 档）

| 模块 | 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|---|
| 就诊 | 中心、就诊类型（发热门诊 / 急诊 / 普通门诊 / 住院）、就诊时间 + 精度 | 枚举 / 时间 | 是 | — |
| 人口学 | 年龄、性别、身高、体重（自动算 BMI） | 数值 / 枚举 | 年龄、性别必填 | 年龄 0–120 |
| 流感检测 | 方法（抗原 / 核酸）、采样时间、结果、型别 | 枚举 / 时间 | 是 | 采样早于发病 1 天以上时只提示、不阻止 |
| 发病 | 首发症状、首发症状时间 + 精度、首次发热时间 + 精度、入组前最高体温 | 枚举 / 时间 / 数值 | 首发症状时间必填 | 发病时间 ≤ 就诊时间 |
| 测量（可重复） | 测量时间、T、HR、RR、SBP/DBP、SpO2、吸氧状态、氧流量、意识 | 数值 / 枚举 | 有 SpO2 时吸氧状态必填 | 合理范围沿用 CDM 字典 |

| 疫苗 | 本季是否接种 | 是 / 否 / 不详 | — | — |
| 影像（如有） | 检查时间、是否肺炎 | 时间 / 三态 | — | — |
| 抗病毒 | 药物、开始时间 + 精度 | 枚举 / 时间 | — | 开始时间 ≥ 发病时间 |
| 去向 | 离院 / 留观 / 收住院 / 转院 / 死亡，时间 | 枚举 / 时间 | 是 | — |
| 随访（第 7/14/28 天） | 是否住院（日期、本院 / 外院）、氧疗 / 高流量 / 无创 / 有创（开始日期）、ICU（日期）、休克或升压药、死亡（日期）、退热日期、随访方式、是否失访 | 三态 / 时间 | 随访方式必填 | 失访时其余字段记"未知" |

### 7.4 随访

入组提交后，系统按就诊日期生成第 7、14、28 天的随访任务。录入员的待办里显示到期和逾期的任务；失访要明确标记，不能留空。

### 7.5 三种部署方式共用一套表单定义

- **院内部署**：同一套代码，只启用录入模块。课题组只拿化名后的导出。
- **课题组服务器 + VPN**：启用录入模块，按中心隔离数据。上线前要做安全评估。
- **Excel 模板**：由表单定义自动生成模板，列名是字段编码，第二行是中文说明，并带数据有效性设置。录完后用 `MDS` 适配器导入，走同一套校验。

三种方式最终都进入同样的表和编码，后续分析不受影响。

## 10 安全、隐私与合规

| 方面 | v0 做法 |
|---|---|
| 数据边界 | 开发和演示只用虚构数据；代码仓库禁止提交任何真实数据（§12 的 `.gitignore` + 提交前标识符扫描）；真实数据只在服务器 `W` 内 |
| 网络 | 只监听 `127.0.0.1`，通过 SSH 隧道访问；不开公网端口；临床医生的远程访问方式（VPN 或院内）待定 |
| 认证与授权 | 账号密码（argon2）+ httpOnly Cookie；每个路由都做角色检查；复核员只能访问分给自己的条目 |
| 最小可见 | 复核员只看片段；观察者只看聚合；质控接口在后端做小格抑制；真实数据的映射预览不给逐行值 |
| 审计 | 登录、查看文书 / 证据、提交判定、共识、导出、改规则集都要留痕；审计只记对象 ID，不记正文 |
| 模型 | 只用服务器本地 LLM；禁止调用任何在线 API；提示词与模型版本写进抽取记录 |
| 前瞻 | 系统里只有研究编号；对照表在医院 |
| 合规（待负责人确认） | 伦理批件与数据使用协议是否覆盖门急诊数据、前瞻收集和网页处理方式；医生账号的开通与注销流程 |

## 11 虚构数据与演示脚本

### 11.1 虚构数据生成器（`flucase/synth/`）

- **输出**：
  - `虚构_GD_CRF_样例.xlsx`：Sheet1 + 合并症表，一人多行，表头与真实 CRF 同构；
  - `虚构_GAM_EHR_样例.xlsx`：住院诊断、医嘱、检验、检查、住院病历；
  - `虚构_急诊导出_样例.xlsx`；
  - 前瞻录入的 JSON 样例。
- **规模**：默认每个来源 60–100 次就诊，固定随机种子。
- **病历文本**：由模板生成，所有姓名、编号都是虚构的（例如"示例甲"、`0099001`）。
- **有意埋入的问题**（让演示能展示处理过程，也作为测试用例）：

| 问题 | 来源 | 期望的处理 |
|---|---|---|
| 一人多行，续行病案号为空或被下拉递增 | GD | 按"年龄非空的行开始一位新患者"分组 |
| 年份笔误（2023 写成 2024 等） | GD | 修正后打 `year+1` 标记 |
| TRT009 编码重复 | GD | 表头校验告警，并按字典改编码 |
| "<0.05"这类删失值 | 两院 | 记 0.05，另加"小于"标记 |
| D-二聚体单位不明 | GD | 映射状态"待确认" |
| "呼吸机"与无创、有创不一致 | GD | 生成 R2 复核条目 |
| "必要时气管插管""家属拒绝插管""全麻下插管" | GAM | 假设 / 拒绝 / 围术期语境，不计入 |
| "无明显诱因出现发热"（伪否定） | GAM | 发热仍记为阳性 |
| "SpO2 降至75%"（规则漏抽） | GAM | LLM 补抽，生成 R2 |
| 有阳性但无时间的 ICU 记录 | GD | 生成 R1 |
| 主诉"反复咳嗽20年，加重伴发热3天" | GAM | 起病时钟取 3 天 |
| 只有 SpO2、没有吸氧状态 | 两院 | 生成 R5 |

### 11.2 演示脚本（约 10 分钟）

1. **登录与总览（管理员）**：两个演示批次、待复核数、隐私审计 0 命中。
2. **导入**：上传虚构 GD 样例 → 自动识别为 GD_CRF → 表头校验发现 TRT009 重复并说明处理方式 → 映射预览中 D-二聚体单位"待确认" → 运行，S1–S11 依次完成，生成 A/B 类复核条目。
3. **病例时间线**：打开虚构 GAM 病例。
   - 发病时钟从主诉"加重伴发热3天"推出；
   - "必要时气管插管"显示为"假设，不计入"；
   - "SpO2 降至75%"由 LLM 补抽（预置结果），进入复核；
   - 分级带显示：中型 → 重型（无创）→ 危重型（有创）。
4. **复核**：切换到 reviewer1，判定"有创通气及首次时间"；再切换到 reviewer2 给出不同的时间 → 管理员打开共识页，定稿 → 回到时间线，显示"已复核"，分级的时间随之更新。
5. **质控看板**：覆盖率热图、时间精度构成、A 类一致性、可行性计数（"<10"抑制）。
6. **前瞻录入**：切换到 entry1 → 新建研究编号 → 填发病和测量（故意漏选吸氧状态，系统阻止提交）→ 提交 → 待办里出现第 7 天随访 → 下载 Excel 模板。
7. **收尾**：冻结快照，显示哈希，并写入数据使用台账。
