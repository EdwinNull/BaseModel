## 1 现状

flucase 现在认得的格式有 GD式 CRF 宽表、GAM式住院 / 门诊、门急诊导出模板、统一格式 Excel，以及成套的 GD式、GAM式原始导出；认不出的文件走格式向导（通用导入）。系统本身按中心代码区分数据，加一个中心只需在服务器上 `admin create-site`，分级、复核、std_v3 导出与验收都不按中心写死（只有新库的默认中心列表写着 GD、GAM）。所以 AH 要做多少开发，取决于 AH 的导出长什么样，这一步只有扫描能回答。

文件夹名“呼吸内二科数据统计”提示它可能是科室自己整理的统计表（一次住院一行、一项一列，类似 GD式 CRF），也可能是信息科导出的病历系统原始数据。两种情况后面的路线差别很大（§2 第 3 步），扫描脚本两种都照顾到了。

## 3 扫描脚本

研究者在 BaseModel 根目录运行（给的路径可以是文件夹、单个文件或压缩包；Windows 上 Python 路径换成 `flucase/backend/.venv/Scripts/python.exe`）：

```bash
flucase/backend/.venv/bin/python scripts/flucase_raw_scan/ah_raw_probe.py "data/AH-呼吸内二科数据统计" --out tmp/ah_scan_20261111/ah_raw_probe.md
```

报告的五节对应上面第 2、3 步要回答的问题：① flucase 现有每个格式认不认得（状态、得分、差异）；② 每张表的角色猜测、表头、行数、编号列、时间列（精度、年月范围、就诊类时间按月计数）、每列的填充 / 类型 / 数值分布 / 写法形状、目录列的名称目录、长表的项目目录、长文字列的小节标题与关键词命中；③ 统一数据项覆盖：按表头、按名称目录、按文字关键词三种来源，数每个数据项（基本信息、症状、基础病、体征、检验、流感病原学、治疗、结局、并发症、影像、中医、老年评估）能在多少个编号上取到；④ 诊断编码按 ICD-10 前缀数流感、基础病、并发症；⑤ 编号重合（加盐哈希）。文末附通用结构扫描（文件类型、遮蔽后的目录形状）。

报告不含单元格原文。例外只有目录类名称（检验项目、医嘱名称等）：在 ≥10 个编号里出现、没有长数字、没有人称词、不像日期，名称里像人名的 2–3 个字再遮蔽（10-31 出过病历类型带医生姓名、低频医嘱是手写原文的事，所以门槛比 GAM 扫描的 5 高）。低基数列的取值严格遮蔽，主诉、诊断、备注一类的文字列即使取值少也只给种数。按编号分类的计数 1–4 写成“<5”；文件名默认遮蔽；压缩包解到它旁边的临时文件夹，扫完删掉。

自测（虚构数据，11-11）：虚构的科室统计表（宽表 + 检验长表 + 病程记录，故意在备注和正文里写姓名、电话，并让一个虚构医生名作为记录类型出现在全部住院里）分别以文件夹、压缩包、单个文件给，另跑 GD式原始导出、GD式 CRF、GAM 虚构样例，共 6 种输入都跑通；用单独的检查脚本把虚构数据里姓名、编号、电话、正文片段类的单元格逐个到报告里找，命中的只有目录名称（“日常病程记录”“普通门诊”“胸部CT平扫”）、ICD 前缀和文件名里的词表词，没有姓名、号码和正文。GD式 CRF、GAM 住院 / 门诊、GD式原始导出都被认成 exact。速度：300 次住院的虚构 GD 原始导出（7.5 MB）27 秒。
