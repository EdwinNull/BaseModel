## 0 准备（约 15 分钟）

在 Mac 上测试看下面的 0.1 节。Windows 在 PowerShell 里（路径按你的电脑改）：

```powershell
git -C G:\BaseModel pull
git -C G:\BaseModel\flucase pull
cd G:\BaseModel\flucase\web; npm run build
cd G:\BaseModel\flucase\backend
.venv\Scripts\python -m pip install -e ".[dev]" -c constraints.txt
```

用一个**新的空数据目录**（放在 BaseModel 的 `data/` 下，不进仓库），设置正式模式：

```powershell
$env:FLUCASE_ENV = "prod"
$env:FLUCASE_DATA_DIR = "G:\BaseModel\data\flucase_test1"
$env:FLUCASE_SECRET_KEY = (.venv\Scripts\python -c "import secrets; print(secrets.token_hex(32))")
$env:FLUCASE_SEED_DEMO = "0"; $env:FLUCASE_LLM = "off"; $env:FLUCASE_COOKIE_SECURE = "0"
$env:FLUCASE_SITE = "研究者设备（第一轮测试）"
```

建账号（密码交互输入两次，至少 8 位），然后自检、启动：

```powershell
.venv\Scripts\python -m flucase.admin create-user researcher --role admin --display-name 研究者
.venv\Scripts\python -m flucase.admin create-user test_gd --role importer --site GD --display-name "测试医生（GD）"
.venv\Scripts\python -m flucase.admin create-user test_gam --role importer --site GAM --display-name "测试医生（GAM）"
.venv\Scripts\python -m flucase.admin create-user test_rev1 --role reviewer --display-name "测试复核员一"
.venv\Scripts\python -m flucase.admin create-user test_rev2 --role reviewer --display-name "测试复核员二"
.venv\Scripts\python -m flucase.admin check
.venv\Scripts\python -m uvicorn flucase.app:create_app --factory --host 127.0.0.1 --port 8000
```

`check` 的结果里除了"FLUCASE_COOKIE_SECURE=0"一条提醒（本机 http 访问，正常），不应有"✗"。浏览器打开 `http://127.0.0.1:8000`。

### 0.1 在 Mac 上（第一次）

需要：Python ≥3.10（`python3 --version`；系统自带的 3.9 不够时 `brew install python@3.12`，下面的 `python3` 换成 `python3.12`）、Node（`brew install node`，只用来构建前端）、能拉 GitHub 的 SSH 密钥。

1. 两个仓库都要拉：`flucase` 是**单独的仓库**，在 BaseModel 里被 gitignore，拉 BaseModel 不会带下来。都用 `main`：

   ```bash
   cd ~/BaseModel && git checkout main && git pull --ff-only
   [ -d flucase ] || git clone git@github.com:EdwinNull/flucase.git flucase
   cd flucase && git checkout main && git pull --ff-only
   ```

2. 真实原始 Excel 也不在 git 里：把三个文件从另一台电脑拷到 Mac 的 `~/BaseModel/data/raw_20261001b/`（U 盘或局域网拷贝；不经过网盘、聊天工具或任何在线服务）。

3. 构建前端、装后端依赖（第一次几分钟；最后一行可选，用虚构数据跑测试，应全部通过）：

   ```bash
   cd ~/BaseModel/flucase/web && npm ci && npm run build
   cd ~/BaseModel/flucase/backend && python3 -m venv .venv
   .venv/bin/python -m pip install -e ".[dev]" -c constraints.txt
   .venv/bin/python -m pytest -q
   ```

4. 正式模式、建账号、自检、启动（环境变量只在当前终端有效；另开终端跑 `admin` 命令时要先重新 `export`，密钥可以重新生成，只是已登录的要重新登录）：

   ```bash
   cd ~/BaseModel/flucase/backend
   export FLUCASE_ENV=prod FLUCASE_DATA_DIR="$HOME/BaseModel/data/flucase_test1"
   export FLUCASE_SECRET_KEY="$(.venv/bin/python -c 'import secrets; print(secrets.token_hex(32))')"
   export FLUCASE_SEED_DEMO=0 FLUCASE_LLM=off FLUCASE_COOKIE_SECURE=0 FLUCASE_SITE="研究者设备（第一轮测试，Mac）"
   mkdir -p "$FLUCASE_DATA_DIR" && chmod 700 "$FLUCASE_DATA_DIR"
   .venv/bin/python -m flucase.admin create-user researcher --role admin --display-name 研究者
   .venv/bin/python -m flucase.admin create-user test_gd --role importer --site GD --display-name "测试医生（GD）"
   .venv/bin/python -m flucase.admin create-user test_gam --role importer --site GAM --display-name "测试医生（GAM）"
   .venv/bin/python -m flucase.admin create-user test_rev1 --role reviewer --display-name "测试复核员一"
   .venv/bin/python -m flucase.admin create-user test_rev2 --role reviewer --display-name "测试复核员二"
   .venv/bin/python -m flucase.admin check
   .venv/bin/python -m uvicorn flucase.app:create_app --factory --host 127.0.0.1 --port 8000
   ```

   之后各节里 `.venv\Scripts\python` 换成 `.venv/bin/python`，`G:\BaseModel` 换成 `~/BaseModel`（如第 5 节的备份目录）。
