设计要点
- 一次预测 = 一个 ED 就诊（stay_id 为主键、edstays 为根表），所有原始表经四种 ID 联结成 master dataset（p2，Fig.1）。
- 变量清单的来源：查阅代表性 ED 研究 + 请熟悉原始数据和急诊流程的临床医生、信息人员确认；剔除无关、重复或大量缺失的变量（p3）。
- 纳排：<18 岁、没有分诊等级的就诊剔除（p3，Fig.2）。
- 离群值两套阈值：超出"可能范围"标为缺失；超出"生理有效范围"截到最近的有效值；阈值来自已有公开管线（MIMIC-Extract / Harutyunyan），由临床专家给出（p3）。
- 固定 20% 测试集（按就诊随机），鼓励后人用同一测试集、尽量少碰它；缺失用训练集中位数填补并同样用于测试集（p3）。
- 合并症：取就诊前 5 年内 ICD 码映射成 Charlson / Elixhauser（p3）。
- 三个结局（p3–4）：住院（ED 后立即收住院；留观不算，除非最终收住院）；危重结局 = 院内死亡或 12 小时内转 ICU（复合）；72 小时内再返 ED。
- 每个结局对应明确的预测时点：分诊时（住院、危重）vs ED 离开时（72h 再返）（Table 5–7 标题）。
- 局限中写明：单中心、缺 GCS、无院外死亡信息会带来偏倚、中位数填补过于简单（p8）。

对本项目
- 与 O3（门急诊当次未收住院 → 14 天内住院或达到重型）最接近：O3 实际是"住院"与"危重"两类 ED 结局的组合；可参照把"立即收住院"与"之后住院"分开定义，留观、转院按规则显式归类（问题单已有"转院记未知"）。
- 两套阈值（标缺失 vs 截断）可用来细化 std_v3 的 implausible 标记：现在越界只标记、不进基线（B 档）；可再区分"不可能值"与"极端但可能值"。
- 固定测试集 + 尽量少碰：与我们"外部验证集只评价一次"的规则一致；建议把新流感季数据在收集时就标为锁定的验证集。
- 合并症窗口（就诊前 5 年）提示：COM 三态应记来源时间窗（既往史文书 vs 本次诊断）。
- 院外结局缺失会带偏：门诊随访的"未关联到全院记录"必须记未知（转重规则 §4.2 已如此），并在说明里报告未知比例。

设计要点（页码=PDF页）
- 构建三步：采集(acquisition) → 转换(transformation) → 去标识(deidentification)（p2，Fig.1）。
- 队列：2008–2019 年进过急诊或 ICU 的全部患者；排除首诊<18岁和需特殊保护名单；同一人多个病案号合并（p2 "Clinical cohort"）。
- 外部字典：ICD 维表先装 2020 版，再逐版补回已废止编码，最后核验库里每个编码都有描述（p3）。
- 院外死亡：用姓名/社保号/生日与州死亡登记做概率链接，规则逐级放宽、以敏感度为先，并报告各规则的匹配占比（p3）。
- 转换两原则：与上一版向后兼容；尽量少加工，让发布数据贴近临床原始记录（p3）。
- 模块化：hosp / icu / note 按"来源相近"分模块，用 subject_id、hadm_id 与去标识时间联结；便于以后接入别的科室和模态（p3–4，Fig.2）。
- 文书：每类文书一张 EAV 明细表（_detail），把文书里的定量信息结构化（p4、p7）。
- 去标识：查找表随机分配 subject_id/hadm_id；按患者整体平移日期，保留间隔；anchor_year/anchor_age/anchor_year_group 保留"大致哪个年代"以便研究诊疗随时间变化（p4–5）。
- 删失语义写明：死亡日期在末次出院后 1 年删失，dod 为空 = 至少活到那时（p5）。
- 诊断顺序 seq_num 不可靠，提醒慎用（p5）。
- 两个时间：charttime（测量对应时刻）与 storetime（护士核实录入时刻）分开存（p7）。
- ICU 住段由转科记录按"地点→ICU 成本中心"查表派生，连续转科合并、中间转普通病房则拆成两段（p6）。
- 系统变迁写进文档：eMAR 2014–2016 分批上线，2016 年后才全覆盖（p6）。
- 技术验证：单一可复现构建脚本 + 版本控制 + 代码评审 + 工单；单元测试分三类——完整性（外键都在维表/患者表里）、一致性（≥99% ICU 住段有诊断、≥99% 有心率）、与上一版比对；去标识检查用人工整理的允许清单（p7–8）。
- 访问与复用：培训 + DUA；派生概念（通气、升压药等）以共享代码（MIMIC Code Repository）发布，而不是各自重写（p8）。
- 版本差异表（Table 2，p8）。

对本项目
- std_v3 已有"原值+来源+时间精度"，可补"测量时间 vs 文书书写时间"两列语义（GAM 体征多为病历书写时间）。
- CRF 宽表脚本/ flucase 测试可照 MIMIC 三类检查写成带阈值的验收：完整性（每条 events 都挂得上 encounter）、一致性（住院≥95% 有检验、≥95% 有体温…阈值由研究者定）、与上一版导出比对。
- codes.csv 做成"累积字典"：新中心、新年份出现的编码只增不删，并核验导出里每个编码都有中文名（A1 已列未知编码，可升级为失败条件）。
- O3 的"之后住院/死亡"相当于 MIMIC 的院外死亡链接：链接规则、匹配率、未匹配记"未知"要写进说明。
- ICU 科室名称→ICU 判定（问题单第 9 题）与 MIMIC 用"地点→成本中心"查表同构，建议做成可版本化的查找表而不是正则。

设计要点
- 中国医院数据怎么建：从 EMR、LIS、CPOE、护理、麻醉、各检查科室报告系统分别抽取（p2）。
- schema 沿用 MIMIC-III 并为本地数据做少量调整，方便熟悉 MIMIC 的人上手、便于与 MIMIC 比较（p2）。
- 三张核心表 PATIENTS / ADMISSIONS / ICUSTAYS，主键索引其他全部数据（p2–3）。
- 各系统时间跨度不一致 → 用核心表的 ID 做整合与过滤；检查不可能的值（就诊年份 1900）、错误字符（数字里出现汉字）、极端离群值并删除或更正（p3）。
- 没有重症信息系统 → 不用监护仪高频数据，只用护士手工记录的生命体征；术中 5 分钟体征单独建表以免与 MIMIC 混淆（p3）。
- 双语字典：保留中文原名 + 英文译名；有标准编码的用标准英文（ICD-10；部分检验用 LOINC），其余人工翻译并由作者复核；本地 ICD-10 扩展到 7 位、比标准 5 位更细（p3）。
- 中文自由文本无法去标识 → 不发布原文，用 NLP 抽症状及否定状态（+/−）并带文书记录时间，作为 EMR_SYMPTOMS 表；抽 100 份文书由两人独立核对，平均准确率 91.9%，并列出典型错误（分词错误、否定误判、家族史/风险被当成本人症状）（p3–4）。
- 去标识：随机 ID 不留对照；日期按患者随机平移 50–100 年，保留时刻、星期、大致季节（春夏秋冬）（p4）。
- 覆盖率表（按住院计算，low/medium/high/excellent）（Table 4，p5）；不同系统上线时间不同、护理与 EMR 厂商更换 → 各表完整度不同，在文档写明（p7）。
- 版本控制、GitHub issue、患者级时间线可视化网站（p7）。

对本项目
- 与我们的情况最像：中文病历、多个院内系统、症状靠 NLP 从文书抽、带否定。PIC 的"两人独立核对 100 份文书、报准确率和典型错误"是 flucase 规则抽取（S5）缺的一份验证报告，可照做：抽样文书 → 两人独立标 → 报一致率与错误类型（家族史、"必要时"、否定）。
- 保留原文 + 统一编码 + 中文/英文名的双轨字典：flucase 的 codes.csv 已有中文名；新中心接入时把"医院原名→统一编码"映射表随导出发布（std_v3 已在 A8 列未进统一编码的名称）。
- 季节保留：如果以后需要对外共享，日期平移时保留流感季信息（PIC 保留季节，可借鉴为保留"流感季编号"）。
- 系统上线时间与厂商更换写进数据说明：GD/GAM 不同年份的导出格式、科室名称变化同理。

设计要点
- 三级身份：uniquePid（患者，按记录链接算法生成）→ patientHealthSystemStayId（住院）→ patientUnitStayId（ICU 住段，所有表的联结键）（p2–3，Fig.1）。
- 去标识：HIPAA Safe Harbor；随机 ID 且不保留对照表；医院、ICU 标识也去掉以保护机构；第三方认证再识别风险；自由文本规则扫描 + 至少三人人工抽查，下拉菜单类表整表审阅（p2）。
- 抽样：从 eRI 库按医院分层随机抽"每人一个索引住段"，再纳入该患者之后所有住段（不论哪家医院）；只住过 step-down/低强度病房的剔除（p3 "Sample selection"）。
- 时间：所有记录用相对入 ICU 的分钟 offset；很多表同时存"相关时间"和"录入/核实时间"（nurseCharting 的 chart time vs validation time；pastHistoryOffset vs EntryOffset）（p9）。
- 本地映射到标准概念：各院检验映射到 158 个标准 labName，带单位、采样时间、最后修订时间（p8）。
- 写明数据含义边界：medication 是医嘱，不保证执行；infusionDrug 只有持续输注（p8）；监护仪数据未经人工核实（p9）。
- 诊断：问题清单分层编码，能映射 ICD 的映射，不确定的不硬映射（"糖尿病"不知 1/2 型就不给 ICD）（p7）。
- 技术验证：传输用 MD5 校验；尽量少后处理；各院流程不同→ 按医院统计各表覆盖率（none/low/medium/high/excellent，Table 8，p11），并提示覆盖≠可靠（p10–11）。
- 版本规则：改 schema 升主版本；新表、修错、补数据升次版本（p11）。
- 共享派生概念代码与 notebook，公开 issue tracker（p10–12）。

对本项目
- flucase 的 患者→就诊→（住院内）记录 三级身份与 eICU 同构；门诊挂住院（§3.6）相当于 uniquePid 下的多次就诊。建议明确"索引就诊"规则写进导出（已有 season_index，D73）。
- Table 8 式"按中心统计各数据项覆盖率分级"可直接加到 CRF 报告 A3/A6（现在是比例），并像 eICU 一样注明"覆盖率不等于可靠性"。
- 不确定就不硬映射：GD 0/1 勾选分不清"无/未记录"（转重规则 §2.1）应保留为"未知"而不是映射成"无"。
- 医嘱≠执行：GAM 西成药医嘱、"必要时"吸氧，与 eICU medication 表的提醒一致；std_v3 的 treatment 可加"order / administered / documented"来源类型。
- 版本号规则可照搬到 std_v3 / 规则集：破坏性变更升主版本。

设计要点
- 联邦式、只交聚合量：各站点在本地跑脚本（多数用 i2b2，没有 i2b2 的用自己的数据仓库），只上交聚合计数；作者指出这样伦理审批更快（Methods: Data collection and aggregation）。
- 统一的 4 个 CSV：DailyCounts（每日新增、ICU、新死亡）、Demographics（按性别、年龄段计数）、Labs（每项 LOINC 检验按天的受检人数、均值、SD）、Diagnoses（阳性前一周至今各 ICD 码的患者数）（同节）。
- 时间约定：检验的"第几天"以首次阳性检测日为第 1 天，从 −6 天起算（同节）。
- 检验标准化：选 14 项常做检验，每项给定 LOINC、单位、参考范围（Selection of laboratory values）。
- 诊断：ICD-9 先经 ACT 本体与 UMLS CUI 映射到 ICD-10（ICD mapping）。
- 小格处理：站点可把小计数改成 −1、缺失写 −2；合并时记录未遮蔽站点数及其和、遮蔽站点数及其阈值和（各站阈值可不同）（同节）。
- 报告的问题（Results/Discussion）：只有 13% 站点交齐全部检验；单位和呈现方式差异大、需大量协调；很多机构内部没有 LOINC 映射，只能人工解读检验名；ICD 编码差异大且稀疏；ICU/照护级别难识别、不可靠；无法区分检验后收住院与分诊回家者；肌酐的院间差异大于国家间差异。
- 建议：以后各站提交前先换算单位、对照参考范围和示例数据自查（Discussion）。
- 局限：只含就诊者、聚合数据无法个体链接、出院/死亡退出造成存活偏倚、右删失可能来自死亡/出院/编码延迟/上传延迟（Discussion）。

对本项目
- 我们的"研究者在本机跑脚本、只回报聚合报告"（CRF 宽表 A1–A10）就是 4CE 模式；4CE 证明它能快速推进多中心，但也暴露短板：单位、检验映射、照护级别（ICU）最容易出错——正是我们 A3/A8/问题单第9题在查的。
- 采用 4CE 的"固定聚合表 + 示例数据 + 参考范围自查"：给新中心发一份带虚构示例的标准导入模板（flucase 已有），并在导入回执里加"单位/参考范围自查"。
- 时间轴锚定在"首次阳性检测日"与我们 GAM 的 t0 取法相同；4CE 的经验是要单独标出"检测后回家"的人，否则曲线有断崖——对应我们门急诊/住院分场景报告。
- 小格规则（−1/−2 且记阈值）比只写 "<10" 更便于合并多中心报告，可考虑在报告 JSON 里同时记"被抑制格数"。

- 动机：各院数据仓库结构与词表各异；OMOP 转换常丢掉 ICU 的细粒度元素（如呼吸机设置）（Introduction）。
- 设计原则：临床可读的结构、可协调的数据元素、可扩展、联邦分析保护隐私、开源并符合 FAIR（Methods）。
- mCIDE（最小公共 ICU 数据元素）：每张表有一组以 "_category" 结尾的最小元素，每个元素是精确定义的临床实体、只有有限的允许取值（受控词表）；能用 NIH 公共数据元素就用，必要时新建（如通气模式 mode_category）（Methods）。

对本项目
- 最接近我们的"转重"变量：CLIF 把呼吸支持（device_category、mode_category、FiO2 等）做成单独一张表，并给出受控取值。我们的 TRT006/TRT007/TRT011/高流量 等治疗类判据，可以照此做一张"呼吸支持"长表：设备类别（空气/鼻导管/面罩/高流量/无创/有创/ECMO）+ 开始/结束 + 原文标签 _name，问题单第 7、11 题就能直接从这张表算。

对本项目
- "进库≠阳性"：flucase 收集时把检测阴性、疑似（诊断写流感但无阳性检测）也收进来、分层标注，比只收确诊更利于以后做敏感性分析与诊断不一致核查（问题单第3题正是这类计数）。建议 encounters 增加"病原学证据等级"枚举（确诊阳性/弱阳性/诊断无检测/检测阴性）。

- "核心变量可以重点修正、其余轻触"：流感检测结果是我们的核心变量，可像 N3C 处理 COVID 检测那样，用结果原文规则化（弱阳性、只写病毒名未写方法）并记录每次修正。
- 小格抑制、溯源图、产物不可变与我们现有的报告自检（1–9 写 "<10"）、生成记录 json 一致，可在说明里引用 N3C 作为先例。

title: ACES: Automatic Cohort Extraction System for Event-Stream Datasets
authors: Xu J, Gallifant J, Johnson AEW, McDermott MBA

设计要点
- 把"任务定义"拆成两份文件：数据集专用的 predicates 文件（把"入院、出院、死亡"等映射到某库的编码）+ 与数据集无关的 task 文件（只用谓词名写触发事件、窗口、约束、标签）。换一份 predicates 文件就能在另一个库上跑"概念上相同"的任务（§方法/Cross-dataset）。
- 语言要素：predicate（单事件上的布尔函数，可用 expr 组合，如"出院 或 死亡"）；trigger（锚点事件，每个触发产生一个潜在预测）；window（start/end 相对触发或其他窗口，可含边界开闭标记）；has 约束（窗内某谓词的计数范围，如 (5, None) 至少 5 个、(None, 0) 一个都没有）；label 窗口（其中某谓词决定标签）（§配置语言）。

- 抽取算法：树状递归——先找触发，再逐个窗口计数，不满足 has 的分支剪掉，保证"系统、确定"的抽取（§算法）。
- 输出：每个有效实例一行（患者标识、预测时间戳、标签，可选各窗口起止与计数）（§输出）。
- 评测：MIMIC-IV 一个 MEDS 分片（约 8 千万行、4.8 万患者）9 个任务各 3–6 分钟；与 DPM360、OMOP-learn 的小规模对比（作者自认初步、可能有偏）（§实验）。
