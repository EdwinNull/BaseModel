## 2. 总体设计

### 2.1 两组实验和一座"桥"

| 组 | 数据 | 核心问题 | 主要模型 |
|---|---|---|---|
| **A 医院组** | GAM（训练）→ GD（外部验证） | 真实世界小样本、稀疏数据上，基础模型能否比传统模型更好地识别流感转重 | TabPFN v2、LLM；时序 FM 只作对照 |
| **B 公开组** | MIMIC-IV（开发）→ eICU、MC-MED（外部验证） | 在高频时序数据上，时序基础模型后训练是否优于监督基线；能否跨机构、跨场景迁移（即 MIMIC 方案） | MIRA R0–R3、MOMENT、Chronos-Bolt、LLM SFT/GRPO |
| **桥接 A4** | 公开数据流感队列 → GAM、GD | 用公开数据补足医院数据事件太少的问题；在美国数据上训练的模型，能否迁移到中国医院 | A 组模型 + 公开数据后训练的模型 |

### 2.2 两类任务口径

| 口径 | 时间粒度 | 输入 | 用于 |
|---|---|---|---|
| **T-day（跨域口径）** | 天 | 索引日（及前一天）每个变量的第一个值 + 年龄、性别（与医院 v1.0 相同） | A 组全部；桥接 A4。公开数据也要按这个口径各抽一份 |
| **T-hour（时序口径）** | 小时 | 每 6 小时一个预测时点，观察窗 [t0−24h, t0] 内的完整序列 | B 组（MIMIC 方案原设计） |

T-day 是唯一能在 5 个数据集上都成立的口径，因为 GD 只有日期。T-hour 只在公开数据内部成立。
**时序基础模型的主战场在 B 组**：医院 v1.0 已经实测，医院数据没有可利用的时间结构。

## 3. 公开数据能否与医院数据对齐？——结论

**结论**：
- 变量层面可以对齐；
- 结局层面部分可以；
- 人群与场景层面只能部分对齐，差异需要在报告里写明，不能消除；
- 患者层面不能对齐，也不需要（不同机构、不同国家）。

对齐方式：把三个公开数据集抽取成与医院数据**同一个 CDM 表结构、同一套变量编码**，然后用同一套实验代码跑所有组合。
变量编码为 `VS001–VS006`、`LAB001–LAB015`、`EXT_*`、`TRT006–TRT009`、`OUT00x`；代码为 `rw_gam2gd` 泛化后的版本（§4.8）。

| 层面 | MIMIC-IV 3.1 | eICU-CRD 2.0 | MC-MED | 医院（GAM / GD） |
|---|---|---|---|---|
| 场景 | 单中心（BIDMC，美国）住院 + ICU | 208 家美国医院的 ICU（2014–2015） | 斯坦福急诊（2020–2022） | 中国医院普通病房住院 |
| 时间 | 精确到分钟；日期按患者整体平移（不能用绝对年份；流感识别只靠检验和诊断） | 相对 ICU 入科的分钟偏移，没有绝对日期 | 分钟 | GAM 分钟 / 病历书写时间；GD 只有日期 |
| 体征 6 项 | ICU 内约每小时（chartevents）。**普通病房没有体征**，急诊体征在 MIMIC-IV-ED | 5 分钟级（vitalPeriodic）+ 无创血压（vitalAperiodic） | 分诊首值（visits 的 `Triage_*`）+ 监护数据（numerics） | GAM 每天数次、几乎无 SpO2；GD 每项 1 次 |
| 核心检验（21 个共享变量中的检验） | 基本都有（labevents，住院全程） | 大多有（lab，按 labname 字符串） | 大多有（labs 的 `Component_name`） | 有 |
| 流感识别 | 病原学（微生物/检验中的流感 PCR、抗原）+ ICD（J09–J11、487–488） | 主要靠诊断字符串或 ICD-9（microLab 以细菌培养为主，流感病原学结果很少） | labs 中的流感检测 + visits 的 `Dx_ICD10` | GAM 病原学阳性；GD CRF |
| 有创通气 IMV | 有（mimic-code `ventilation` 概念） | 有（respiratoryCare、treatment、APACHE intubated） | 需核对（orders 的 `Procedure_name`） | 有 |
| 入住 ICU | 有（icustays） | **不适用**（全员在 ICU） | 有（visits 的 `ED_dispo`） | 有 |
| 院内死亡 | 有 | 有（hospitaldischargestatus） | 需核对（visits 的 `DC_dispo` 等） | 有 |
| ECMO | 极少 | 极少 | 极少 | 极少 |

**终点公约数**【A 档】：
- **E1**（IMV / ICU / ECMO / 死亡）：除 eICU 外都能定义。推荐作为桥接 A4 的主终点，与医院 v1.0 一致；eICU 不参与 A4。
- **E0'**（IMV / 死亡）：MIMIC-IV、eICU 和两家医院都能定义；MC-MED 取决于 IMV 能否从 orders 推导（§4.6）。推荐作为共同的敏感性终点。
- MC-MED 若没有院内死亡字段，则只能用"ICU 收治 / IMV"。

### 4.4 Step 4 单位、合理范围、去重

1. 单位按映射表中的系数换算，保留 `raw_value`、`unit`。
2. 超出生理合理范围的值置空，并标记 `implausible`。
   直接复用 `alignment/common.py` 的 `apply_plausibility(values, codes)`（按变量编码查合理范围）；时间精度可复用同文件的 `time_precision()`。
3. 去除完全重复的行（encounter × var × time × value）。医院数据已经踩过这个坑：GAM 的生化检验有大量完全重复的行。
4. **验收**：
   - 每个共享变量换算后的中位数与临床常识一致，例如：肌酐 60–120 μmol/L、尿素 3–10 mmol/L、Hb 100–150 g/L。
   - ℉ 已全部转成 ℃。

### 4.7 Step 7 QC 与验收（每个来源一份，写入 `docs/basemodel/result/weekNN/公开数据对齐报告_<日期>.md`）

### A2 反向迁移：GD 训练 → GAM 验证（需要 §4.8 的改动）

- 目的：检验可迁移性。GD 有 38 个事件，更适合训练；GAM 作为验证集只有 10 个事件，结果只作描述。
- 配置：`train_sources: ["GD_CRF"]`，`eval_sources: ["GAM_IP"]`，其他同 v1.0。

### A3 当地重新校准 + 决策曲线（不需要重训；约 1 小时）

- 输入：`basemodel/derived/rw_gam2gd/E1_stay_fluidx_all_20260927/predictions.parquet`，其中 set = GD_primary。
- 做法：
  1. 按患者把 GD 分层随机对半分，20 次，种子固定。
  2. 在一半上只更新截距：以 logit(p) 为偏移量的逻辑回归（`evaluate.calibration_intercept_slope` 里已有牛顿法实现）。
  3. 在另一半上评价 Brier、校准截距与斜率、O/E；20 次取平均和范围。
  4. 决策曲线：`pip install dcurves`，阈值 5%–30%，比较逻辑回归 / TabPFN / LLM 与"全部干预、全不干预"。
- 产出：`result/weekNN/医院数据_当地校准与决策曲线_<日期>.md`。
- 【A 档】阈值范围与临床场景需要你定。推荐 5%–30%，对应"加强监护或会诊"。

### A4 桥接：公开数据 → 医院（依赖 §4 完成 MIMIC-IV 的 T-day 抽取）

目的：用事件多得多的公开数据训练，看模型迁移到 GAM、GD 的表现，同时补足医院数据只有 10 个事件的问题。

1. **T-day 口径在公开数据上的定义**，与医院 v1.0 一一对应：
   - 索引日：到院日（MIMIC 用 edregtime 或 admittime；MC-MED 用急诊到达）。
     院内发病者（首次阳性在到院 48h 后）改用首次阳性日，与 GAM 的"流感索引"一致。
   - 输入：[索引前一天 0 点, 索引日 24 点) 内每个变量的第一个值 + 年龄、性别。**所有时间落到日期**。
   - 标签：E1（stay 口径）；索引日之前已发生的排除。
2. 实验：

   | ID | 训练 | 评价 | 说明 |
   |---|---|---|---|
   | A4-1（主） | MIMIC-IV FLU | GD（主）、GAM（次） | 美国 → 中国，跨国外部验证 |
   | A4-2 | MIMIC-IV FLU + GAM 合并（可加来源指示变量） | GD | 【A 档】是否合并、是否加来源变量 |
   | A4-3 | MIMIC-IV RESP（扩展队列） | GD、GAM | 事件更多；人群更宽 |
   | A4-4 | A4-1 的模型在 GAM 上只更新截距后，再评价 GD | GD | 最常见的实际部署方式 |
   | A4-5 | MC-MED FLU（若事件足够） | GD、GAM | 急诊首值 → 住院结局 |

3. 模型：
   - 逻辑回归、LightGBM、TabPFN v2（上限约 1 万样本 / 500 特征，够用）、Qwen3-8B 零样本（已有，可直接对照）。
   - MIRA R0b 在 T-day 上已证实没有意义。【A 档】推荐不再纳入 A4。
4. 预期困难：
   - 测量场景不同：美国 ICU 或急诊对中国普通病房；
   - SpO2 在 GAM 缺失，公开数据几乎都有：共享变量集合按"GD 有且训练源有"确定；
   - O/E 会明显偏离 1：必须报告校准，并做 A4-4。

### A5 LLM 变体（不训练；估计各 10–20 分钟）

## 11. 已知的坑与对策（都是这次实际遇到的）

| 问题 | 对策 |
|---|---|
| 服务器 shell 是 zsh | `echo ====` 会报错；`${PIPESTATUS}` 不可用；没有匹配文件的通配符会中止命令。脚本写到本机文件，用 `ssh ... python - < 文件` 执行 |
| 含反斜杠的 f-string | Python 3.10 下报语法错。同上，写成文件再执行 |
| pip 默认源（HTTP）被拒 | 加 `-i https://mirrors.aliyun.com/pypi/simple/` |
| HF 大文件（xet）服务器下不了 | 本机下载后上传，并核对 sha256 |
| 归档 MIRA 代码与 transformers 4.57 不兼容 | `model.config.use_cache=False` |
| MIRA 对单点序列的表示与时间无关 | 时序模型只在高频数据上有意义 |
| TabPFN | 只用 v2 权重（Prior Labs License 1.1）；v2.5 以上要浏览器授权，不用 |
| LLM 成批推理 | bf16 补齐会让得分变化，逐条推理 |
| 旧数据生化检验完全重复 | 特征层已去重；公开数据抽取时也要去重 |
| GD 的时间 | 只有日期；4 次住院没有任何时间 |
| 本机 Windows 改文件会变 CRLF | 用字节读写 |
| 700 目录 | 不要用 tar 解包（会改目录权限），用 `ssh 'cat > 路径' < 文件` 上传 |
| 临时文件 | 只能放在 `W` 内，不写 `/tmp`、`/dev/shm` |
| MIMIC 日期按患者平移 | 不能用绝对年份，也不能跨患者比较日期；流感识别只用检验和诊断 |
| 检验时间 | T-hour 任务按结果可用时间进入输入：MIMIC 用 `storetime`，MC-MED 用 `Result_time`；eICU 只有 `labresultoffset`，含义按官方文档核对。用采样或医嘱时间会泄漏 |
| eICU 年龄 | 有 `'> 89'` 的字符串 |
| eICU 体温 | vitalPeriodic 的体温大量缺失，要从 nurseCharting 补 |
| MIMIC 的 D-二聚体 | 单位与 FEU/DDU 口径可能与国内不同，映射前核对 |
