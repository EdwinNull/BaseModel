flucase 现在能做什么

从“骨架 + 静态原型”推进到真实运行的演示系统：三个虚构来源（CRF 宽表 80 次住院、EHR 导出 40 次住院 230 份文书、门急诊导出 120 次就诊）在后端跑完 S1–S11，共 7,419 条带证据的抽取记录，隐私审计 0 命中；后端 35 个测试全部通过。

接入

  1. S1导入：按文字读入，记 sha256，表头签名识别来源
  2. S2识别：一人多行分组、续行病案号不信任
  3. S3化名与清洗：隐私审计不为 0 就停止

规范化

  1. S4映射：统一编码、删失值、越界值、单位待确认
  2. S5抽取：规则（三态与语境）+ 本地 LLM 第二抽取
  3. S6时间：精度标记、年份笔误、起病时钟

表型

  1. S7分级：按规则集 YAML 出分级时间线、病程类型、候选结局 O1/O2/O3/D0
  2. S8标记：R1–R7 生成 A/B 类复核条目

复核与质控

  1. S9回流：盲法判定、共识写入复核层，有效层实时重算
  2. S10质控：覆盖率、精度、一致性、可行性计数（小格抑制）
  3. S11冻结：快照哈希写入数据使用台账
模块10/09 原型现在
数据源只有 CRF 表头校验三个适配器：识别、校验、映射预览、构建；生成器埋入设计文档 §11.1 的全部问题
复核状态存浏览器后端分派（A 类两人；B 类一人 + 15% 抽样第二人）；复核员只拿到问题、背景和证据片段；按抽取记录编号回流，换规则集重算时沿用
规则集v0 只读v0 与 v0.1；校验器区分错误与提醒；版本对比；“用此版本重算”只从 S7 开始

评测—逐字段召回率、准确率、时间误差，分自动层与有效层

规则集 v0.1 改了什么（候选）

  • 中型停用“发热>3 天”：早期预测“轻→中”时属循环定义
  • 中型判据补 kind，生理 / 治疗 / 诊断可以分开报告
  • 肺炎判据同时认 CRF 合并症表的“病毒性肺炎”
  • 新参数：COPD 者不用“吸空气 SpO2≤93”判重型（A 档）
  • 影像进展>50%、急性坏死性脑病显式标为不可评估

前瞻录入表单 v0.2 改了什么（候选）

  • “本次是否发热”三态：留空时分得清“不发热”和“没评估”
  • 体温测量部位；退热药与开始时间
  • 关键检验：白细胞、淋巴细胞、CRP、血糖
  • 中医证候（自由文本，选项待临床给定）
  • 随访的实际联系日期：区分“确定阴性”和“随访不足”

复核候选条目（S8）

CRF 的 28 条 R5 来自同一个结构性缺口：CRF 没有吸氧状态列。EHR 的 R3 是“必要时气管插管”这类假设、拒绝、围术期语境。演示批次按类型限量后共 42 条。

抽取评测：会后计划 §5.5 的口径，标准答案为生成器真值

字段真值事件召回率准确率时间误差中位说明

模板文本上规则召回率接近 100%，不说明真实性能；真实评测要两位医生不看系统结论做全字段标注。值得看的是最后一行：规则漏抽的值，只有进入复核批次并经两人确认后才进有效层（空心框为复核后）。
