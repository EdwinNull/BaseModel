## 0 一页结论

- **原始导出不是一张表，而是一套 20 个 xlsx**：1 份病例名单、1 份医嘱、1 份生命体征、1 份检验、1 份检查，另有 `病历/` 下 8 类病历文书（入院记录、首次病程、查房记录、出院记录、死亡记录、24 小时内入出院记录、有创操作记录、手术记录；大的分成“第1页”“第2页”……）。共 618 次住院、610 位病人，年龄 60–97 岁，入院时间从 2020-08 到 2026-06。旧的 GD式 CRF 是 297 次住院，两者的纳入范围不同。
- **各表靠住院编号连在一起**：`ENCT_ID`（11 位）是住院级主键，在医嘱、体征、检查、名单、入院记录里全部对得上；`ENCT_UUID` 与它一一对应（病历文书用它）；住院号（7 位）= 名单里的病案号，是病人级编号（8 位病人有两次住院）。名单按“同一住院号、医嘱开始时间落在入院前 2 天到出院后 2 天之间”能唯一对上 615/618 次住院（另有 <5 次对上多个），用入院记录的入院时间对应该能全部对上。
- **检验表挂不上（卡点）**：检验表只有 `JZH`（8 位，617 个），没有住院号、`ENCT_ID` 或姓名。两轮扫描试过完全相等和“一个是另一个的一段”，和任何编号都对不上。**要么请 GD 信息科在检验导出里加上 `ENCT_ID` 或住院号，要么给一张 `JZH → ENCT_ID` 对照表**，否则 24.6 万行检验一条都进不了病例库（§5 第 1 项）。
- **比 CRF 丰富得多**：CRF 里人工摘的 0/1 勾选和少数几个时间点，原始导出里有完整的时间序列。体征 49 万行、医嘱 16 万行，开始、停止时间都有；诊断带 ICD-10 编码，分入院、出院、补充、修正几类；入院记录已按主诉、现病史、既往史等拆成列；查房记录有近 5 千份，每份都有查房时间。
- **要做的事**：
  1. 新格式族“病历系统多文件导出”，**一整套文件一起读**。现在的导入是一个文件配一个读取器，同一次住院出现在几个文件里会被当成重复丢掉，必须改。
  2. 新读取器“GD式原始导出”：按表头认出每个文件的角色，按编号挂接，把各表读成病例记录。
  3. 目录对应（体征项目、检验名称、医嘱名称 → 统一数据项）写进格式配置。Claude 只写默认的关键词规则，看不到真实的名称清单；没对应上的名称列进问题清单，由研究者在页面上补。
- **不变**：旧的 GD式 CRF 读取器保留（旧数据、别的中心按同一份 CRF 填的表）；不做对齐；Claude 只用虚构数据开发；A 档口径归研究者。
- **工作量（估计）**：开发约 3 周（§6）。检验要等对照表，不影响其余部分先做。

### 1.4 读取时要处理的写法

1. **表尺寸写坏**：病历文件不是 Excel 生成的，表尺寸写成 A1。用 openpyxl 只读模式读时只能读到第一格，pandas 会先重置表尺寸、能读全（已用虚构文件验证）。读取器统一走“重置表尺寸”的读法。
2. **分页**：同一类文书分成“第1页”“第2页”……几个文件，表头相同，要合并后再读。
3. **文本里的标记**：查房内容 99% 含 `<`，查房目的里有 `<…/>` 形状的写法。要把换行标记换成换行，再去掉其余标记；原文照样保存，便于追溯。
4. **时间写法**：病历文书的时间是带 0.1 秒的文字（`9999-99-99 99:99:99.9`），医嘱、体征、检验是 Excel 日期单元格，名单只有日期。
5. **体征的取值**：值1–值5 的含义按项目不同。体温有约 1% 的值在 379 这一级（像漏了小数点），呼吸有 0；血压有 10 种项目名，只有 12% 的行有值2。要按项目逐一定义怎么读（写进对应表）。
6. **检验单位**：同一单位有大小写不同的写法（`μmoL/L` / `μmol/L`、`ng/mL` / `ng/ml`），要统一。“血红蛋白”关键词命中的大多是动脉血里的 % 值，是血气项目，不是血红蛋白；要按名称、标本、单位一起判断。
7. **名单的“ICD码”列不是流感编码**：多为 J18.9、J15.9 这类肺炎编码；流感编码在“其他诊断”里（J11 有 499 次、J10 有 118 次住院），主要诊断是流感的不到 5 次。
8. **呼吸衰竭的分型**：编码几乎都是 J96.9（未特指），Ⅰ型、Ⅱ型要靠血气或文字判断。

## 2 目标与范围

**目标**：GD 的医生把病历系统导出的这一套文件（或打成 zip）一次上传，系统认出“GD式原始导出”，读成病例记录，照常预览、确认、累加、撤销、更正。读出的数据项与现有编码一致，下游的分级、复核、质控、冻结导出不用改。

**这次不做**：

- 实验侧（服务器 `alignment/gd_crf.py` → CDM、`rw_gam2gd` 外部验证）怎么改用原始导出：口径属 A 档，研究者另定。
- 别的中心的病历系统导出：这次的“多文件导出”族和对应表要设计成通用的，但只内置 GD 一个格式。

## 3 设计

### 3.1 新的格式族：一套文件一起读

现在 `flucase/repo/jobs.py` 的 `read_job` 对每个文件单独认格式、单独读，得到一个读取结果；`merge.group_results` 按就诊编号分组时，同一编号在一次导入里出现两组，就记 `DUP_ENCOUNTER`，两组都不导入。原始导出里，同一次住院散在 13 类表里，逐文件读会全部撞上这条规则，而且名单、入院记录以外的文件单独读时没有入院时间、年龄、性别。

**做法**：加一种“成套读取器”（bundle reader）。

- 接口：`match_bundle(files) → BundleMatch`（认出哪些文件属于这一套、各是什么角色、缺什么），`read_bundle(files, ctx) → ReadResult`，产出**一个**读取结果。
- `read_job` 先让成套读取器认一遍本次上传的文件，被认领的文件一起读；剩下的文件照旧逐个认格式。导入记录的每个文件多记一个“角色”，页面上显示“医嘱”“检验”“查房记录（第 3 页）”这类说法。
- 格式库照旧登记，格式族新增“病历系统多文件导出”（`ehr_bundle`），内置格式“GD式原始导出 v1”。派生格式以后照旧能存（改角色识别的表头、对应表）。

### 3.2 认角色：按表头，不按文件名

文件名里有导出平台的编号（`WY` + 6 位数字），每次导出可能都不同，所以只按表头认角色。每个角色在格式配置里写“必须有的列”和“可以有的列”，例如：

| 角色 | 必须有的列 |
|---|---|
| 名单 | 病案号、入院日期、出院日期 |
| 入院记录 | `ENCT_ID`、`ENCT_UUID`、住院号、入院时间、性别、主诉、现病史 |
| 首次病程 | 住院号、`enct_uuid`、病例特点 |
| 查房记录 | `ENCT_UUID`、查房时间、查房内容 |
| 出院记录 | `ENCT_UUID`、记录时间、诊疗经过 |
| 死亡记录 | `ENCT_UUID`、死亡原因 |
| 有创操作记录 | `ENCT_UUID`、操作名称、操作起始时间 |
| 手术记录 | `ENCT_UUID`、手术名称、手术开始时间 |
| 24 小时内入出院 | `ENCT_UUID`、入院情况、出院情况、可靠程度 |
| 医嘱 | `ENCT_ID`、医嘱名称、开始时间、普通或出院 |
| 生命体征 | `ENCT_ID`、项目、值1、记录时间 |
| 检验 | 名称、结果、标本类型、采集时间（编号列见 §3.3） |
| 检查 | `ENCT_ID`、影像所见、影像诊断、报告时间 |

同一角色的多个文件（分页）合并读取；完全相同的行去重，并记一条提示。缺了某个角色时，写成“请确认”级的问题，例如“这次没有检验结果文件”；只有缺入院记录时才判为“不能导入”，因为年龄、性别、入院时间都靠它。

### 3.3 编号与就诊

- **就诊编号**：推荐 `住院号-入院日期`（如 `1234567-20240105`，虚构），与 D37 和现有 GD 编号的写法一致，医生看得懂；`ENCT_ID`、`ENCT_UUID` 存进就诊的附加信息，用来挂接。也可以直接用 `ENCT_ID`（§5 第 2 项）。
- **病人编号**：住院号，规范化时去空白、去非字母数字字符、去前导零。
- **就诊的基本信息**：入院时间、出院时间、性别、年龄、科室取自入院记录；名单只补诊断编码，按“住院号 + 入院日期”挂到入院记录上，对不上或对上多个的写进问题清单。
- **检验**：格式配置里写“检验用哪一列挂接住院”。拿到对照表之前，检验文件读出来但不导入，问题清单写明“检验结果挂不上住院（只有 JZH）”，数量写清楚。对照表到了以后有两种接法：GD 重新导出时直接带 `ENCT_ID` 或住院号列，读取器认出来就能用；或者单独上传一张对照表（角色“编号对照”）。

### 3.4 各表怎么读

| 数据项 | 来源与规则 | 时间 |
|---|---|---|
| 预测时点 t0 | 入院记录的入院时间（精度到分），取法写“入院记录的入院时间”。院内发病仍按 D48，由病例库计算时改 | 入院时间 |
| 出院时间、住院天数、去向 | 入院记录的出院时间、住院天数；死亡记录或死亡医嘱 → 院内死亡；出院记录文字写明自动出院 → 自动出院 | — |
| 死亡 DEATH | 死亡记录（时间取出院时间，标“取自出院时间”），死亡医嘱可以佐证 | 出院时间 |
| 体征 VS001–006 | 体征表按对应表把项目名映射到编码，并写明读值1还是值2（如舒张压）；有明确规则的笔误自动改（如体温 300–430 按 ÷10），原值留在来源里、记“已修正”；说不清的超范围值保留原值、记问题、不参与分级（§5 第 6 项）；合理范围用通用范围（收缩压 40–280、舒张压 15–180 等），有创动脉压另定为收缩压 20–280、舒张压 10–180（研究者 10-18 定，休克时可以很低） | 记录时间（分） |
| SpO2 的吸氧状态 | 测量时有没有生效的吸氧医嘱（开始 ≤ 测量时间 < 停止）：有 → 吸氧，没有 → 未吸氧或未知（口径见 §5 第 6 项） | — |
| BMI | 同一次住院最早的身高、体重 | 记录时间 |
| 检验 | 按对应表：名称 + 标本 + 单位 → 编码；非血标本（尿、胸水等，标本类型列直接给）不当作血液指标；单位统一大小写；流感检测 → FLU_TEST（甲 / 乙型、阳 / 阴 / 弱阳）；没对应上的按原名保留（`LABX:`） | 采集时间，没有就用报告时间 |
| 抗病毒药、中成药 TRT001–005 | 医嘱的医嘱名称 + 通用名按对应表；普通或出院 = 出院医嘱的不算 | 开始时间 → 停止时间 |
| 氧疗、高流量、无创、有创、ECMO、CRRT、升压药 | 医嘱按对应表（如“无创血压监测”不算无创通气）；插管再看有创操作记录的操作名称和起止时间；查房记录的文字规则做补充，带假设、拒绝、围术期语境（现有规则） | 医嘱开始时间 / 操作起始时间 / 查房时间 |
| ICU TRT008 | 有医嘱的科室在 ICU 科室名单里（格式配置）→ 开始时间取该科室第一条医嘱；转科医嘱、查房文字作补充 | 同上 |
| 病危 / 病重 | 医嘱 → 就诊附加信息“病危通知”（同 GAM 读取器） | — |
| 症状、起病时间、基础病文字、疫苗 | 入院记录的主诉、现病史、既往史、流行病学史，交给现有规则抽取（`textx.extract`）；这些列已经分好，不用再从全文里切节 | 入院时间 |
| 入院体征 | 入院记录的一般状况、专科情况（规则抽取） | 入院时间 |
| 影像 IMG | 检查表按类别、项目归到模态（CT、DR、超声、MR……），所见和诊断写成“检查报告”病历，交给规则抽取 | 报告时间 |
| 病历 RNote | 入院记录（各列拼成一份，节名作标题）、首次病程（时间取入院时间，标“无书写时间”）、查房记录（查房时间，类型取查房类型）、出院记录（记录时间）、死亡记录、24 小时内入出院、有创操作记录、手术记录 | 各自的时间 |

每个值都带来源：文件、工作表、Excel 行号、列字母、表头、原值，和现有读取器一样。病历规则抽取的结果带病历区间。

### 3.5 诊断编码 → 流感诊断、基础病、并发症

原始导出有两套编码：名单的主要诊断 + 其他诊断，入院记录的入院 / 出院 / 修正 / 补充 / 确定诊断。规则如下：

- **流感诊断 FLU_DX**：任一诊断编码以 J09–J11 开头；J10 记“已确定病毒”，型别还是以检验为准。
- **基础病**：入院诊断编码落在研究者定的范围里，或既往史文字规则命中。
- **并发症**：出院、补充或修正诊断里有、入院诊断里没有的，记“住院期间新出现”，没有诊断时间；入院诊断里已有的，记“入院时已有”（同 GAM 读取器的做法）。

按名单诊断编码算的可行性计数（主要 + 其他诊断，编码范围是初稿，待研究者定）：慢阻肺 145、冠心病 251、糖尿病 187、慢性肾病 100、脑卒中 209、心衰 142、肿瘤 64；呼吸衰竭 195（几乎全是 J96.9 未特指）、细菌性肺炎 412、病毒性肺炎 41、脓毒症 52、感染性休克 32、急性肾损伤 24、低蛋白血症 113、低钾 47、低钠 19。

编码范围写进格式配置，不写死在代码里。

### 3.6 目录对应：项目名、检验名称、医嘱名称 → 数据项

真实的名称清单（163 种体征项目、816 种检验名称、约 1.07 万种医嘱名称）Claude 看不到，所以分三层：

1. **默认规则**（Claude 写进代码）：按关键词 + 排除词 + 标本 / 单位约束，与扫描时用的关键词同源（如“血红蛋白”要求单位 g/L、标本是静脉血；“无创”要排除“血压”）。
2. **对应表**（格式配置的一部分）：名称 → 编码，以及读哪个值列、单位换算。研究者在格式库页面编辑；存成新版本，旧导入可以复现。
3. **未对应清单**：每次预览都列出“没对应上的名称 + 行数 + 住院数”（现有 `LAB_UNMAPPED` 扩到体征和医嘱），研究者可以下载，补进对应表后重新读。

这一层的页面（对应表编辑、未对应清单下载）是新的，对以后接别的中心也有用。另一种做法见 §5 第 7 项：研究者同意时把名称清单（只含名称和出现次数）给 Claude，Claude 直接写好对应表。

### 3.7 导入流程与页面

- **上传**：导入页支持①多选文件、②选整个文件夹（`webkitdirectory`，保留相对路径作为显示名）、③上传 zip 或 rar，由服务器解到这次导入的工作目录（zip 用 Python 自带的 zipfile；rar 调 7-Zip / unar / bsdtar），先列清单再解，防路径穿越，有解压后总大小和文件数上限；压缩包本身也按 sha256 归档。
- **第 2 步“认格式”**：一套文件显示成一组：“GD式原始导出：认出 20 个文件 / 13 种角色”，逐个列出角色，缺的角色标出来（如“检验挂不上住院”）。
- **第 3 步“看读到了什么”**：照旧（新增 / 更新 / 不变、问题清单、抽查一次住院）；另加“各角色读了多少行、对上了多少次住院”。
- **重新导入**：整套重导，内容不变的住院判“不变”。只导了一部分文件时（如只有医嘱），新版本会少掉别的部分，预览里写成“请确认”，列出会少掉哪几类记录。以后如果确实需要，再做“按角色沿用上一版”（§7）。
- **医生说明与教程**：导入说明、GD 医生测试教程（docx）加“上传整套原始导出”一节。

### 3.8 体量与性能

单次导入：体征 49 万行、检验 25 万行、医嘱 16 万行、病历约 7,700 份（查房内容合计约 1,500 万字）。按对应表筛完，估计要入库 30–40 万条记录。

- 体征、检验、医嘱逐行流式读（openpyxl 只读 + 重置表尺寸），不整表进内存；只保留对上编码的行，没对上的只计数。
- 预览的读取结果（`read.json.gz`）会到几十 MB；合并时按就诊分批写库。
- 部署那台 ECS 给 flucase 的内存上限是 1.5 GB（`flucase.service` 的 `MemoryMax`）。要在同等上限下，用同样规模的虚构数据测读取和确认的耗时与峰值内存，再决定要不要调高（这是 flucase 自己的服务文件，不碰 CRF）。
- nginx 上传上限 200 MB，这一套约 51 MB，够用。

### 3.9 与现有部分的关系

- **GD式 CRF 读取器**：保留，格式库里照旧有。
- **病例库里已有的 GD CRF 数据**：如果研究者第一轮测试或 ECS 上已经导入过 GD CRF，同一中心会有两种来源。CRF 的锚点是首个有效体征时间，原始导出用入院时间，日期多数相同或相差几天，会被判成“疑似同一次”（7 天内）并按更新处理，读法不同会造成大面积更新。建议先撤销 CRF 的导入，再导原始导出（§5 第 5 项）。
- **下游**：分级、复核、质控、冻结导出读的是同一套数据项编码，不用改；记录多了，候选分级的时间线会更密，要在研究者测试时看一下页面表现。

## 7 测试与验收

**自动测试（虚构数据）**：

- 认格式：整套认出 13 种角色；文件改名、调换顺序也能认；缺角色时写问题；混进一份 GAM 文件也能分开读。
- 读取：坏表尺寸、分页去重、文本标记、时间写法、编号规范化；名单按“住院号 + 入院日期”挂接（含再入院）。
- 规则：出院医嘱不算用药，无创血压不算无创通气，ICU 科室判定，诊断编码的入院时已有 / 住院期间新出现，SpO2 吸氧状态推断。
- 合并：同一套重导全部“不变”；少了文件时预览里写明少掉哪几类记录；撤销。
- 检验：没有对照时不入库并写问题；有对照时挂上。
- 性能：618 次住院、49 万行体征的虚构数据，读取和确认的耗时与峰值内存。
- 前后端各自的测试和 `npm run typecheck` 照旧通过；pandas 2、3 都要跑。

**研究者真实数据核对（只回报计数）**：就诊数 618（病人 610）；各角色读到的行数与 §1.1 一致；入院记录 618 次全部建成就诊；名单 618 行全部挂上；体温、脉搏、血压覆盖 618 次住院；问题代码计数里没有大量“这一行没导入”。

## 8 风险

| 风险 | 对策 |
|---|---|
| 检验迟迟拿不到编号 | 其余部分照常上线；检验单独补导（同一套重导，内容不变的部分判“不变”） |
| 默认关键词误判（如“无创”命中无创血压、“血红蛋白”命中血气 %） | 用对应表而不是宽泛关键词；预览里给每个编码命中的名称种数和行数，研究者核对 |
| 记录量大，ECS 内存不够 | 流式读取、只入库对上编码的行、分批写库；先做性能测试再部署 |
| 只导一部分文件，导致新版本少数据 | 预览写成“请确认”并列出少掉的类别；版本保留、可以撤销；以后需要时做“按角色沿用上一版” |
| GD 下次导出的列名有变化 | 角色按表头认，配置里可以写别名；差异进“相似格式”，研究者确认后存成派生格式 |
| 诊断编码只有“有没有”，没有并发症的诊断时间 | 标“没有时间”；需要时间的分级规则照旧用病历规则抽取、检验和医嘱的时间；口径由研究者定 |

## 附 扫描脚本

研究者本机运行，只输出结构和计数（姓名、编号、正文不输出）：

```bash
cd BaseModel/scripts/flucase_raw_scan
python gd_raw_scan.py  <原始导出目录> --out <报告.md>     # 第一轮：文件、表头、类型、写法形状、编号重合
python gd_raw_probe.py <原始导出目录> --out <报告.md>     # 第二轮：编号挂接、目录覆盖、低基数列取值（严格遮蔽）
```

需要 pandas、openpyxl；读老式 `.xls` 还要 xlrd。`make_fake*.py` 生成验证扫描脚本用的虚构样例。GD 以后重新导出（例如带上检验编号）时，用这两个脚本再扫一遍就能看出列有没有变。
