03主结果：GD 外部测试的区分度

AUROC = 随机取一个发生事件和一个未发生事件的住院，模型给前者更高分的概率。 0.5 是随机猜测。误差条是 10,000 次患者聚类 bootstrap 的 95% 置信区间， 所有模型共用同一批重抽样，因此模型之间是配对比较。

完整指标表：AUROC、AUPRC、Brier、校准斜率、O/E、90% 特异度下的敏感度

AUPRC 对事件率敏感，跨评价集不可比。Brier 越低越好。 校准斜率 1.0 为理想，明显小于 1 表示预测过于极端。O/E = 实际事件数 / 预测事件数之和， 小于 1 表示高估风险。90% 特异度下的敏感度是把模型当告警器用时的实际捕获率。

内部交叉验证 vs 外部测试：哪些模型是过拟合，哪些不是
模型GAM 内部 CV AUROCGD 主评价集 AUROC 落差判读

判读口径必须区分模型容量。 URB-65 内部高出 GD 0.092，但它是固定的 4 分制评分，训练集上只拟合一个一维单调校准—— 单调变换不改变排序，而 AUROC 只取决于排序，所以它的 AUROC 没有可过拟合的自由度。 它的内外落差只能解释为两家医院病例构成与变量可得性的差异。 本页第 05 节给出实测印证：换训练标签后它的 ΔAUROC 恰为 0.000。 真正命中「过拟合或迁移失败」的是 MIRA 冻结嵌入。

冒烟检查：标签打乱后，模型确实退回随机水平
模型正式运行 AUROC标签打乱后 AUROC

冒烟运行（SMOKE_v2_main_20260928）在训练集和验证集内部各自打乱标签。 如果流程有泄漏，打乱后仍会有区分度。打乱后各模型都落回 0.5 附近，说明流程没有把标签信息漏进输入。 冒烟的指标本身没有意义，只用于检查流程。

04把 GAM 训练标签从规则改成人工裁定，结果变了吗

v1.0 的 GAM 结局标签全部来自病历文本规则，没有人工核查，而训练集只有 10 个事件—— 错 1 个就是 10%。v2 对 46 次住院的 79 个判定做了人工裁定（规则宽召回 → 本地 Qwen3-14B 第二标注 → 研究者裁定）。 GD 侧标签完全不动，所以「同一模型在 v2 与 v1.0 之间的差值」只反映训练标签的影响。

＝
没有改变任何结论。

一个可用来自检的现象

URB-65 的差值恰好是 0.000（区间也是 0.000–0.000）。这不是巧合，而是必然： 它的预测是固定 4 分制评分经过一个单调校准得到的，换训练标签只改变校准曲线， 不改变住院之间的排序，而 AUROC 与 AUPRC 只取决于排序。

这条性质让它成为配对流程的内置自检：如果 URB-65 的差值不为 0， 说明配对对齐或数据读取环节出了错。Qwen3-8B / 14B 零样本同理。

06数据集对齐细节：逐项审计

两家医院的数据已经被映射到同一个通用数据模型（CDM aligned_20260927）： 表结构、变量编码、单位都统一了。但「对齐」不等于「可比」。 下面是对四类语义不对称的量化审计，脚本 scripts/data_audit/cdm_v2_gap_audit.py， 窗口口径直接调用实验代码本身，保证看到的和模型看到的一致。

≠
一句话总结：结构层面已经对齐；语义层面有四类不对称，其中两类已知会影响结论。

影响最大的是结局标签来源不对称（v2 的人工裁定正是针对它）和时间语义不对称 （GD 没有真实测量时刻，被统一放在索引前一天 0 点）。这两类无法靠改代码解决，需要数据方补充。

逐变量明细：覆盖率、观测密度、时间精度、中位数比、取整堆积
变量GAM 覆盖率GD 覆盖率 GAM 每次观测数GD 每次观测数 中位数比 GAM/GDSMD GAM 末位 0/5GD 末位 0/5

观测数是去重后的（按住院 × 变量 × 时刻折叠，与实验特征构造同一步）。 「末位 0/5 占比」衡量人工读数的取整习惯：均匀取整时期望是 0.2，明显高于 0.2 说明有人工凑整， 两院差异大则说明测量方式不同。

B · 时间层：索引时点意味着什么

GAM（旧数据）

  • t0 = 流感首次阳性时刻，不是入院时刻。163 次住院中 99 次按此规则。
  • 入院到流感确诊的中位间隔约 87 小时（3.6 天）。这段时间的观测全部落在输入窗口之外。
  • 入院锚点本身可信：入院时刻与首次观测之差中位数 0 小时，无负值。
  • 窗口内观测的时间精度：分钟级与病历书写时间混合。

GD（新数据 CRF）

  • t0 = 首个体征日期。没有入院时间。
  • 数值没有真实测量时刻：提前量在四分位上都恰好是 24.0 小时， 说明它们被统一放在索引前一天 0 点。
  • 窗口内 2,721 个观测是纯日期精度、1,242 个是分钟精度。
  • 每个变量每次住院基本只有 1 个值，没有时间序列。
!
后果一：时序基础模型在这份数据上没有发挥空间。

GD 有 99.4% 的变量序列只有 1 个点。MIRA 的 CT-RoPE 对每条序列做时间归一化， 单点序列的表示与时间无关，只取决于数值。这解释了为什么 MIRA 冻结嵌入（0.578） 和微调版（0.682）都没有超过逻辑回归——不是模型不行，是这份数据里没有时间结构可用。

后果二：日期精度的时间戳目前在表里看起来和真实时间戳一样。 CDM v2 需要新增 time_kind 字段（真实时刻 / 仅日期 / 由锚点推算）显式标注， 否则任何依赖时间间隔的分析都会把「推算值」当成「实测值」。

C · 结局层：同一个终点，两家医院的来源完全不同

这是四类不对称里影响最大的一类，也是 v2 人工裁定要解决的问题。

终点组成GAM 来源GAM 时间精度 GD 来源GD 时间精度

precision 含义：minute = 精确到分钟；day = 只有日期（存成当天 0 点）； note = 病历书写时间（近似，可能晚于事件实际发生）；unknown = 没有时间。 GAM 的 ICU 与有创通气全部是 note 精度——病历写下的时间不等于事件发生的时间。 GD 的全部是 CRF 人工填写的 day 精度。两侧不仅来源不同，时间精度也不同。

E1 阳性住院事件 / 纳入首个组成构成 首个组成的时间精度无任何时间的事件

这张表把「来源不对称」落到了实处。GAM 训练集 10 个事件的首个组成时间精度是 note 15 / minute 3——以病历书写时间为主；GD 主评价集 38 个事件则是 day 52 / unknown 3，全部是日期精度，还有 3 个事件连日期都没有。 换句话说，模型在训练时学的是「病历何时写下」，评价时用的是「CRF 填了哪一天」， 两者的时间含义并不相同。计数大于事件数是因为同一事件可能有多个组成同时发生。

07局限与下一步

按重要性排序。前三条会改变结论强度，不是形式化的免责声明。

  1. 索引当天事件占比过半。GD 主评价集 38 个事件中 26 个发生在 t0 当天， 模型的输入可能已包含「正在转重」的信号，而非提前预警。前瞻子集是针对这一点的检验， 但只有 9 个事件，不足以支持结论。需要数据方补充真实入院时间与事件时刻（A6）。
  2. GD 不再是未使用过的外部集。v1.0、A1 七项、A3、A5、v2 都在 GD 上评价过。 v2 与 v1.0 并列报告，不替代 v1.0，也不构成新的独立外部验证。
  3. 裁定人只有 1 名，没有第二人独立复核，无法给出人际一致性。 报告的 κ 是「规则 / LLM 对裁定」的一致性，不是裁定本身的可靠性。 并且裁定工具中各组成的 LLM 结论对裁定人可见，可能造成锚定—— κ 0.88–1.0 的一部分可能来自这条路径，不能读作 LLM 独立准确性。
  4. 训练集事件数极少（v1.0 为 10 个、v2 为 14 个）。所有 v2−v1.0 的差值区间都很宽， 方向性不作结论。MIRA 微调的结果只作探索性描述。
  5. GD 没有时间序列（99.4% 单点），时序基础模型在这份数据上没有发挥空间。 这限制了本路线能回答的问题，不是模型实现的缺陷。
  6. CDM v2 的对齐改造尚未执行。本页第 06 节完成的是差距审计（只读）， 去重、time_kind、三态编码、outcome_components 表都还没做。
